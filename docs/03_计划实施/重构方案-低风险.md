## R5 清理 re-export shim（低风险）

- 问题：纯转发文件增加一跳间接，属冗余。当前已确认的 shim：
  - `src/db/training/archive.mjs`（6 行，纯 re-export 自 `adapters/postgres/archive-repository.pg.mjs`）
  - `src/adapters/telegram/sync-batch.adapter.mjs`（9 行，纯 re-export 自 `sync-batch-logic.adapter.mjs`）
  - `src/telegram/commands.mjs`、`src/telegram/index.mjs`（转发 `command-registry.mjs` / `help.mjs`）
  - 其余 2–8 行 `index.mjs` barrel（逐个确认后再删）
- 方案：逐个内联——把调用方 import 直接指向真实实现文件，删除 shim。确有"对外稳定聚合点"价值的 barrel 保留并在首行注释说明理由；其余删除。
- 影响面：上述文件及其所有 import 方。
- 外部行为：不变。
- 验证：每删一个 shim 立即跑相关测试 → 全量测试 + `npm run build` + `git diff --check`；确认净删除文件数为正。
- 注意：`src/db/training/archive.mjs` 的删除与 R1（合并 PG 双层）目标一致，但本档只做"内联 import + 删文件"，不迁移实现；实现迁移属 R1，放高风险档。
