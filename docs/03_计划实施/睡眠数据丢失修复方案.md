# 健身训练系统图片数据偶发丢失问题排查与修复方案

## Context（背景）

用户在使用 Telegram/飞书发送训练图片时，偶尔会出现部分数据在页面上丢失的情况，但重新发送同一张图片后，数据能够完整入库并正常显示。这表明系统存在非确定性的数据处理失败场景，但这种失败未能被正确捕获和重试。

根据用户提供的 GitHub Actions 截图，可以看到多个 "Sync queue task" 的成功执行记录，这表明：
1. 第一次发送图片时某些数据未能入库
2. 重新发送后系统能够正常处理
3. 问题具有间歇性和可恢复性特征

## 根本原因分析

通过深入阅读代码，我发现了一个**关键的数据完整性风险点**：

### 核心问题：睡眠数据回填失败的静默丢失

**位置**：`src/app/use-cases/telegram-sync.use-case.mjs:500-523`

```javascript
if (shouldRunSleepBackfill({ rawEnv, storedSleepAny })) {
  try {
    await measureSyncStage(timings, 'sleepBackfill', () =>
      backfillCoreSleep({
        processedAt: now,
        sourceChannel: options.sleepBackfillSourceChannel ?? 'telegram_sync',
        targetArchivedDates: [...storedSleepArchivedDates].sort(),
      }),
    );
  } catch (error) {
    // 关键问题：错误被捕获但只标记 partialFailure，不进入 pending 重试
    const errorMessage = error instanceof Error ? error.message : String(error);
    const warning = `sleep backfill failed: ${errorMessage}`;
    for (const batch of batches) {
      if (batch.persistenceStatus !== 'stored' || !hasSleepBatchPayload(batch)) {
        continue;
      }
      batch.partialFailure = true;  // 仅标记失败
      batch.failureCategory ??= 'database';
      batch.failureReason ??= errorMessage;
      batch.warnings = [...new Set([...(batch.warnings ?? []), warning])];
    }
    process.stderr.write(`[telegram-sync] sleep backfill failed: ${errorMessage}\n`);
    // 问题：没有将失败任务加入 pending_task 队列
  }
}
```

**问题机制**：

1. **主事务已提交**：在执行 `sleepBackfill` 前，图片识别结果已经通过 `persistNormalizedBatch` 写入 `ingest.*` 表并提交事务
2. **睡眠回填失败**：`backfillCoreSleepFromIngestBatches` 查询 `ingest.source_batch` 和 `archive.training_sleep`，将睡眠数据合并写入 `core.sleep`，但此过程可能因为：
   - 数据库连接瞬时中断
   - 查询超时
   - 并发冲突
   - 临时资源不足
   而失败
3. **静默标记**：失败后只在 batch 上标记 `partialFailure`，但**不将任务加入 `ingest.pending_task` 进行后续重试**
4. **数据不一致**：`ingest.*` 有完整识别结果，但 `core.sleep` 缺失，导致页面查询时睡眠数据丢失
5. **重发成功**：用户重新发送图片时，识别结果因为 `payloadHash` 不同（包含新的 messageId/updateId）被视为新批次，再次执行 `sleepBackfill` 成功

### 次要问题：增量写入的原子性不足

**位置**：`src/adapters/postgres/incremental-write.pg.mjs:15-36`

```javascript
export async function persistTelegramImageBatchIncremental(client, batch, processedAt, writeOptions = {}) {
  const day = buildTelegramImageBatchDay(batch);
  if (!day) {
    return;
  }
  
  // 问题：这四个插入操作在主事务内，但如果其中某个失败，整个 batch 会被标记为失败
  // 而实际上其他类型的数据（如 measurement、activity）可能已经成功插入
  await ensureCoreTrainingDayStub(client, day.date, batch.batchId, processedAtIso, sourceChannel);
  await insertCoreMeasurements(client, [day], rowOptions, processedAtIso);
  await insertCoreActivities(client, [day], rowOptions, processedAtIso);
  await insertCoreMeals(client, [day], rowOptions, processedAtIso);
  await insertCoreSleep(client, [day], rowOptions, processedAtIso);  // 如果只有这一步失败？
  
  await refreshCoreTrainingDaySummary(client, batch, processedAtIso, sourceChannel);
}
```

虽然这些操作在同一事务内（由外层 `persistNormalizedBatch` 的 BEGIN/COMMIT 控制），但如果在 `insertCoreSleep` 执行期间遇到特定错误（如数据库连接突然中断），事务会回滚，但此时 `ingest.*` 的识别结果已经提交，导致识别结果与核心数据不一致。

### 第三个风险：sleep 去重逻辑的边界条件

**位置**：`src/adapters/postgres/core-row-writer.pg.mjs:441-466`

```javascript
async function deleteCoreSleepRowsByIdentity(client, rows) {
  await client.query(`
    delete from core.sleep existing
    using (
      select * from unnest(
        $1::date[],
        $2::text[],
        $3::text[],
        $4::text[]
      ) as incoming(archived_date, sleep_type, bedtime, wake_time)
    ) incoming
    where existing.archived_date = incoming.archived_date
      and coalesce(existing.sleep_type, '夜间睡眠') = coalesce(incoming.sleep_type, '夜间睡眠')
      and coalesce(existing.bedtime, '') = coalesce(incoming.bedtime, '')
      and coalesce(existing.wake_time, '') = coalesce(incoming.wake_time, '')
  `, [
    rows.map((row) => row.archivedDate),
    rows.map((row) => row.sleepType),
    rows.map((row) => row.bedtime),
    rows.map((row) => row.wakeTime),
  ]);
}
```

这个逻辑在插入前先删除匹配的旧记录，但如果：
- `bedtime` 或 `wakeTime` 为 `null` 时，匹配可能过于宽泛
- 并发场景下，两个 batch 同时处理同一天的睡眠数据时，可能产生竞态条件

## 解决方案

### 方案 1：将 sleepBackfill 失败加入 pending 重试队列（推荐）

**目标**：确保睡眠回填失败时能够自动重试，而不是静默标记为 `partialFailure`

**实施步骤**：

1. **修改 `telegram-sync.use-case.mjs` 的 sleepBackfill 错误处理**：

```javascript
// 位置：src/app/use-cases/telegram-sync.use-case.mjs:500-523
if (shouldRunSleepBackfill({ rawEnv, storedSleepAny })) {
  try {
    await measureSyncStage(timings, 'sleepBackfill', () =>
      backfillCoreSleep({
        processedAt: now,
        sourceChannel: options.sleepBackfillSourceChannel ?? 'telegram_sync',
        targetArchivedDates: [...storedSleepArchivedDates].sort(),
      }),
    );
  } catch (error) {
    const errorMessage = error instanceof Error ? error.message : String(error);
    const failureCategory = classifyFailureCategory(errorMessage, { phase: 'database' });
    const warning = `sleep backfill failed: ${errorMessage}`;
    
    // 新增：对于非用户输入错误，将睡眠批次加入 pending 队列
    for (const batch of batches) {
      if (batch.persistenceStatus !== 'stored' || !hasSleepBatchPayload(batch)) {
        continue;
      }
      
      batch.partialFailure = true;
      batch.failureCategory ??= failureCategory;
      batch.failureReason ??= errorMessage;
      batch.warnings = [...new Set([...(batch.warnings ?? []), warning])];
      
      // 新增：如果不是用户输入错误，加入 pending 重试
      if (failureCategory !== 'user_input') {
        await measureSyncStage(timings, 'queueSleepBackfillReplay', () =>
          appendPendingRecognitionBatch({
            batch: {
              ...batch,
              kind: 'sleep_backfill',  // 新增 kind 类型
              targetArchivedDates: [...storedSleepArchivedDates].sort(),
            },
            failureCategory,
            error: errorMessage,
            failedAt: now.toISOString(),
          }),
        );
        process.stderr.write(
          `[telegram-sync] queued sleep backfill replay for ${batch.batchId} (${batch.archivedDate ?? 'unknown date'}): ${errorMessage}\n`,
        );
      }
    }
    
    process.stderr.write(`[telegram-sync] sleep backfill failed: ${errorMessage}\n`);
  }
}
```

2. **扩展 `ingest.pending_task.kind` 支持**：

当前 `kind` 字段只有 `'image'` 类型，需要支持 `'sleep_backfill'` 类型。

3. **修改 pending replay 逻辑支持睡眠回填重试**：

在 `src/db/training/pending-recognition.mjs` 的重放逻辑中，增加对 `sleep_backfill` kind 的处理。

### 方案 2：增强 sleepBackfill 的幂等性和重试机制

**目标**：让 sleepBackfill 本身更健壮，减少失败概率

```javascript
  const processedAt = options.processedAt ?? new Date();
  const maxRetries = options.maxRetries ?? 3;
  const retryDelayMs = options.retryDelayMs ?? 1000;
  
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      // 原有逻辑
      const hasTargetArchivedDates = Object.hasOwn(options, 'targetArchivedDates');
      // ... 省略查询和处理逻辑 ...
      
      return {
        status: 'stored',
        batchesBackfilled: candidates.length,
        daysBackfilled: [...daysBackfilled].sort(),
      };
    } catch (error) {
      if (attempt < maxRetries) {
        const isRetryable = isRetryableDatabaseError(error);
        if (isRetryable) {
          process.stderr.write(
            `[sleep-backfill] attempt ${attempt}/${maxRetries} failed, retrying in ${retryDelayMs}ms: ${error.message}\n`,
          );
          await new Promise((resolve) => setTimeout(resolve, retryDelayMs));
          continue;
        }
      }
      throw error;
    }
  }
}
```

2. **增加数据库错误分类函数**：

```javascript
function isRetryableDatabaseError(error) {
  const message = error instanceof Error ? error.message : String(error);
  const retryablePatterns = [
    /connection.*terminated/i,
    /connection.*reset/i,
    /timeout/i,
    /deadlock/i,
    /lock.*timeout/i,
    /serialization.*failure/i,
  ];
  return retryablePatterns.some((pattern) => pattern.test(message));
}
```

### 方案 3：改进睡眠数据的去重和身份验证

**目标**：确保睡眠数据的唯一性约束更加精确

**实施步骤**：

1. **优化 `deleteCoreSleepRowsByIdentity` 的匹配逻辑**：

```javascript
async function deleteCoreSleepRowsByIdentity(client, rows) {
  // 增加更精确的匹配条件：当 bedtime 或 wakeTime 为 null 时，额外匹配 totalSleepMinutes
  await client.query(`
    delete from core.sleep existing
    using (
      select * from unnest(
        $1::date[],
        $2::text[],
        $3::text[],
        $4::text[],
        $5::integer[]
      ) as incoming(archived_date, sleep_type, bedtime, wake_time, total_sleep_minutes)
    ) incoming
    where existing.archived_date = incoming.archived_date
      and coalesce(existing.sleep_type, '夜间睡眠') = coalesce(incoming.sleep_type, '夜间睡眠')
      and (
        -- 精确匹配：如果 bedtime 和 wakeTime 都有值，按时间匹配
        (incoming.bedtime is not null and incoming.wake_time is not null
         and coalesce(existing.bedtime, '') = coalesce(incoming.bedtime, '')
         and coalesce(existing.wake_time, '') = coalesce(incoming.wake_time, ''))
        or
        -- 模糊匹配：如果时间缺失，额外匹配总睡眠时长
        (incoming.bedtime is null or incoming.wake_time is null)
         and coalesce(existing.total_sleep_minutes, 0) = coalesce(incoming.total_sleep_minutes, 0)
      )
  `, [
    rows.map((row) => row.archivedDate),
    rows.map((row) => row.sleepType),
    rows.map((row) => row.bedtime),
    rows.map((row) => row.wakeTime),
    rows.map((row) => row.totalSleepMinutes),
  ]);
}
```

### 方案 4：增加数据一致性检查和自动修复

**目标**：定期检查 `ingest` 和 `core` 之间的数据一致性，自动修复丢失

**实施步骤**：

1. **创建数据一致性检查脚本**：

```javascript
// 新文件：tools/check-sleep-data-consistency.mjs
export async function checkSleepDataConsistency(options = {}) {
  const client = await createDatabaseClient(options.env);
  
  try {
    await client.connect();
    
    // 查找 ingest 中有睡眠数据但 core 中缺失的批次
    const inconsistentBatches = await client.query(`
      select 
        b.batch_id,
        b.archived_date,
        b.payload_json->'sleep' as sleep_payload
      from ingest.source_batch b
      where b.status = 'ready'
        and b.archived_date is not null
        and b.payload_json->'sleep' is not null
        and not exists (
          select 1 
          from core.sleep s 
          where s.archived_date = b.archived_date
            and s.source_batch_id = b.batch_id
        )
      order by b.archived_date desc
      limit 100
    `);
    
    return {
      inconsistentCount: inconsistentBatches.rows.length,
      batches: inconsistentBatches.rows,
    };
  } finally {
    await client.end();
  }
}
```

2. **在 `npm run sync:db` 中集成一致性检查和修复**：

```javascript
// 位置：tools/training-maintenance.mjs
async function runSyncPhase() {
  // ... 现有逻辑 ...

  console.log('\n检查睡眠数据一致性...');
  const consistencyResult = await checkSleepDataConsistency({ env: process.env });
  
  if (consistencyResult.inconsistentCount > 0) {

      env: process.env,
      targetArchivedDates: targetDates,
    });
    
    console.log('睡眠数据修复完成');
  } else {
    console.log('睡眠数据一致性检查通过');
  }
}
```
