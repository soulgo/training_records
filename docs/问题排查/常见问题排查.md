# 常见问题排查

本文按现象给出排查顺序。先看 GitHub Actions 日志，再结合本地命令复现。

## 1. 页面没有更新

排查顺序：

1. 看 GitHub Actions 的 `Deploy GitHub Pages` 或 `Telegram Sync` 是否运行。
2. 看 workflow 是否生成并上传 `public/`。
3. 本地运行 `npm run build`，确认 `source/_data/training.json` 和 `source/_data/dashboardView.json` 生成。
4. 检查 `TRAINING_SNAPSHOT_SOURCE` 是否切到 `database`，以及数据库是否可读。
5. 检查 `source/CNAME` 和 GitHub Pages 自定义域名设置。

## 2. `npm run build:data` 失败

常见原因：

- `训练记录.md` 不存在或编码异常。
- `TRAINING_SNAPSHOT_SOURCE=database` 但数据库不可用。
- PostgreSQL schema 缺失或账号权限不足。
- archive 写入失败通常只会写入 `runtime/training-db-sync.ndjson`，不应阻断主输出。

处理：

```bash
$env:TRAINING_SNAPSHOT_SOURCE = "markdown"
npm run build:data
```

如果 Markdown 源可正常构建，再单独排查数据库。

## 3. Telegram 消息没有触发同步

排查顺序：

1. 给 Bot 发送 `/help`，确认 Worker 或同步脚本能回发帮助。
2. 检查 Telegram webhook 是否配置到当前 Worker URL。
3. 检查 Cloudflare Worker 日志是否收到 POST。
4. 检查 Worker 是否返回 `401 unauthorized`。
5. 检查 Worker 是否缺少 `GITHUB_TOKEN`。
6. 检查 GitHub Actions 是否收到 `repository_dispatch: telegram_update`。

相关配置见 [GitHub 与 Cloudflare 配置](../部署维护/GitHub与Cloudflare配置.md)。

## 4. Telegram 图片被跳过

常见原因：

- chat 不在 `TELEGRAM_ALLOWED_CHAT_IDS`。
- AI 识别失败或返回为空。
- 识别置信度低于 0.75。
- 同一批次识别出多个不同日期。
- 图片内无日期，Telegram 又没有保留原始文件名。
- 以 `photo` 发送导致 Bot API 拿不到原始文件名。

处理：

- 一批只发同一天截图。
- 尽量保证截图画面中有日期。
- 需要依赖文件名日期时，用 Telegram `文件` 发送，不要用 `照片`。
- 查看 workflow 输出的 batch `reason`、`warnings`、`issues`。

## 5. PostgreSQL 写入失败

表现：

- 图片批次 `persistenceStatus=fallback_markdown`。
- 随想批次 `persistenceStatus=pending_replay`。
- `runtime/telegram-sync-pending.ndjson` 非空。

处理：

1. 检查 `TRAINING_DB_ENABLED=true` 和 `TRAINING_DB_URL`。
2. 检查数据库网络、SSL、账号权限和 schema。
3. 数据库恢复后运行 `npm run sync:telegram` 重放 pending。
4. 重放成功后 pending 队列会移除对应批次。

## 6. `/分析` 没有回复或回复失败

排查顺序：

1. 确认消息来自白名单 chat。
2. 确认 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` 已配置。
3. 确认 `TRAINING_SNAPSHOT_SOURCE` 对应数据源可读取。
4. 看 Telegram Sync 日志中的 `analysisReplyStatus` 和 `analysisReplyError`。

`/分析` 不会写 `训练记录.md`、`source/_posts` 或 PostgreSQL。

## 7. `/ai` 没有回复或回答缺数据

排查顺序：

1. 确认消息来自白名单 chat。
2. 检查 AI 配置。
3. 检查 `TELEGRAM_AI_AGENT_ALLOWED_TOOLS` 是否限制了所需工具。
4. 若查询数据库源，确认 `TRAINING_SNAPSHOT_SOURCE` 和数据库配置。

当前 `/ai` 只调用 MCP 查询和分析类工具，不写训练记录。

## 8. 随想没有出现在页面

排查顺序：

1. 检查 `source/_posts/YYYY-MM-DD-telegram-thought-<id>.md` 是否生成。
2. 检查 front matter 中 `thought_module` 是否为 `workout`、`misc` 或 `body_feedback`。
3. 检查 tags 是否包含对应模块标签和 `随想`。
4. 运行 `npm run build`。
5. 检查 `themes/cactus/layout/thoughts.ejs` 过滤逻辑是否被修改过。

## 9. 数据库导出覆盖了回退内容

`npm run export:markdown` 在检测到 `runtime/telegram-sync-pending.ndjson` 非空时，会优先使用 Markdown 源，避免数据库未补偿时覆盖回退内容。

如果仍怀疑内容被覆盖，先检查：

- pending 队列是否为空。
- 最近一次 `telegram-sync.yml` 是否执行了 export。
- `训练记录.md` 中是否有 `telegram-fingerprint` 注释。

## 10. 链接或文档失效

文档目录已中文化。新增或移动文档后：

```bash
rg "docs/|docs\\\\" README.md docs
git diff --check
```

优先更新 [文档总览](../README.md) 和项目根 [README](../../README.md)。
