# 系统配置

> 历史归档：本文是迁移前的部署配置快照，不是当前配置入口。当前配置请阅读 [系统配置](../01_系统配置/README.md)。

本文记录当时的系统部署配置。第一部分是需要配置的参数总表（main/dev 分开），第二部分是每个参数在哪里找、在哪里设置的平台配置指南。当时的系统核心逻辑见 [旧系统核心](旧系统核心.md)。

部署涉及 GitHub Actions、Cloudflare Worker/Pages、Telegram、飞书、GitHub Pages、腾讯云 COS 和 PostgreSQL。

基本原则：

- main 和 dev 隔离。
- 外部平台配置需要人工确认。
- 仓库只能证明 workflow、wrangler、代码读取哪些配置，不能证明平台当前值。


## 参数总表

下表列出当时系统需要的全部参数，按 **main 环境** 和 **dev 环境** 分开。完整的当时环境变量说明见 [旧系统核心 > 命令与接口参考 > 环境变量索引](旧系统核心.md#环境变量索引)。

配置位置含义：

- **GitHub Secret**：仓库 Settings → Secrets and variables → Actions → Secrets（敏感值）。
- **GitHub Variable**：仓库 Settings → Secrets and variables → Actions → Variables（非敏感值）。
- **Cloudflare Worker secret/variable**：Cloudflare 控制台 Worker 环境（不在 GitHub）。
- **Workflow env/input**：workflow 固定注入或由 `workflow_dispatch` 输入决定，不在 GitHub Settings 里单独手填。
- **代码支持运行时 env**：代码会读取，但当前 workflow 未必注入；只有手动运行或后续显式把它接入 workflow 时才生效。

> 读法说明：dev 环境里凡是带 `DEV_` 前缀的变量，由 `sync-dev.yml` 读取后映射成运行时同名变量（如 `DEV_COS_BUCKET` → 运行时 `COS_BUCKET`）。**不带 `DEV_` 前缀的变量表示 main 和 dev 共用同一个值**（例如 AI 配置、`TELEGRAM_ALLOWED_CHAT_IDS`）。dev 专属但可选回退 main 的变量用 `DEV_* || *` 表示（例如飞书：dev 优先读 `DEV_FEISHU_*`，未设置时回退 main 的 `FEISHU_*`）。

- `GITHUB_SYNC_REF`：`dev`。


## 平台配置指南

### GitHub（Settings > Secrets and variables > Actions）

**在哪里设置**：仓库 Settings → Secrets and variables → Actions。

- Secret：敏感值（token、key、连接串）。填入后不可从仓库反读。
- Variable：非敏感配置（开关、频率、URL、模型名）。

**在哪里找**：

- `TELEGRAM_BOT_TOKEN` / `DEV_TELEGRAM_BOT_TOKEN`：来自 [@BotFather](https://t.me/BotFather)，`/newbot` 或 `/token`。
- `FEISHU_APP_ID` / `FEISHU_APP_SECRET` / `DEV_FEISHU_*`：来自飞书开放平台应用详情页「凭证与基础信息」。
- `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL`：来自 AI 服务商控制台。
- `TRAINING_DB_URL` / `DEV_TRAINING_DB_URL`：PostgreSQL 连接串，来自数据库提供商或自建实例。
- `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_PAGES_API_TOKEN`：来自 Cloudflare 控制台「My Profile → API Tokens」和「账户首页右下」。
- `COS_SECRET_ID` / `COS_SECRET_KEY`：来自腾讯云 CAM 子账号密钥。

**main/dev 区分**：同一仓库的 GitHub Secrets/Variables 同时被 main 和 dev workflow 读取。区别方式：

- **dev 专属**：带 `DEV_` 前缀的变量（如 `DEV_TELEGRAM_BOT_TOKEN`、`DEV_TRAINING_DB_URL`、`DEV_COS_*`），只有 `sync-dev.yml` 读取并映射成运行时同名变量。
- **main 专属**：无前缀的变量（如 `TELEGRAM_BOT_TOKEN`、`TRAINING_DB_URL`、`COS_*`），只有 `sync.yml` 读取。
- **main/dev 共用**：AI 全部配置、`TELEGRAM_ALLOWED_CHAT_IDS`、`TRAINING_DB_TIMEOUT_MS`、`TRAINING_SNAPSHOT_SOURCE` 等，两个 workflow 读同一个值。
- **dev 可选回退 main**：`DEV_FEISHU_*` 未设置时，`sync-dev.yml` 回退到 main 的 `FEISHU_*`。

配置 dev 环境时，只需新增带 `DEV_` 前缀的变量；共用变量无需重复配置。

**workflow 读取关系**：

| Workflow | 读取的配置 |
| --- | --- |
| `sync.yml`（main） | 无前缀变量：`TELEGRAM_BOT_TOKEN`、`FEISHU_*`、`AI_*`、`TELEGRAM_RECOGNITION_MODEL`、`TELEGRAM_RECOGNITION_FALLBACK_*`、`TRAINING_DB_URL`、`COS_*`、`TRAINING_*` |
| `sync-dev.yml`（dev） | `DEV_*` 前缀变量映射成运行时同名；AI/`TELEGRAM_RECOGNITION_MODEL`/`TELEGRAM_ALLOWED_CHAT_IDS`/`TRAINING_DB_TIMEOUT_MS` 等共用 main 同名变量；`DEV_FEISHU_*` 未设时回退 `FEISHU_*` |
| `deploy-pages.yml` | `CLOUDFLARE_*`、`TRAINING_*` |
| `deploy-cloudflare-pages-dev.yml` | `CLOUDFLARE_PAGES_*`、`DEV_TRAINING_DB_*`、`CLOUDFLARE_*` |
| `markdown-backup.yml` | `MARKDOWN_BACKUP_*`、`TRAINING_DB_URL`（仅 main） |
| `deploy-cloudflare-worker.yml` | 部署 main Worker，并自动写入 main Worker 的 `TELEGRAM_BOT_TOKEN` / `TELEGRAM_SECRET_TOKEN` 后刷新 webhook |
| `deploy-cloudflare-worker-dev.yml` | 部署 dev Worker 并刷新 dev webhook；不自动写入 dev Worker secrets |

### Cloudflare（Workers & Pages 控制台）

**在哪里设置**：Cloudflare 控制台 → Workers & Pages → 选择 Worker → Settings → Variables and Secrets。

Worker secrets（在 Worker 环境配置，不在 GitHub）：

- main Worker 部署 workflow 会自动写入 `TELEGRAM_BOT_TOKEN` 和 `TELEGRAM_SECRET_TOKEN`（来自 GitHub Secrets）。
- dev Worker 部署 workflow 不自动写入 Worker secrets；dev Worker 里的 secret 名仍然是 `TELEGRAM_BOT_TOKEN` 和 `TELEGRAM_SECRET_TOKEN`，值分别对应 GitHub 的 `DEV_TELEGRAM_BOT_TOKEN` 和 `DEV_TELEGRAM_SECRET_TOKEN`。
- `GITHUB_TOKEN`：Worker 触发 GitHub dispatch 用的 token（需要 `repo` 权限），main/dev Worker 都需要在 Cloudflare 平台确认。
- `FEISHU_ENCRYPT_KEY`：飞书事件加密密钥，main/dev Worker 都需要在 Cloudflare 平台确认。
- `FEISHU_VERIFICATION_TOKEN`：飞书事件校验 token，main/dev Worker 都需要在 Cloudflare 平台确认。

Worker variables（非敏感）：

- 必填/常用：`GITHUB_OWNER`、`GITHUB_REPO`、`GITHUB_DISPATCH_EVENT_TYPE`、`GITHUB_DISPATCH_EVENT_TYPE_TELEGRAM`、`GITHUB_DISPATCH_EVENT_TYPE_FEISHU`、`GITHUB_SYNC_WORKFLOW_FILE`、`GITHUB_SYNC_REF`、`GITHUB_RUN_LOOKUP_TIMEOUT_MS`。
- 可选覆盖：`GITHUB_API_BASE_URL`、`TELEGRAM_API_BASE_URL`、`FEISHU_API_BASE_URL`、`FEISHU_SIGNATURE_MAX_SKEW_SECONDS`、`FEISHU_EVENT_LOGGING`、`TELEGRAM_ALBUM_BUFFER_LOGGING`。

Durable Object 绑定（在 `wrangler.toml` / `wrangler.dev.toml` 配置）：

- `TELEGRAM_ALBUM_BUFFER`：Telegram 图片 burst 聚合；类名 `TelegramAlbumBuffer`。
- `FEISHU_IMAGE_BUFFER`：飞书图片 burst 聚合；类名 `FeishuImageBuffer`。
- `SYNC_DISPATCH_QUEUE`：排队触发 GitHub workflow；类名 `SyncDispatchQueue`。

不要把 `SyncDispatchQueue` 当作绑定名；它是 Durable Object class name。代码访问的是 `env.SYNC_DISPATCH_QUEUE`。

部署验证（dry-run）：

```bash
npx wrangler deploy --dry-run --config wrangler.toml
npx wrangler deploy --dry-run --config wrangler.dev.toml
```

真实部署和 secret 状态需要 Cloudflare 控制台或 wrangler 实际环境确认。

Pages：

- 生产站点由 GitHub Pages 发布（不走 Cloudflare Pages）。
- dev 预览由 Cloudflare Pages 发布，项目名由 `CLOUDFLARE_PAGES_DEV_PROJECT_NAME` 决定，默认地址 `https://training-records-dev.pages.dev`。
- dev 构建前使用 dev 数据库变量，上传前删除 `public/CNAME`，避免覆盖生产域名。

### Telegram（@BotFather）

**在哪里找 token**：[@BotFather](https://t.me/BotFather) → `/newbot` 创建机器人，或 `/token` 获取已有机器人 token。

**在哪里设置 webhook**：

- 自动：`refresh-telegram-webhook.yml` 每 6 小时刷新，或 `deploy-cloudflare-worker.yml` 部署后刷新。
- 手动：`npm run telegram:webhook`。

webhook 目标 URL 是 Cloudflare Worker 的入口地址，由 `TELEGRAM_WEBHOOK_URL`（main）或 `DEV_TELEGRAM_WEBHOOK_URL`（dev）指定。

`npm run telegram:webhook` 支持两个可选运行时 env：

- `TELEGRAM_WEBHOOK_ALLOWED_UPDATES`：逗号分隔的 Telegram update 类型，默认 `message,edited_message`。
- `TELEGRAM_WEBHOOK_DROP_PENDING_UPDATES`：是否让 Telegram 丢弃旧 pending updates，默认 `false`。

当前 `refresh-telegram-webhook.yml`、`deploy-cloudflare-worker.yml` 和 `deploy-cloudflare-worker-dev.yml` 没有注入这两个可选变量；需要临时覆盖时应在手动运行环境里显式传入，或先把 workflow 接线。

secret token：

- 自定义 `X-Telegram-Bot-Api-Secret-Token` 校验值。
- main：同一个值需同时存在于 GitHub Secret `TELEGRAM_SECRET_TOKEN` 和 main Worker secret `TELEGRAM_SECRET_TOKEN`；main deploy workflow 会自动写入 Worker 侧。
- dev：GitHub Secret 使用 `DEV_TELEGRAM_SECRET_TOKEN`，但 dev Worker secret 名仍为 `TELEGRAM_SECRET_TOKEN`，值需与 `DEV_TELEGRAM_SECRET_TOKEN` 一致；dev deploy workflow 不会自动写入。

验证：

发送 `/help`，确认 Worker 或同步脚本能回复。再发送一张有清晰日期的测试截图，查看 Actions summary 和数据库结果。

2. `/帮助` 能回复。

### 腾讯云 COS

COS 只用于随想图片附件，不用于训练截图识别原图归档。默认 `COS_ENABLED` 未开启时继续写本地 `source/images/thoughts`。

**在哪里找**：腾讯云控制台 → 对象存储（创建 bucket）+ 访问管理 CAM（创建子账号获取密钥）。

main 配置（`sync.yml` 读取）：

- `COS_ENABLED`：开关。
- `COS_PROVIDER`：默认 `tencent_cos`。
- `COS_SECRET_ID` / `COS_SECRET_KEY`：腾讯云 CAM 子账号密钥。
- `COS_BUCKET`：bucket 名。
- `COS_REGION`：bucket 所在 region。
- `COS_DOMAIN`：公有读域名，当前必须用腾讯云默认 HTTPS 域名 `https://{COS_BUCKET}.cos.{COS_REGION}.myqcloud.com`。
- `COS_PATH_PREFIX`：路径前缀。

dev 配置（`sync-dev.yml` 读取 `DEV_COS_*`，映射成运行时 `COS_*`）。

要求：

- bucket 访问模型是私有写、公有读；不要改成私有读，否则已落库的静态 URL 会失效。
- CAM 子账号需要 `PutObject` / `HeadObject` / `GetObject` 权限。
- dev 和 main 应使用独立 bucket、独立 CAM 子账号、独立 domain 和独立 prefix。
- `sync-dev.yml` 会 fail fast 校验 dev bucket/domain 不得等于 main。

不需要 COS Secret 的组件：

- Cloudflare Worker。
- Pages deploy。
- Markdown backup。

### PostgreSQL

**在哪里找**：数据库连接串来自数据库提供商（如 Supabase、Neon、自建实例）。

main：`TRAINING_DB_URL`。
dev：`DEV_TRAINING_DB_URL`。

相关变量：

- `TRAINING_DB_ENABLED`：是否启用 PostgreSQL。
- `TRAINING_DB_TIMEOUT_MS`：连接超时，默认 5000ms；数据库偶发抖动时可适当调大。
- `TRAINING_SNAPSHOT_SOURCE`：`markdown` 或 `database`，线上推荐 `database`。
- `TRAINING_SNAPSHOT_STRICT_DATABASE`：严格数据库模式，数据库源失败时不回退 Markdown，默认 `false`。DB-only 异步部署会启用 `true`。

初始化 SQL：

- `sql/pgsql17.sql` 是汇总初始化脚本。
- `sql/training_records/core.sql`、`ingest.sql`、`archive.sql` 是分层维护入口。


## main/dev 环境矩阵

| 项 | main | dev |
| --- | --- | --- |
| 同步 workflow | `sync.yml` | `sync-dev.yml` |
| 同步分支 | `main` | `dev` |
| Worker 配置 | `wrangler.toml` | `wrangler.dev.toml` |
| Telegram dispatch | `telegram_update` | `telegram_update_dev` |
| 飞书 dispatch | `feishu_update` | `feishu_update_dev` |
| 数据库连接串 | `TRAINING_DB_URL` | `DEV_TRAINING_DB_URL` |
| 数据库开关 | `TRAINING_DB_ENABLED`（变量） | 硬编码 `true` |
| Telegram Bot token | `TELEGRAM_BOT_TOKEN` | `DEV_TELEGRAM_BOT_TOKEN` |
| Telegram chat 白名单 | `TELEGRAM_ALLOWED_CHAT_IDS`（共用） | `TELEGRAM_ALLOWED_CHAT_IDS`（共用） |
| 飞书凭证 | `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | `DEV_FEISHU_*`（可选，未设回退 main） |
| AI 配置 | `AI_*`（共用） | `AI_*`（共用） |
| COS 图片存储 | `COS_*` | `DEV_COS_*`（bucket/domain 必须 ≠ main） |
| Pages | GitHub Pages（生产域名） | Cloudflare Pages（dev 预览） |
| Markdown 备份 | `markdown-backup.yml`（仅 main） | 无 |

原则：

- dev 不能误写 main 数据库。
- dev 不能使用 main COS bucket 或 domain。
- dev Request URL 不能填生产 Worker。
- main deploy 不能使用 dev CNAME 或 dev DB。

## Secrets 维护规则

- 文档只记录变量名和用途，不记录 secret 值。
- GitHub Secret 值不可从仓库反读。
- Cloudflare Worker secret 需要在目标环境单独配置。
- 平台当前值需要人工确认。
- 新增变量时必须同步检查 `.github/workflows/*.yml`、`wrangler*.toml`、`src/`、`tools/`、`cloudflare/`。
- 删除变量前必须确认没有 workflow、Worker、CLI 或测试仍在读取。

Secrets 分类：

| 类别 | 示例 |
| --- | --- |
| 通道 | `TELEGRAM_BOT_TOKEN`、`FEISHU_APP_ID` |
| AI | `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` |
| 数据库 | `TRAINING_DB_URL`、`DEV_TRAINING_DB_URL` |
| Worker | `GITHUB_TOKEN`、`TELEGRAM_SECRET_TOKEN`、`FEISHU_ENCRYPT_KEY` |
| Pages | `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID` |
| 图片存储 | `COS_*`、`DEV_COS_*` |
