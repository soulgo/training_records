## 重点验证项结论

| 验证项 | 结论 | 依据 |
|---|---|---|
| 幂等性是否真实存在 | ✔ 真实存在 | telegram_message / telegram_recognition / thought 主键均为 `(source_channel, source_chat_id, source_message_id)`；upsert 均 ON CONFLICT |
| 顺序执行是否可能乱序 | ⚠ 不同任务串行成立；同任务 run 查询异常后存在重复 dispatch 窗口 | DO 单线程 + processing 标记保证互异任务串行；但 `dispatchGithubTask` 成功后若 `findDispatchedRunId` 抛错，重试保留旧 `phase: 'dispatch'`，会再次创建 workflow run |
| AI fallback 是否真的不一致 | ⚠ 部分成立 | strict→json_object→无格式链解析逻辑一致；但 fallback provider 切换不检查置信度，attemptKind 区分但输出结构一致 |
| 双通道是否真的字段不一致 | ✔ 成立 | 飞书 source id 哈希成数字塞进 telegram_message_id；导出/随想定位/缓存 join 仍以数字 messageId 为主 |
| 是否真的存在重复写库 | ✖ 未发现隐性重复写库 | 主链路在单事务内按顺序 upsert，无并行多路径写同一表 |
| 是否真的存在隐性丢数据路径 | ⚠ 部分成立 | Markdown 备份先删后写非原子成立；但 commit 是 diff 驱动而非"无条件"，措辞需修正 |

## 判定标准

- **✔ 已验证（代码支持）**：声称的代码位置、机制、行为与实际代码完全一致。
- **⚠ 部分成立（条件成立）**：核心机制存在，但声称的代码位置、措辞或触发条件需修正/补充。
- **✖ 未验证（代码无依据）**：代码中找不到声称的机制，或声称与现实相反。
