# 数据安全优化

## 结论

当前系统已经有脱敏工具，但没有覆盖同步命令的 raw stdout 和 GitHub Actions 的 env 展示。结果是：Action 成功 run 中仍能看到 chat id、飞书 `oc_`、COS bucket/domain、AI base URL、`sourceId`、`chatIds` 等敏感标识。

这不是功能正确性问题，而是数据暴露面问题，应优先修。

## 优先级划分

| 优先级 | 事项 | 代码/日志依据 | 验收重点 |
| --- | --- | --- | --- |
| 高 | sync CLI stdout 改 safe report，完整 report 只写 result path。 | `telegram-sync.use-case.mjs:80-83` pretty-print 完整 report；workflow `tee` 进日志。 | 新 run 日志不出现 `sourceId`、`chatIds`、`oc_`、file/caption/prompt。 |
| 高 | workflow env 展示和 dev COS 隔离检查不再泄露敏感标识。 | `.github/workflows/sync.yml:124-160` 使用 vars 注入；`sync-dev.yml:163-170` 内联比较 prod COS 值。 | 新 run 日志不出现完整 chat id、COS bucket/domain、AI base URL。 |
| 中 | 配置并验证只读 DB URL。 | `src/db/training/config.mjs` 支持 readonly；抽样 run 中 `TRAINING_DB_READONLY_URL:` 为空。 | 只读任务使用 readonly user，权限摘要无 superuser/migrator-like。 |
| 中 | sync workflow 权限拆分或保留说明。 | `sync.yml` / `sync-dev.yml` 同时有 `contents: write`、`actions: write`。 | 写仓库、dispatch deploy、通知 summary 权限边界清楚。 |
| 低 | 历史日志保留和复核记录。 | 历史 run 已有明文标识。 | 新日志脱敏后记录复核 run，不复制历史明文。 |

## 问题 1：workflow env 展示泄露配置标识

抽样日志中可见：

```text
AI_BASE_URL: https://www.packyapi.com/v1
TELEGRAM_ALLOWED_CHAT_IDS: 6314355239
FEISHU_ALLOWED_CHAT_IDS: oc_...
COS_BUCKET: training-records-...
COS_DOMAIN: https://training-records-...
TRAINING_DB_READONLY_URL:
```

`AI_API_KEY`、token、DB URL 这类 secrets 会被 GitHub mask，但 repository vars 不会自动隐藏。chat id、Feishu `oc_`、COS bucket/domain 虽不是传统 secret，也足以关联用户身份、数据桶和运行环境。

建议：

- 把 chat id、Feishu `oc_`、COS bucket/domain/path prefix 等“敏感标识型配置”从 vars 移到 secrets，或在 workflow 启动前通过安全脚本读取，避免 raw env 展示。
- 不在 `run:` 脚本里直接内联 `${{ vars.COS_BUCKET }}` / `${{ vars.COS_DOMAIN }}`。dev/main COS 隔离检查改为 Node 脚本读取 env 后比较 hash 或布尔结果。
- 对非 secret 但不该公开的值，使用 `::add-mask::` 只能作为辅助；不能依赖它遮住同一步开始时已经展示的 env。

验收：

```text
gh run view <run-id> --log | rg -n "oc_|6314355239|COS_BUCKET|COS_DOMAIN|training-records-pro|training-records-dev|AI_BASE_URL"
```

目标：无明文命中，或只出现 GitHub mask 后的 `***`。

## 问题 2：同步 CLI stdout 输出完整 report

`src/app/use-cases/telegram-sync.use-case.mjs:80-83` 默认 pretty-print 完整 `buildTelegramSyncReport(result)`。workflow 又在 `Sync updates` 中执行：

```text
npm run <sync_command> 2>&1 | tee "$log_path"
```

因此完整 report 会进入 Action log。抽样 run 中可见完整：

```text
sourceId: "feishu:chat:oc_..."
chatIds: ["oc_..."]
```

建议：

- CLI stdout 默认只输出安全摘要，例如 `{status, changed, readyBatches, pendingCount, timingsMs}`。
- 完整 report 只写入 `TELEGRAM_SYNC_RESULT_PATH` / `FEISHU_SYNC_RESULT_PATH`，供后续 summary/notify step 读取。
- 如果本地需要完整调试，新增显式 `--debug-json` 或 `SYNC_DEBUG_JSON=true`，并在 GitHub Actions 中阻断。
- stdout/stderr 统一走 `redactSensitive()` 或新的 `buildSafeSyncReport()`。

验收：

```text
gh run view <run-id> --log | rg -n "sourceId|chatIds|fileUniqueId|file_id|caption|prompt|oc_"
```

目标：无明文业务标识；summary 中只保留 hash、计数和安全状态。

## 问题 3：`TRAINING_DB_READONLY_URL` 抽样为空

系统文档和数据库优化规划已经支持 `TRAINING_DB_READONLY_URL` / `DEV_TRAINING_DB_READONLY_URL`。但本次 main/dev 抽样日志里 `TRAINING_DB_READONLY_URL:` 为空，说明至少这些 run 没有使用只读连接。

建议：

- 在 main/dev GitHub Secrets 配置只读连接串。
- `maintenance:inspect`、站点构建、分析快照读取优先只读；缺失时在 summary 中给出安全 warning，不输出 URL。
- 把“是否配置 readonly URL”作为安全验收项，而不是只看代码是否支持。

验收：

- `npm run maintenance:inspect` 的 DB 权限摘要显示 current user 不是 superuser / migrator-like。
- `database.permissionAudit.schemaCreatePrivileges` 对业务/只读运行账号为 false。
- Action log 不输出 DB URL。

## 问题 4：workflow 权限仍偏宽

`sync.yml` / `sync-dev.yml` 使用：

```text
permissions:
  contents: write
  actions: write
```

当前原因可以理解：同步需要提交派生数据，且需要 dispatch deploy workflow。但所有 step 都处在同一个 job 权限下，暴露面偏大。

建议：

- 评估拆成两个 job：同步提交 job 需要 `contents: write`，deploy dispatch job 才需要 `actions: write`。
- 通知和 summary step 不需要写权限时，尽量不要共享高权限 token。
- deploy workflow 已是 `contents: read`，保持不扩大。

## 问题 5：日志保留与回溯策略

在完成脱敏前，历史 Action log 已经包含敏感标识。建议：

- 缩短包含同步 raw stdout 的 workflow log retention。
- 完成脱敏后记录一次安全复核 run id。
- 不把旧日志里的明文标识复制到新文档或 issue；文档只写模式和 hash。

## 安全验收清单

- [ ] `gh run view <new-run> --log` 不出现飞书 `oc_`、Telegram chat id、完整 COS bucket/domain、`sourceId`、`chatIds`。
- [ ] Action summary 仍能显示批次状态、AI 耗时、DB rowCounts、pending/rollback、image storage 计数。
- [ ] `TRAINING_DB_READONLY_URL` / `DEV_TRAINING_DB_READONLY_URL` 已配置，读取型任务优先只读。
- [ ] sync job 权限拆分或有明确保留说明。
- [ ] 新增测试覆盖 stdout safe report 和 summary 脱敏。
