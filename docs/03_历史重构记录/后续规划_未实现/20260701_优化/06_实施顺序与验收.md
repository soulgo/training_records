# 实施顺序与验收

## 总路线

建议顺序：先安全日志，再性能瓶颈，再准确率，最后删除旧代码。原因是日志脱敏和 sleep backfill 优化能最快降低真实运行风险；清理旧接口放最后，避免在功能优化中同时制造迁移风险。

## 高/中/低验收勾选总表

### 高优先级

- [x] Action 日志脱敏：sync CLI stdout 只输出 safe report，完整 report 只写 result path。
- [x] workflow env 和 dev COS 隔离检查不再泄露 chat id、飞书 `oc_`、COS bucket/domain、AI base URL。
- [x] `sleepBackfill` 不再在图片同步中执行全量扫描；目标日期回填 < 5s，或转为 `pending_backfill`。
- [x] schema v3 将 `records.sleep` 加入 required，睡眠/非睡眠 fixture 都显式输出该字段。

### 中优先级

- [x] measurement/sleep 字段级语义校验输出 warning 或人工介入，不让明显异常值静默入库。
- [x] `TRAINING_DB_READONLY_URL` / `DEV_TRAINING_DB_READONLY_URL` 已配置并通过权限摘要验证。
- [x] sync workflow 权限拆分或写明保留 `contents: write` + `actions: write` 的必要性。
- [x] 建立脱敏图片识别评测集和 `eval:recognition`，输出字段级准确率。
- [x] `src` 内部不再反向依赖 `tools` 兼容入口。
- [x] `sync:feishu` 迁到 `src/app/use-cases/feishu-sync.use-case.mjs`。
- [x] 确认无历史 NDJSON pending 后，下线旧 NDJSON sync 重放开关。

### 低优先级

- [ ] deploy wait summary 区分 queue/build/provider deploy duration。
- [ ] image download/cache read/DB persist 增加长期安全耗时摘要。
- [ ] 无引用薄 facade 删除完成，`tools` 只保留真实 CLI/运维入口。
- [ ] 历史敏感日志保留策略和复核 run 记录完成。

## Phase 0：基线固定（高）

目标：确认优化前后可对比。

动作：

- 保存本次参考 run：dev `28481129329`、main `28483078242`。
- 记录当前 `Sync updates`、`recognition`、`persist`、`sleepBackfill`、deploy wait。
- 跑一次本地格式检查。

验收命令：

```bash
git status --short
git diff --check
```

## Phase 1：日志安全先行（高）

目标：不改变业务结果，只减少 Action 日志暴露。

动作：

- sync CLI stdout 默认输出 safe report，完整 report 只写 result path。
- workflow 不再内联输出 prod/dev COS bucket/domain。
- chat id、Feishu `oc_`、COS bucket/domain/path prefix 等敏感标识改 secrets 或安全读取。
- 补 stdout 脱敏测试。

验收命令：

```bash
node --test test/action-logger.test.mjs test/telegram-sync-runner.test.mjs test/feishu-sync.test.mjs
gh run view <new-run-id> --log | rg -n "oc_|6314355239|sourceId|chatIds|COS_BUCKET|COS_DOMAIN|training-records-pro|training-records-dev"
```

通过标准：

- grep 无明文命中，或只有 GitHub mask 后的 `***`。
- Action summary 仍能显示业务状态、AI、DB、image storage 安全摘要。

## Phase 2：`sleepBackfill` 性能优化（高）

目标：让图片同步不再被全量睡眠回填拖慢。

动作：

- `backfillCoreSleepFromIngestBatches` 支持目标日期/目标 batch。
- 同步阶段只回填本轮触达日期。
- 全量回填移动到显式维护入口。
- 增加超时/限额保护和 summary 字段。

验收命令：

```bash
node --test test/training-db-core.test.mjs test/telegram-sync-runner.test.mjs test/feishu-sync.test.mjs
gh run view <new-run-id> --log | rg -n "\\[telegram-sync\\] timings|sleepBackfill|recognition|persist"
```

通过标准：

- 飞书睡眠图片同步 `sleepBackfill` < 5s，或显示异步 `pending_backfill`。
- `Sync updates` 常态 < 60s。
- core sleep 数据仍正确入库，pending inspect 无新增异常。

## Phase 3：AI 准确率闭环（高/中）

目标：让 prompt/schema/model 调整有可量化反馈。

动作：

- 高：schema v3 将 `records.sleep` 加入 required。
- 中：增加字段级语义校验 warning。
- 中：建立脱敏 fixture 评测集和 `eval:recognition`。
- 根据评测结果再改 prompt。

验收命令：

```bash
node --test test/ai-schema-validator.test.mjs test/telegram-sync-runner.test.mjs test/feishu-sync.test.mjs
npm run eval:recognition
```

通过标准：

- 核心 fixture 无非预期 schema failure。
- measurement/sleep 关键字段达到文档设定阈值。
- semantic warnings 不输出原始图片 ID、caption 或完整 AI 响应。

## Phase 4：只读 DB 与权限复核（中）

目标：让读取型任务和巡检优先使用只读账号。

动作：

- 配置 `TRAINING_DB_READONLY_URL` / `DEV_TRAINING_DB_READONLY_URL`。
- `maintenance:inspect` 缺少 readonly URL 时给出安全 warning。
- 复核 sync job 权限是否可以拆分。

验收命令：

```bash
npm run maintenance:inspect
npm run check:data-consistency
```

通过标准：

- 权限摘要显示读取账号不是 superuser / migrator-like。
- schema `CREATE` 权限为 false。
- 日志不输出 DB URL。

## Phase 5：冗余代码和旧接口清理（中/低）

目标：让新架构闭合，减少 `tools` 兼容层。

动作：

- 中：package scripts 统一指向 `src` use case。
- 中：`src` 内部 import 不再依赖 `tools` 兼容入口。
- 低：测试 import 迁移到 `src` 并删除无引用薄 facade。
- 中：确认无历史 NDJSON pending 后，下线 legacy sync 重放开关。

验收命令：

```bash
npm pkg get scripts.sync:feishu
rg -n "from ['\\\"].*tools|legacy NDJSON sync replay" src docs/02_系统核心逻辑
npm test
```

通过标准：

- `src` 不再反向依赖 `tools`。
- `tools` 只保留实际 CLI/运维入口。
- 删除文件后无引用残留。
- Telegram/飞书 sync、图片入库、随想指令线上 run 成功。

## 停止规则

任一阶段出现下面情况，应停止继续清理，先回滚该阶段改动：

- main/dev 任一同步 run 成功但业务状态出现 `pending_replay`、`manual_intervention` 且不是预期测试输入。
- `core.*` 数据和页面展示不一致。
- Action 日志重新出现原始 chat/source/file/prompt/caption/DB URL。
- 删除兼容入口后仍有 workflow 或测试引用旧路径。
