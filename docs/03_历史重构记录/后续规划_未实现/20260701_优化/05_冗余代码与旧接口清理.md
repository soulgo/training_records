# 冗余代码与旧接口清理

## 结论

多轮重构后，系统已经形成 `src` 目录下的新结构，但 `tools` 目录仍同时承担三类职责：

1. 仍在使用的运维 CLI。
2. 兼容旧测试/旧脚本的薄 facade。
3. 尚未迁入 `src` 的少量运维实现。

因此不能“一刀切删除 tools”。正确路线是先迁移引用、统一入口，再删除已经无引用的 facade 和老旧兼容接口。

## 优先级划分

| 优先级 | 事项 | 代码依据 | 验收重点 |
| --- | --- | --- | --- |
| 中 | `src` 内部 import 不再反向依赖 `tools`。 | 已迁移，真实实现位于 `src`，`tools` 仅保留 CLI/兼容转发壳。 | `rg "from ['\\\"].*tools" src` 无核心业务命中。 |
| 中 | `sync:feishu` 入口迁到 `src` use case。 | 已迁移为 `node src/app/use-cases/feishu-sync.use-case.mjs`。 | package script、workflow、测试全部通过新入口。 |
| 中 | 下线旧 NDJSON pending 前做历史队列确认。 | 本地旧 NDJSON 队列为空，sync 主链路已下线旧 NDJSON 重放开关。 | 无历史队列后删除 env、测试分支和旧文档。 |
| 低 | 删除无引用薄 facade。 | 多个 `tools/*` 当前只是 re-export，但测试仍引用。 | 迁移测试 import 后 `rg` 无引用再删。 |
| 低 | magic number/config 集中化。 | 本轮未发现直接导致问题的阈值。 | 遇到容量/性能问题时顺手归并，不单独阻塞。 |

## 建议删除顺序

1. 已完成：迁移 package script，`sync:feishu` 指向 `src/app/use-cases/feishu-sync.use-case.mjs`。
2. 已完成：改 `src` 内部 import，不再从 `tools` 引入业务模块。
3. 后续低优先级：迁移测试 import，优先改薄 facade 的测试引用。
4. 删除 A 类薄 facade，并用 `rg` 验证没有残留引用。
5. 迁移 B 类真实实现到 `src`，`tools` 只保留 CLI 壳。
6. 已完成：确认本地旧 NDJSON pending 为空并下线 sync 重放开关；独立 inspect 工具留待后续低优先级清理。

## 不建议删除的内容

- `tools/training-maintenance.mjs`：当前仍是维护入口。
- `tools/action-sync-summary.mjs`：当前 workflow summary 依赖它，且安全 formatter 有价值。
- `tools/run-hexo-command.mjs`、`tools/merge-dev-to-main.mjs`、`tools/check-*`：属于运维/质量 CLI，不是冗余代码。
- `tools/*-notify.mjs`、`tools/*-monitor.mjs`：workflow 仍调用，先做脱敏和入口统一，后续再评估。
