# 10 最终建议：基于现有代码的收敛性建议

## 一句话结论

本轮不要迁移 Skills，不要重做识别架构。先修 Prompt/schema/fallback 的真实合同问题，再用测试保护 Prompt source、batch 归档和 DB 映射。

## 当前应执行的路线

推荐顺序：

1. P0 合同修复。
2. Prompt source 文案收敛。
3. caption/text 边界。
4. 最小 fixtures。
5. Prompt source 模块化。
6. DB 映射验证。

这个顺序对应当前代码依赖：

```text
prompts/_source
  -> tools/prompt-generator.mjs
  -> prompts/telegram-training-image-recognition.md
  -> loadRecognitionSystemPrompt()
  -> recognizeTelegramImageMessage()
  -> buildRecognitionSchema()
  -> analyzeTelegramBatch()
  -> persistNormalizedBatch()
  -> core.*
```

## 必须优先修复的 3 个 P0

### 1. `records.sleep` required 合同

当前 Prompt 要求 sleep 图输出 `records.sleep`，但 schema 的 `records.required` 未包含 `sleep`。

建议：

- 改 `src/core/ai/telegram-recognition-schema.mjs`。
- 补 `test/ai-schema-validator.test.mjs`。

### 2. meals recommended nullable 合同

当前 Prompt 和 SQL 都允许推荐范围为空，但 schema 不允许。

建议：

- `recommendedMin/recommendedMax` 改为 `['number', 'null']`。
- 补 schema 测试和 DB 写入测试。

### 3. fallback Prompt 漏 sleep

当前生成 Prompt 支持 sleep，但硬编码 fallback Prompt 不支持。

建议：

- 改 `src/app/use-cases/telegram-sync/image-processing.mjs`。
- 补 fallback 测试。

## 当前不建议做的事

- 不建议迁移 Skills。
- 不建议拆成分类调用 + 专项调用。
- 不建议设计统一识别引擎。
- 不建议新增 workout sets/reps/weight 字段。
- 不建议新增 nutrition foods/macros 字段。
- 不建议改 DB 表结构。

理由很直接：这些不是当前代码已有能力，本轮目标是“文档代码一致性校准 + 可落地性收敛”，不是重做架构。

## 最终收敛结论

当前最优目标模型是：

```text
结构化 Prompt source
  -> 生成单一运行时 Prompt
  -> schema v2 合同
  -> 单次图片识别
  -> JSON/schema/业务归一化
  -> batch 日期和置信 gate
  -> ingest 审计
  -> core 事实表
```

Skills、动态 Prompt、多调用专项识别都不是本轮目标。只有当 P0 合同修复、fixtures 和字段级评估完成后，才有资格重新讨论是否需要更大的识别架构升级。
