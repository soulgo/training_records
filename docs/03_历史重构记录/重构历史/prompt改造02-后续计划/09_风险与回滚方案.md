# 09 风险与回滚方案：仅保留代码中真实风险

## 范围

本风险清单只覆盖当前代码中真实存在的链路：

- Prompt source 和生成 Prompt。
- schema 校验。
- fallback Prompt。
- AI 请求和 JSON 解析。
- batch 日期/置信/字段合并。
- ingest/core 入库。
- Telegram/飞书共享链路。

不覆盖未实现内容：

- NOT IMPLEMENTED IN CODE：Skills 运行时。
- NOT IMPLEMENTED IN CODE：多次 AI 调用。
- NOT IMPLEMENTED IN CODE：统一识别引擎。

## R1：生成 Prompt 丢规则

### 真实触发点

- 修改 `prompts/_source/*.json`。
- 修改 `tools/prompt-generator.mjs`。
- 拆分 `prompts/_source/recognition/*.json`。

### 可能表现

- 生成 Prompt 缺少某个 `imageType`。
- app profile alias 被截断或丢失。
- sleep total/night 不相加规则丢失。
- caption/text 日期禁止规则丢失。

### 控制

- `test/prompt-generator.test.mjs` 增加关键规则断言。
- 每次改 source 后运行 `node tools/prompt-generator.mjs`。
- 不手写 `prompts/telegram-training-image-recognition.md`。

### 回滚

1. 回退 `prompts/_source/*` 或拆分 source。
2. 回退 `tools/prompt-generator.mjs`。
3. 重新运行：

```bash
node tools/prompt-generator.mjs
node --test test/prompt-generator.test.mjs
```

4. 如需临时生产回滚，设置 `TELEGRAM_RECOGNITION_PROMPT_PATH` 指向旧 Prompt 文件。

## R2：schema 改动导致识别失败增加

### 真实触发点

- 修改 `src/core/ai/telegram-recognition-schema.mjs`。

### 可能表现

- AI 返回被 `validateAiJsonValue()` 拒绝。
- `AiSchemaError` 增加。
- `recognitionErrors` 增加，batch 被 pending 或 skipped。

### 当前高风险点

- `records.sleep` required 修复后，旧缓存或旧模型输出缺 sleep 可能失败。
- `recommendedMin/Max` nullable 修复是放宽，风险较低。

### 控制

- schema 修复必须配套 `test/ai-schema-validator.test.mjs`。
- `normalizeRecognitionPayload()` 已补 `records.sleep: null`，需确认非 sleep 图片不受影响。
- 先跑 `test/ai-recognition-service.test.mjs` 和 `test/telegram-sync.test.mjs`。

### 回滚

1. 回退 schema 文件。
2. 回退对应测试期望。
3. 如果已 bump Prompt metadata/schemaVersion，保持 cache key 一致性，避免新旧缓存混用。

## R3：fallback Prompt 与生成 Prompt 不一致

### 真实触发点

- `prompts/telegram-training-image-recognition.md` 读取失败。
- `TELEGRAM_RECOGNITION_PROMPT_PATH` 指向不存在或空文件。
- fallback 文本过时。

### 可能表现

- sleep 图片无法按当前能力识别。
- fallback 允许的 `imageType` 与 schema 不一致。
- 生产排障时误判为模型问题。

### 控制

- 给 fallback Prompt 增加测试。
- fallback 文本至少覆盖五类 `imageType` 和日期边界。

### 回滚

- 回退 `src/app/use-cases/telegram-sync/image-processing.mjs`。
- 或修复 Prompt 文件路径/内容，让运行时不走 fallback。

## R4：caption/text 干扰识别

### 真实触发点

- `buildRecognitionMessages()` 直接拼入用户 caption/text。
- 飞书 text/caption 也映射到同一结构。

### 可能表现

- 用户文本影响分类或字段。
- 超长文本增加请求体和超时风险。
- caption 中日期被模型误当截图日期。

### 控制

- 增加截断。
- user text 中标明 caption/text 只是外部上下文。
- Prompt 和 `sync-dates.adapter.mjs` 继续禁止 caption/text 成为 `detectedDate`。

### 回滚

- 回退 `buildRecognitionMessages()` 改动。
- 如果新截断误伤必要上下文，调大 maxLength 并补测试。

## R5：日期归档错误或跳过增加

### 真实触发点

- 修改 `prompts/_source/recognition-rules.json` 日期规则。
- 修改 `src/adapters/telegram/sync-dates.adapter.mjs`。
- 修改 `src/adapters/telegram/sync-batch-logic.adapter.mjs`。

### 可能表现

- `conflicting detected dates` 增加。
- `no reliable image or filename date` 增加。
- sleep 归档日期错一天。
- document filename fallback 行为变化。

### 控制

- 保持 AI/程序日期职责分层：
  - AI 只输出截图内可见日期。
  - 程序处理 filename fallback。
  - 程序处理 sleep 醒来日期减一天。
- 跑日期相关测试。

### 验证

```bash
node --test test/telegram-sync.test.mjs test/telegram-sync-runner.test.mjs
```

### 回滚

- 回退日期 Prompt source。
- 回退 `sync-dates.adapter.mjs` 或 batch 逻辑。
- 使用 ingest `batch_payload_json` 和 `recognition_json` 按 batchId 排查。

## R6：DB 写入字段不匹配

### 真实触发点

- 修改 `src/adapters/postgres/incremental-write.pg.mjs`。
- 修改 `src/adapters/postgres/core-row-writer.pg.mjs`。
- 修改 SQL schema。
- 修改 batch payload 字段。

### 可能表现

- core insert/update 报错。
- nullable 字段被错误写成 0。
- sleepStageDetail 类型不匹配。
- training_day 汇总覆盖已有值。

### 控制

- 以 `sql/training_records/core.sql` 为合同。
- 不新增 DB 字段。
- DB 写入改动必须跑 `test/training-db-core.test.mjs`。

### 回滚

1. 回退 writer 改动。
2. 如果只是 core 写入风险，保留 ingest 写入，暂停 core 写入逻辑。
3. 用 `ingest.telegram_batch.batch_payload_json` 和 `ingest.telegram_recognition.recognition_json` 定位重放来源。

## R7：Telegram 与飞书行为分叉

### 真实触发点

- 修改 `runFeishuSync()` 注入参数。
- 修改 `groupFeishuUpdates()` 映射。
- 修改 `recognizeBatch()` 的 sourceChannel/input mode 逻辑。
- Prompt 写入 Telegram-only 语义。

### 可能表现

- Telegram 图片 ready，飞书图片 skipped。
- Feishu inline image 下载或识别失败。
- sourceChannel 丢失，写入 core 变成 telegram。

### 控制

- 保持飞书通过 `runTelegramSync()` 复用链路。
- 保持 `sourceChannel: 'feishu'` 透传。
- 跑 `test/feishu-sync.test.mjs`。

### 回滚

- 回退飞书 adapter/use-case 改动。
- 临时设置 `FEISHU_RECOGNITION_IMAGE_INPUT_MODE` 回到已验证模式。

## R8：识别缓存命中旧结果

### 真实触发点

- `TELEGRAM_RECOGNITION_CACHE_ENABLED=true`。
- Prompt 修改但 metadata version 未变。
- schema 修改但 schemaVersion 未变。

### 可能表现

- 新 Prompt 不生效。
- 旧 recognition JSON 被复用。

### 控制

- Prompt 语义变化时 bump `prompts/_source/recognition-rules.json` metadata version。
- schema 合同变化时检查 `RECOGNITION_SCHEMA_VERSION` 和 Prompt metadata schemaVersion。
- cache key 已包含 promptVersion/schemaVersion/model。

### 回滚

- 禁用 `TELEGRAM_RECOGNITION_CACHE_ENABLED`。
- bump version 迫使 cache miss。
- 如需排查，查询 `ingest.telegram_recognition.recognition_json`。

## 停止条件

出现任一情况应暂停发布：

- P0 合同测试失败。
- sleep 图片识别回退到 fallback 时不支持 sleep。
- `AiSchemaError` 明显增加。
- `no reliable image or filename date` 或 `conflicting detected dates` 非预期增加。
- `test/feishu-sync.test.mjs` 失败。
- core 写入测试失败。

## 恢复流程

1. 停止发布新 Prompt/source/schema。
2. 切回旧 Prompt 文件或回退 source 后重新生成。
3. 禁用识别缓存或 bump Prompt version。
4. 用 batchId 查 ingest batch 和 recognition。
5. 如 core 已写错，按 `source_batch_id` 定位并人工修复或重放。
6. 将失败样例补入测试 fixture。
