## 问题 1：`records.sleep` 没有进入必填字段

`records` 的 required 当前是：

```text
measurement, activities, meals, totalCalories, details, dailyWorkoutSummary
```

但同一个 schema 又定义了 `sleep` 属性。严格 schema 下，模型可以完全省略 `records.sleep`，这会削弱睡眠图片解析的稳定性。

建议：

- schema v3 中把 `sleep` 加入 `records.required`，类型仍保留 `object | null`。
- 非睡眠图片要求 `records.sleep=null`，睡眠图片要求 `records.sleep` 为对象。
- 同步更新 prompt、schema tests、缓存 key 的 schema version，避免老缓存污染新 schema。

验收：

- 睡眠图片 fixture 输出必须包含 `records.sleep`。
- 非睡眠图片 fixture 输出必须包含 `records.sleep:null`。
- schema 失败进入 pending recognition，而不是静默入库。

## 问题 2：缺少字段级合理性校验

当前 schema 只校验类型，不校验业务合理性。体脂称和运动截图最容易出现 OCR/视觉误读，例如小数点、百分号、kg/kcal/min 混淆。

建议新增 `validateRecognitionSemantics()`，放在 schema parse 后、`analyzeTelegramBatch` 前，输出 warnings 和可选阻断原因：

| 类型 | 校验建议 | 处置 |
| --- | --- | --- |
| 体脂称 `measurement` | `weightKg`、`bmi`、`bodyFatPct`、`bodyWaterPct`、`proteinPct`、`boneMassKg`、`basalMetabolismKcal` 的合理范围。 | 超出软范围写 warning；明显不可能值进入 `manual_intervention`。 |
| 体脂称字段关系 | `bmi` 与 `weightKg` 相对历史身高/历史 BMI 是否大幅冲突，`fatFreeMassKg` 不应大于体重。 | 默认 warning，避免误杀。 |
| 睡眠 | `totalSleepMinutes` 应接近 `nightSleepMinutes + napMinutes`，睡眠分期总和不应明显大于总睡眠。 | warning；差异过大阻断。 |
| 运动 | `workoutDurationMinutes`、`activityCaloriesKcal`、活动列表时间格式。 | warning；负数阻断。 |
| 日期 | `detectedDate`、`measuredAt`、message date、caption date 的冲突数量。 | 延续现有 dateConfidence，不可靠日期不入库。 |

关键原则：不要在 validator 里自动猜测或改数值；只做“可解释的警告/阻断”。真正修正仍交给 AI retry、人工回看或后续样本改 prompt。

## 问题 3：没有固定样本评测闭环

当前日志只能看单次 run 成功与耗时，不能回答“准确率是否提升”。下一轮 prompt/schema/model 调整前，应先建立小型评测集。

建议目录：

```text
test/fixtures/recognition/
  measurement/
  sleep/
  workout/
  nutrition/
```

每个样本保存：

- 脱敏后的图片或截图裁剪。
- 期望 JSON 中的关键字段。
- 可接受误差，例如体重 `0.1kg`、体脂率 `0.1%`、睡眠分钟 `5min`。
- 样本来源标签：Telegram / Feishu、App 名、图片类型、是否多图。

建议新增命令：

```text
npm run eval:recognition
```

输出字段级指标：

| 指标 | 目标 |
| --- | --- |
| imageType 准确率 | 100% 覆盖核心样本。 |
| detectedDate 准确率 | 核心样本 >= 95%。 |
| measurement 关键字段准确率 | weight/bodyFat/bmi/bodyScore 等核心字段 >= 95%。 |
| sleep 关键字段准确率 | total/night/deep/light/rem/score 等核心字段 >= 90%。 |
| schema failure | 0 个非预期失败。 |
| invalid silent store | 0 个。 |

## 问题 4：识别观测还缺少“准确率维度”

Action summary 已有 provider、model、promptVersion、fallback/retry、duration、tokens。建议继续增加两类只含安全摘要的字段：

| 字段 | 用途 |
| --- | --- |
| `semanticWarningCount` | 观察字段级不确定性是否变多。 |
| `criticalFieldMissingCount` | 观察核心字段缺失，不输出字段原始值。 |
| `evalProfile` | 本地/CI 评测时记录样本集版本。 |
| `imagePreprocessMode` | 比较 inline、原图、裁剪/压缩后的准确率。 |

不要在 Action 日志输出原图 URL、file id、caption、完整 AI 响应或原始字段值。

## 建议落地顺序

1. 先加 schema v3：`records.sleep` 必填但可为 null。
2. 加语义校验模块和单元测试，只输出 warning，不先阻断大量线上数据。
3. 建立 20-50 张脱敏评测样本，固定 prompt/model/schema 的基线。
4. 根据评测结果再改 prompt，例如强调体脂称字段小数点、单位和睡眠分期总和。
5. 最后决定哪些语义错误要从 warning 升级为 `manual_intervention`。
