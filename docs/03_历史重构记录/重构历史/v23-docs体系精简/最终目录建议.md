# 最终目录建议

## 设计目标

- 层级不超过 3 层。
- 主文档数量尽量少。
- 当前事实只有一个主位置。
- 新人 30 分钟内理解系统。
- AI Agent 可以按固定顺序读取，不需要反复跳转。

## 信息不丢失原则

迁移时每个事实只能落到以下一种位置：

| 事实类型 | 目标 |
| --- | --- |
| 系统价值、边界、不可破坏能力 | `总览/系统导览.md` |
| 架构分层、组件关系 | `架构/系统架构.md` |
| 业务规则 | `核心业务/核心业务.md` |
| 通道、Worker、Queue、Actions、失败状态 | `消息链路/消息链路.md` |
| AI prompt/schema/fallback/analysis | `AI识别体系/AI识别体系.md` |
| DB schema、生命周期、幂等、事务、迁移 | `数据模型/数据模型.md` |
| 字段级映射 | `数据模型/图片识别字段映射.md` |
| SQL 查询 | `数据模型/查询手册.md` |
| 配置部署 | `部署运维/部署运维.md` |
| 恢复和日常维护 | `运维手册/运维手册.md` |
| 故障症状 | `故障排查/故障排查.md` |
| 命令、变量、接口、术语 | `参考资料/参考资料.md` |
| 历史方案、审查、迁移前原貌 | `归档/` |

## 明确删除的跳转层

建议移除以下跳转层：

- 只列链接、不提供事实的目录 README。
- 只有 10 到 30 行的单主题短文档。
- 同一主题下“总览 + 子页 + 排障 + 运维”都重复解释的章节。

| 运维排障跨目录跳转 | 高 | 中低 |
| 单事实维护位置 | 多处 | 单处 |
