# 日常规则

本目录记录日常开发、合并和文档维护时必须遵守的规则。这里写的是长期执行规则，不记录某一次重构的临时计划。

## 文档列表

| 文档 | 主题 |
| --- | --- |
| `dev-main分支合并规则.md` | `dev` 与 `main` 合并时的数据隔离和保护规则。 |
| `后续规划落地文档同步规则.md` | `后续规划_未实现` 中的规划完成后，如何同步进当前系统文档。 |
| `文档目录维护规则.md` | 根目录 Markdown 保留边界、当前/历史文档归位和移动验证规则。 |

## 基本原则

1. `dev` 和 `main` 的运行数据互相独立，合并代码时不能覆盖对方环境的数据。
2. `docs/03_历史重构记录/后续规划_未实现/` 只放未完成规划；规划完成后，当前系统事实必须写回 `docs/01_系统配置/`、`docs/02_系统核心逻辑/`、`docs/04_问题与排查/` 等当前文档。
3. 历史规划文档可以保留为背景材料，但不能替代当前系统文档。
