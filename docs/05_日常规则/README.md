# 日常规则

本目录记录日常开发、合并和文档维护时必须遵守的规则。这里写的是长期执行规则，不记录某一次重构的临时计划。

## 文档列表

| 文档 | 主题 |
| --- | --- |
| `dev-main分支合并规则.md` | `dev` 与 `main` 合并时的数据隔离和保护规则。 |
| `实施规划落地文档同步规则.md` | 一次性规划完成后，如何把最终事实同步进当前文档并删除过程副本。 |
| `文档目录维护规则.md` | 根目录 Markdown 保留边界、当前/历史文档归位和移动验证规则。 |

## 基本原则

1. `dev` 和 `main` 的运行数据互相独立，合并代码时不能覆盖对方环境的数据。
2. 一次性规划完成后，当前事实必须写回 `docs/01_系统配置/`、`docs/02_系统核心逻辑/`、`docs/04_问题与排查/` 等长期文档。
3. 已完成的目标、方案、TDD 和验收过程不在仓库中长期保留重复副本，通过 Git 历史和 CHANGELOG 追溯。
