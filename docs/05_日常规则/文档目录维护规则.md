# 文档目录维护规则

本规则用于保持仓库根目录整洁，并区分当前系统文档、历史资料和运行生成物。

## 根目录允许保留的 Markdown

| 文件 | 保留原因 |
| --- | --- |
| `README.md` | 项目入口、快速开始和文档导航。 |
| `CHANGELOG.md` | 版本与未发布变更记录，站点版本读取也依赖该文件。 |
| `训练记录.md` | 数据库导出的人工可读备份，也是显式导入、对账和恢复流程的固定输入路径。 |
| `训练数据解析.md` | `npm run build:data` 生成的解析排查产物，路径由构建和测试约定。 |

除上述文件外，不应在根目录长期新增分析报告、执行计划、TDD 记录、会议纪要或临时说明。

## 文档归位规则

| 内容类型 | 目录 | 要求 |
| --- | --- | --- |
| 当前环境配置 | `docs/01_系统配置/` | 必须与 workflow、环境变量和配置文件一致。 |
| 当前运行逻辑 | `docs/02_系统核心逻辑/` | 只描述真实代码和数据库行为。 |
| 历史重构、ADR、审计、目标、方案、TDD、验收报告 | `docs/03_历史重构记录/` | 按专题建子目录，并提供 README 阅读顺序。 |
| 当前问题排查 | `docs/04_问题与排查/` | 给出可执行排查入口，避免引用过期表名或命令。 |
| 长期开发和维护规则 | `docs/05_日常规则/` | 只保留可重复执行的规则，不存某一次任务的临时计划。 |

## 新增和移动文档时

1. 先判断文档是“当前事实”“历史依据”还是“运行生成物”。
2. 使用 `rg` 检查旧路径在代码、测试、workflow 和文档中的全部引用。
3. 历史专题必须提供 README，说明阅读顺序和“不作为当前操作入口”的边界。
4. 移动后更新 `docs/README.md`、所属一级目录 README 和根 `README.md` 中必要的导航。
5. 运行 `git diff --check`、相关测试和站点构建；不能只验证 Markdown 链接。

## 禁止事项

- 不把运行依赖文件仅因扩展名是 `.md` 就迁入 `docs/`。
- 不在根目录保留一次性目标、过程报告或重复副本。
- 不把历史规划写成当前已实现能力。
- 不为了保留旧路径创建无维护价值的兼容副本。
