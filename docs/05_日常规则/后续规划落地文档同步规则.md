# 后续规划落地文档同步规则

本文定义 `docs/03_历史重构记录/后续规划_未实现/` 中的规划完成后，如何同步到当前系统文档。目标是让历史规划归历史，当前系统事实归当前 docs，避免实现完成后文档分裂。

## 1. 文档分工

| 目录 | 职责 |
| --- | --- |
| `docs/03_历史重构记录/后续规划_未实现/` | 只放尚未实现的规划、方案、审计和 checklist。 |
| `docs/03_历史重构记录/重构历史/` | 放已经完成的历史背景、实施记录和验收材料。 |
| `docs/01_系统配置/` | 放当前仍有效的环境变量、GitHub Settings、Cloudflare、数据库、AI、Telegram、飞书、COS 配置事实。 |
| `docs/02_系统核心逻辑/` | 放当前仍有效的业务流程、数据流、核心规则和源码事实。 |
| `docs/04_问题与排查/` | 放当前仍有效的运行问题、日志特征、排查步骤、解决方案和预防措施。 |
| `docs/05_日常规则/` | 放长期维护规则。 |

规划一旦实现，不能只把完成状态写在 `后续规划_未实现` 里。凡是影响当前系统的内容，都必须写回对应的当前系统文档。

## 2. 规划完成后的必做动作

当 `docs/03_历史重构记录/后续规划_未实现/` 下某个规划已经实现，按以下顺序处理：

1. 找出该规划实际改变了哪些代码、workflow、SQL、配置、运行流程、排查方式。
2. 把仍然有效的当前事实写入 `docs/01_系统配置/`、`docs/02_系统核心逻辑/`、`docs/04_问题与排查/` 中对应文档。
3. 如果规划文档里有已经不再准确的设想、备选方案、临时步骤，不要复制到当前系统文档。
4. 在原规划位置补充完成说明，或将其移动到 `docs/03_历史重构记录/重构历史/` 下合适目录。
5. 更新相关目录 README，确保读者能从当前 docs 找到最新事实，而不是必须翻历史规划。

## 3. 写回当前 docs 的判断规则

| 实现内容 | 必须同步到哪里 | 写什么 |
| --- | --- | --- |
| 新增 / 修改 GitHub Secret、Variable | `docs/01_系统配置/dev.md`、`docs/01_系统配置/main.md` | 变量名、配置位置、是否必填、作用、来源。 |
| 新增 / 修改 Cloudflare Worker、Pages、route、Durable Object、Worker Secret | `docs/01_系统配置/` | Cloudflare 配置清单、Worker Secret、部署和验收方式。 |
| 新增 / 修改 AI、Telegram、飞书、COS、PostgreSQL 参数 | `docs/01_系统配置/` | 参数来源、环境差异、运行时映射、注意事项。 |
| 新增 / 修改业务流程 | `docs/02_系统核心逻辑/` | 当前流程、入口文件、关键不变量、数据流。 |
| 新增 / 修改数据库 schema 或写入读取规则 | `docs/02_系统核心逻辑/数据库模型.md`、相关流程文档 | 表、字段、写入条件、读取来源、兼容规则。 |
| 新增 / 修改 webhook、同步队列、Action 日志、失败补偿 | `docs/02_系统核心逻辑/Action日志与失败补偿.md` 和 `docs/04_问题与排查/Action日志.md` | 正常链路、失败表现、日志字段、处理方式。 |
| 新增 / 修改故障场景 | `docs/04_问题与排查/` | 现象、原因、日志特征、排查步骤、解决方案、预防措施。 |
| 新增长期维护约束 | `docs/05_日常规则/` | 日常执行规则和验收要求。 |

## 4. 不能直接复制的内容

从 `后续规划_未实现` 写回当前 docs 时，以下内容不能原样搬运：

- 已被实现否定的备选方案。
- 临时调研结论、猜测、待验证风险。
- 只适用于实施过程的 checklist。
- 旧目录、旧变量、旧 workflow 名称。
- 没有代码、配置或运行事实支撑的描述。
- “计划将要”“建议未来”“可以考虑”这类未落地内容。

当前系统文档必须写“现在是什么”，不是写“当初计划怎么做”。

## 5. 完成标准

一个后续规划只有同时满足以下条件，才算文档落地完成：

1. 代码、workflow、SQL 或配置已经实现。
2. 当前配置事实已经写入 `docs/01_系统配置/`，如果该规划涉及配置。
3. 当前核心流程已经写入 `docs/02_系统核心逻辑/`，如果该规划涉及业务逻辑。
4. 当前排查方式已经写入 `docs/04_问题与排查/`，如果该规划新增或改变故障场景。
5. 原 `后续规划_未实现` 文档不再作为当前事实入口。
6. 相关 README 的链接和说明已经更新。
7. 文档中没有把 dev/main 环境数据混写，也没有把 Secret 明文写入仓库。

## 6. 实施检查清单

每次完成一个 `后续规划_未实现` 目录下的规划后，提交前检查：

```text
[ ] 规划影响的代码、workflow、SQL、配置已经确认。
[ ] 需要写入 01_系统配置 的配置事实已经更新。
[ ] 需要写入 02_系统核心逻辑 的流程事实已经更新。
[ ] 需要写入 04_问题与排查 的排查内容已经更新。
[ ] 历史规划文档已标注完成或移动到重构历史。
[ ] 相关 README 已更新。
[ ] 没有 Secret 明文。
[ ] 没有把 dev 和 main 的运行数据写混。
```
