# v23 docs 体系精简审查

审查日期：2026-06-22

## 审查定位

本目录是 Documentation Consolidation Review 的审查输出，不是新的长期事实文档。

目标是把 `docs/` 从“历史讨论集合 + 当前事实入口”收敛为“当前系统事实源”。本次只给出盘点、重复分析、合并方案、AI Agent 阅读路径和迁移 checklist，不直接删除或搬迁现有主文档。

## 审查范围

- 当前主文档：`docs/归档/` 以外的 Markdown，共 92 个。
- 归档文档：`docs/归档/` 下 Markdown，共 64 个。
- 非 Markdown 历史图文件：`docs/归档/旧版长期文档/系统架构/*.drawio`。

## 总体结论

当前 docs 已经完成一次从旧长期文档到新 IA 的迁移，方向正确：正式文档和 `归档/` 已经分开，当前事实也多次强调 PostgreSQL、统一消息链路、双通道一致性、AI 校验边界和 Markdown 派生备份。

主要问题不是缺文档，而是主文档被拆得过细。同一事实在总览、架构、消息链路、数据模型、部署运维、运维手册、故障排查和 AI-Agent 中反复出现。对人类读者来说跳转多，对 AI Agent 来说上下文碎片化，对维护者来说一次事实变更需要同步 4 到 8 个文件。

建议下一轮迁移采用“合并为少数事实文档 + 保留查表型参考 + 归档历史方案”的方式，把正式主文档从 92 个收敛到约 15 到 18 个。
