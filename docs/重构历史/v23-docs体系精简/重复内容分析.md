# 重复内容分析

## 总体判断

当前重复不是简单文字重复，而是同一事实被按角色、阶段和目录多次复述。短文档让单页很轻，但让系统事实分散。建议把重复事实收敛到主文档章节，把角色化入口改为链接路径。

| 图片类型 `measurement/workout/nutrition/sleep/unknown` | `AI识别体系/AI识别体系.md`、`图片分类.md`、`核心业务/核心业务.md`、`数据模型/图片识别字段映射.md` | AI 主文档概述，字段表保留映射细节 |
| schema 通过不等于入库成功 | `识别Schema.md`、`图片识别字段映射.md`、`核心业务/核心业务.md`、`故障排查/数据质量问题.md` | AI 主文档保留原则，故障排查引用 |
| fallback 触发条件 | `Provider与Fallback.md`、`AI主备容灾演练.md`、`故障排查/AI异常.md` | AI 主文档 |
| fallback 不处理低置信度/缺日期/非目标图片 | `Provider与Fallback.md`、`AI主备容灾演练.md`、`故障排查/AI异常.md` | AI 主文档 |
| `ingest.ai_call_log` 审计字段 | `AI可观测性.md`、`运维手册/运维手册.md#日常维护`、`数据模型/索引与查询手册.md` | 数据模型或运维手册，AI 文档只说明用途 |
| Prompt source 和生成结果 | `Prompt体系.md`、`AI识别体系/AI识别体系.md`、`参考资料/环境变量索引.md` | AI 主文档 |
| 分析 AI 不写事实 | `分析AI.md`、`核心业务/分析系统.md`、`总览/系统导览.md` | 核心业务或 AI 主文档，另一个链接 |

### 结论

AI 识别体系应合并为一个主文档，章节为：

1. 定位与边界
2. 图片分类
3. Prompt source
4. 识别 Schema
5. 业务校验与入库 gate
6. Provider 与 fallback
7. AI 可观测性
8. 分析 AI
9. 字段映射链接

`图片识别字段映射.md` 可保留独立，因为它是查表型、字段级、高维护价值文档。

| 事实 | 出现位置 | 建议唯一位置 |
| --- | --- | --- |
| Telegram/飞书 -> Worker -> Queue -> Actions -> runMessageSync -> AI/DB | `总览/系统导览.md`、`架构/消息同步架构.md`、`消息链路/消息链路.md` | `消息链路/消息链路.md` |

| Action success 不等于业务 success | `消息链路/调度队列与GitHub-Actions.md`、`部署运维/GitHub-Actions.md`、`故障排查/GitHub-Actions异常.md`、`运维手册/运维手册.md#日常维护` | `消息链路/消息链路.md` |

### 结论

消息链路应保留一个主文档，内部以“总链路 -> 通道差异 -> 队列/Action -> 失败状态 -> Markdown backup”组织。部署与故障排查只引用链路事实，不再重复链路图。

### 结论

运维体系应按动作分层：

- 部署运维：配置、部署、环境隔离。

- 故障排查：按症状定位和处理。
- 参考资料：环境变量、CLI、接口、命令、术语。

其中每层建议一个主文档，减少多个短文件之间的重复跳转。
