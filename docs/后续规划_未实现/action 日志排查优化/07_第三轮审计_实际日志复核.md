## 4. 测试 fixture 日志污染（从 CI 专属升级为 deploy 共发）

### 文档原结论

04/05 把 fixture 噪声归到 `ci-tests.yml`，建议 CI 降噪与去重。

### 实测真实状态

- `site-build/action.yml` 第 130-133 行有 `Run tests` step，条件 `inputs.run_tests == 'true'`。
- `deploy-pages.yml:78` 与 `deploy-cloudflare-pages-dev.yml:72` 都传 `run_tests: 'true'`。
- 因此**每次部署都跑 `npm run test:fast`**，fixture 的 `primary AI recognition failed... retrying with fallback provider` 等 stderr 进入 deploy 日志。
- Deploy #350 build step 含 **350** 行此类 fixture 噪声；CI #285 的 `test` job 同样有（第 245-254 行）。

### 修订

- fixture 噪声的**主要入口是 deploy，不是 CI**。04/05 的"CI 降噪"应改为"deploy 与 CI 共同降噪"。
- 建议：deploy 的 `run_tests` 默认设为 `false`（生产部署不需要每次跑测试，CI 已覆盖），或测试 stderr 加 `[test-fixture]` 前缀并仅在失败时展开。
