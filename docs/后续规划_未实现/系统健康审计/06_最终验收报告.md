# 最终验收报告

## 验收结论

有条件通过。

核心链路仍可在当前代码中找到实现入口，Telegram、飞书、图片识别、AI 主备、数据库写入、Markdown 导入导出、随想系统和分析系统均未缺失；但最终可信风险清单中的 P0/P1 风险仍成立，尤其是 webhook Action concurrency 策略需决策、DO dispatch 后 run 查询异常重试幂等、同日来源追踪和随想 Markdown 非原子备份。因此本轮归档通过，系统健康状态为有条件通过。

## 最终可信风险汇总

仅保留经当前代码复核后仍成立的问题：

| 级别 | 风险 |
|---|---|
| P0 | webhook 路径 Action 并发不串行，串行完全依赖 DO；现有测试明确保护唯一 concurrency group 设计，需先做策略决策。 |
| P0 | DO 在 `workflow_dispatch` 发出后若 run 查询异常，重试会回到 `phase: 'dispatch'`，存在重复 dispatch 窗口。 |
| P0 | 同日 `core.training_day` 汇总来源会被后到批次覆盖。 |
| P0 | 随想 Markdown 备份先删后写，非原子。 |
| P1 | 双通道字段不一致，飞书 source id 仍以哈希数字兼容 telegram 字段。 |
| P1 | 识别缓存 join 未使用完整 source identity。 |
| P1 | 飞书复用 telegram 命名链路，排障语义不清。 |
| P1 | Pages cache purge 失败会使整条同步链路报失败。 |
| P1 | AI 单批多图无全局预算。 |
| P1 | AI fallback provider 不检查业务置信度。 |
| P2 | 运行时 schema preflight 直接 ALTER 生产表。 |
| P2 | `ai_call_log` 在主事务外 best-effort 写入。 |
| P2 | 随想编辑、删除、移动 DB-only，Markdown 不即时同步。 |
| P2 | 主 Worker 手动部署，代码与线上可能滞后。 |
| P2 | `wrangler.toml` 名称仍偏飞书，实际承载双通道。 |

完整证据以 `05_最终可信风险清单.md` 为准。

## 未来重构红线

任何重构不得破坏以下能力：

- Telegram webhook 接入、鉴权、图片相册缓冲、同步结果通知。
- 飞书事件接入、鉴权/校验、图片分组、同步结果通知。
- 图片识别、Prompt 元数据读取、schema 校验、识别结果入库。
- AI 主备 provider 配置、错误 fallback、AI 调用审计字段。
- 随想新增、编辑、删除、移动、模块分类和图片引用。
- 分析系统的只读快照、Prompt 规则和通道回执。
- Markdown 导入到 PostgreSQL core 的维护入口。
- PostgreSQL `ingest.*`、`core.*`、`archive.*` 写入与幂等约束。
- Markdown 派生备份和 Hexo 站点构建输入。

重构前必须确认这些能力有对应测试或人工验收路径；无法证明不破坏时，不得合并。
