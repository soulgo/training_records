# 部署运维

本文是 GitHub Actions、Cloudflare Workers、Pages、Telegram、飞书、main/dev 环境和 Secrets/Variables 部署配置的唯一入口。


## 部署运维总览

部署涉及 GitHub Actions、Cloudflare Worker、Telegram、飞书、GitHub Pages 和 Cloudflare Pages。

## 基本原则

- main 和 dev 隔离。
- 外部平台配置需要人工确认。
- 仓库只能证明 workflow、wrangler、代码读取哪些配置，不能证明平台当前值。

## 排障口径

先看 workflow 是否运行，再看业务 summary。绿色 workflow 仍可能包含 `partialFailure`、`pending_replay` 或 `manual_intervention`。

消息同步 workflow 的业务字段优先级：

- `taskStatus`
- `persistenceStatus`
- `failureDisposition`
- `queue_task_id`
- `payload_hash` / `payloadHash`
- `imageUploadStats`

启用 COS 随想图片存储时，`sync.yml` / `sync-dev.yml` 的 summary 会出现 `## Image storage` 小节，用于确认 provider、bucket、pathPrefix、上传/跳过/失败数量、耗时和首个图片 URL host。

## 队列与重跑

- Worker 的 `SyncDispatchQueue` 触发 `.github/workflows/sync.yml` 或 `.github/workflows/sync-dev.yml`。
- `queue_task_id` 用于关联 Worker 队列任务和 workflow run。
- workflow run 查找超时 / run lookup timeout 后，应检查 dead-letter 和 Worker 日志。
- 重跑 / rerun 必须保持幂等；同一 `batch_id + payload_hash` 应返回 `unchanged`，不得重复写 core。

## GitHub Pages 与 Cloudflare Pages

## 生产

生产站点由 GitHub Pages 发布。`source/CNAME` 指向生产域名。

## Dev

dev 预览由 Cloudflare Pages 发布，构建时应使用 dev 数据库配置，并删除 `public/CNAME`，避免覆盖生产域名。

## 页面没有更新时

先判断是数据未写入、构建未执行、部署失败，还是 CDN 缓存。

Pages 构建不会上传 COS 图片，也不会代理 COS 图片。随想图片 URL 来自数据库 `core.thought.image_refs_json`，浏览器直接请求本地 `/images/...` 或 COS 公有读 URL。

## main/dev 环境矩阵

| 项 | main | dev |
| --- | --- | --- |
| 同步 workflow | `sync.yml` | `sync-dev.yml` |
| Worker 配置 | `wrangler.toml` | `wrangler.dev.toml` |
| Telegram dispatch | `telegram_update` | `telegram_update_dev` |
| 飞书 dispatch | `feishu_update` | `feishu_update_dev` |
| 数据库 | `TRAINING_DB_URL` | `DEV_TRAINING_DB_URL` |
| Bot token | `TELEGRAM_BOT_TOKEN` | `DEV_TELEGRAM_BOT_TOKEN` 或独立 dev 配置 |
| 飞书配置 | `FEISHU_*` | `DEV_FEISHU_*` 可覆盖 |
| COS 图片存储 | `COS_*` | `DEV_COS_*` |

## 原则

- dev 不能误写 main 数据库。
- dev 不能使用 main COS bucket 或 domain。
- dev Request URL 不能填生产 Worker。
- main deploy 不能使用 dev CNAME 或 dev DB。

## 腾讯云 COS 图片存储

COS 只用于随想图片附件，不用于训练截图识别原图归档。默认 `COS_ENABLED` 未开启时继续写本地 `source/images/thoughts`。启用后：

- main 由 `sync.yml` 读取 `COS_ENABLED`、`COS_PROVIDER`、`COS_SECRET_ID`、`COS_SECRET_KEY`、`COS_BUCKET`、`COS_REGION`、`COS_DOMAIN`、`COS_PATH_PREFIX`。
- dev 由 `sync-dev.yml` 读取对应 `DEV_COS_*`，并映射成同步脚本运行时的同名 `COS_*`。
- `COS_PROVIDER` 默认 `tencent_cos`；回退本地存储可关闭 `COS_ENABLED`。
- `COS_DOMAIN` 当前必须使用腾讯云默认 HTTPS 域名：`https://{COS_BUCKET}.cos.{COS_REGION}.myqcloud.com`。
- bucket 访问模型是私有写、公有读；不要改成私有读，否则已落库的静态 URL 会失效。
- Cloudflare Worker、Pages deploy、Markdown backup 不需要 COS Secret。

dev 和 main 应使用独立 bucket、独立 CAM 子账号、独立 domain 和独立 prefix。仓库只能证明 workflow 读取哪些变量，真实 bucket 权限、CORS、CAM 权限和 Secret 值需要在腾讯云和 GitHub 平台人工确认。
