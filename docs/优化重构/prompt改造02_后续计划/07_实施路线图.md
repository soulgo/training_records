# 07 实施路线图：按代码依赖顺序

## Go / No-Go

- Judgment：Go。
- Reason：本路线只覆盖当前代码可直接修改的 Prompt source、schema、fallback、测试、batch 和 DB 映射，不包含未实现 Skills 或统一识别引擎。

## 目标结果

完成后，图片识别文档和代码合同一致：

- Prompt、schema、fallback 支持相同 `imageType` 和字段空值。
- `records.sleep` 与 meals recommended nullable 合同一致。
- 生成 Prompt、运行时 fallback、batch 分析和 DB 映射都有测试保护。
- Telegram 和飞书继续共享识别语义。

## 非目标

本轮不做：

- Skills 迁移。
- 多次 AI 调用。
- 动态 app profile 拼装。
- workout sets/reps/weight 字段。
- nutrition foods/macros 字段。
- core 表结构新增字段。
- 统一 RecognitionTask 引擎。

## 回滚顺序

1. Prompt source 改坏：回退 `prompts/_source/*`，重新运行生成器。
2. fallback 改坏：回退 `src/app/use-cases/telegram-sync/image-processing.mjs`。
3. schema 改坏：回退 schema 和对应测试；注意 schemaVersion/prompt metadata 一致性。
4. DB 写入改坏：停止写 core，只保留 ingest；用 batchId 定位受影响数据。
