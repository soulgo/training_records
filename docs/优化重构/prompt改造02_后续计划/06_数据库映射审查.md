# 06 数据库映射审查：完全以 SQL 和写入代码为准

## 结论

当前 Prompt 输出不能直接等同 DB row。真实链路是：

```text
AI recognition JSON
  -> normalizeRecognitionPayload()
  -> analyzeTelegramBatch()
  -> persistNormalizedBatch()
  -> ingest.telegram_*
  -> persistTelegramImageBatchIncremental()
  -> core.*
```

数据库事实源：

- `sql/training_records/core.sql`
- `sql/training_records/ingest.sql`
- `sql/training_records/archive.sql`
- `src/adapters/postgres/incremental-write.pg.mjs`
- `src/adapters/postgres/core-row-writer.pg.mjs`

## Ingest 边界

### 表结构

`ingest.telegram_batch`：

```text
batch_id, status, archived_date, reason, confidence,
warnings_json, issues_json, update_ids_json,
payload_hash, batch_payload_json, processed_at, updated_at
```

`ingest.telegram_message`：

```text
message_id, batch_id, update_id, media_group_id, chat_id,
caption, text, date_unix,
photo_file_ids_json, photo_file_unique_ids_json, updated_at
```

`ingest.telegram_recognition`：

```text
message_id, batch_id, recognition_json, updated_at
```

`ingest.telegram_pending_batch`：

```text
pending_id, batch_id, kind, status, batch_payload_json,
failure_category, failure_reason, attempt_count,
next_retry_at, last_failed_at, resolved_at, created_at, updated_at
```

### 映射结论

| Prompt 字段 | ingest 保存位置 | core 保存位置 |
|---|---|---|
| `imageType` | `telegram_recognition.recognition_json`、`batch_payload_json` | 不直接保存 |
| `detectedApp` | recognition JSON、batch payload 的 `detectedApp` | 不保存固定列 |
| `detectedDate` | recognition JSON、dateSources/batch payload | 转换为 `archived_date` 后写 core |
| `dateEvidence` | recognition JSON、dateSources | 不保存固定列 |
| `confidence` | recognition JSON、batch confidence | 不保存 fixed core 列 |
| `warnings` | recognition JSON、`telegram_batch.warnings_json` | 不保存 fixed core 列 |
| `records.*` | recognition JSON 和 batch payload | 经过 normalizer 后写 core |

## Core 总表：`core.training_day`

SQL 字段：

```text
archived_date, source_channel, source_batch_id,
total_activities, total_duration_seconds, training_calories,
workout_duration_minutes, active_hours, cycling_distance_km,
intake_calories,
sleep_total_minutes, night_sleep_minutes, nap_minutes,
sleep_start_time, sleep_end_time,
deep_sleep_minutes, light_sleep_minutes, rem_sleep_minutes, awake_minutes,
nutrition_details_json, updated_at
```

写入代码：

- `src/adapters/postgres/incremental-write.pg.mjs`
- `ensureCoreTrainingDayStub()`
- `refreshCoreTrainingDaySummary()`

映射说明：

- 活动汇总从 `core.activity` 聚合。
- 饮食总热量可来自 batch `nutrition.totalCalories` 或 `core.meal` sum。
- `nutrition_details_json` 只保存 `records.details[]`。
- 睡眠汇总从 `core.sleep` 聚合，只包含时长和阶段分钟，不包含 sleepScore/HRV/SpO2。

## Measurement 映射

### Prompt/schema 字段

```text
records.measurement.measuredAt
records.measurement.bodyScore
records.measurement.weightKg
records.measurement.bmi
records.measurement.bodyFatPct
records.measurement.skeletalMuscleKg
records.measurement.visceralFatLevel
records.measurement.basalMetabolismKcal
records.measurement.bodyWaterPct
records.measurement.proteinPct
records.measurement.boneMassKg
records.measurement.fatFreeMassKg
records.measurement.bodyAge
records.measurement.bodyType
```

### DB 字段

`core.measurement`：

```text
measurement_key, archived_date, source_channel, source_batch_id,
measured_at, body_score, weight_kg, bmi, body_fat_pct,
skeletal_muscle_kg, visceral_fat_level, basal_metabolism_kcal,
body_water_pct, protein_pct, bone_mass_kg, fat_free_mass_kg,
body_age, body_type, updated_at
```

### 写入规则

`src/adapters/postgres/core-row-writer.pg.mjs`：

- `measurement_key = md5(day.date | measuredAt | weightKg)`。
- `bodyScore`、`basalMetabolismKcal`、`bodyAge` 写入前四舍五入为整数。
- kg 类字段保留 numeric。

`src/adapters/telegram/sync-batch-logic.adapter.mjs`：

- 多个 measurement candidate 取 `measurementCandidates.at(-1)`。
- `measuredAt` 只有 `HH:mm` 时拼成 `detectedDate/archivedDate + HH:mm`。

### 差异点

- DB 不保存原始单位。
- DB 不保存 detectedApp。
- key 不包含 source_channel/source_batch_id，相同业务键冲突时会更新来源字段。

## Workout 映射

### Prompt/schema 字段

```text
records.activities[].time
records.activities[].type
records.activities[].detail
records.dailyWorkoutSummary.activityCaloriesKcal
records.dailyWorkoutSummary.workoutDurationMinutes
records.dailyWorkoutSummary.activeHours
```

### DB 字段

`core.activity`：

```text
activity_key, archived_date, source_channel, source_batch_id,
activity_time, activity_type, raw_type, detail,
calories, heart_rate, distance_km, avg_speed_kmh,
duration_text, duration_seconds, updated_at
```

`core.training_day` 相关：

```text
total_activities, total_duration_seconds, training_calories,
workout_duration_minutes, active_hours, cycling_distance_km
```

### 写入规则

`src/core/entities/training-record.mjs` 的 `normalizeBatchActivity()`：

- `time` -> `activity_time`。
- `type` -> `activity_type`。
- `rawType ?? type` -> `raw_type`。
- `detail` -> `detail`。
- `calories/heart_rate/distance_km/avg_speed_kmh/duration_text/duration_seconds` 从 `detail` 正则解析。

`activity_key = md5(day.date | time | type | detail)`。

### 差异点

- Prompt 没有结构化输出 `calories`、`heartRate`、`distanceKm`、`avgSpeedKmh`、`durationSeconds`。
- DB 没有 sets/reps/weight 字段。
- `raw_type` 由代码兜底，不是 Prompt schema 字段。

## Nutrition 映射

### Prompt/schema 字段

```text
records.meals[].name
records.meals[].calories
records.meals[].recommendedMin
records.meals[].recommendedMax
records.totalCalories
records.details[]
```

### DB 字段

`core.meal`：

```text
meal_key, archived_date, source_channel, source_batch_id,
meal_name, calories, recommended_min, recommended_max, updated_at
```

`core.training_day`：

```text
intake_calories, nutrition_details_json
```

### 写入规则

`normalizeNutrition()`：

- 用 `inferMealSlot()` 归一餐次。
- 同餐次 calories 累加。
- recommended 非数字转 null。
- details 去重后保留。
- totalCalories 缺失时使用 meals sum。

`core-row-writer.pg.mjs`：

- `meal_key = md5(day.date | meal.name | meal.calories)`。
- `recommendedMin/Max` 可写 null。

### 当前合同不一致

- Prompt 允许 recommended null。
- SQL 和 writer 支持 null。
- schema 当前不支持 null。

修复方向：改 schema 允许 `['number', 'null']`，不改 SQL。

### 不存在字段

当前 core 不存在：

- food item 独立表。
- protein/carb/fat macros 字段。
- weightGram/amount 结构化字段。

这些不能写入 Prompt JSON 顶层或 core 映射。

```text

sleep_start_time, sleep_end_time,

```

### 写入规则

- `resolveSleepArchiveDate()` 根据 `wakeTime` 或 `detectedDate` 得到醒来日期并减一天。
- `normalizeSleepRecord()` 有真实值才生成记录。
- `sleep_key = md5(day.date | sleepType | bedtime | wakeTime | totalSleepMinutes)`。
- `sleepStageDetail` 如果是 array，会 `JSON.stringify()` 后写入 `core.sleep.sleep_stage_detail` text。

### 差异点

- `core.sleep.sleep_stage_detail` 是 text，不是 jsonb。
- `archive.training_sleep.sleep_stage_detail` 是 jsonb；这是 archive 旧结构，不等于 core 当前结构。
- `core.training_day` 不保存 sleepScore、HRV、SpO2、呼吸率、analysisText、suggestionText。
- schema 当前没有把 `sleep` 加入 `records.required`，但 Prompt 要求 sleep 图输出 `records.sleep`。

## Archive 边界

`archive.*` 是训练记录解析/回填相关历史归档结构，不是图片识别直接写入的主路径。

当前图片 ready batch 的主写入路径：

```text
persistNormalizedBatch()
  -> PostgresTelegramBatchRepository upsert ingest
  -> persistTelegramImageBatchIncremental()
  -> core.*
```

不要把 `archive.training_*` 字段误写成当前 AI recognition 的直接落库目标。
