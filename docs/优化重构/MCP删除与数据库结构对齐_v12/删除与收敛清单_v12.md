## P2：`/ai` Agent 删除边界

用户已澄清 `/ai` 和 `/智能助手` 与 Telegram 发送、图片分析和 `/analysis` 没有关系。因此本轮不再做“去 MCP 化后保留 `/ai`”的方案，直接删除独立 Agent 入口。

### 删除范围

- `tools/telegram-ai-agent.mjs`
- `tools/telegram-sync.mjs` 中处理 `persistedBatch.kind === 'ai_agent'` 的分支和导入
- `tools/telegram-sync-lib.mjs` 中 `ai_agent` batch 分类、解析和报告分支
- `src/telegram/command-registry.mjs` 中 `ai_agent` command 及 `/ai`、`/智能助手` aliases
- README、docs、help text、测试和示例中对 `/ai` / `/智能助手` Agent 的当前能力描述

### 明确保留

- `/analysis` / `/分析`
- Telegram 图片发送、相册归并、AI 图片识别、pending recognition 重试
- 随想文本入库
- `src/ai/**` provider 能力，因为图片识别和 `/analysis` 仍需要它

### 验证口径

```bash
rg -n "telegram-ai-agent|ai_agent|/ai|智能助手" README.md docs src tools test
rg -n "analysis|/分析|pending-recognition|telegram_pending_batch" src tools test
```

目标结果：第一条只允许命中历史审计文档或归档说明；第二条确认 `/analysis` 和图片识别链路仍有测试或 active code 覆盖。
