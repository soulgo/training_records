## 三、范围缺口（建议实施时注意）

### 4. `tools/lib/` 目录未在 B9 表格中列出

`tools/lib/` 目录包含被 `src/db/training/write.mjs` 和多个 `tools/` 模块引用的文件：

| 文件 | 被引用方 | 应归属 |
| --- | --- | --- |
| `tools/lib/thought-modules.mjs` | `src/db/training/write.mjs` | `src/core/` 或 `src/shared/` |
| `tools/lib/http-retry.mjs` | AI provider 相关 | 基础设施层 |
| `tools/lib/fs-walk.mjs` | 文件系统工具 | 基础设施层 |
| `tools/lib/markdown-render.mjs` | Markdown 渲染 | 基础设施层 |
| `tools/lib/snapshot-fallback.mjs` | 快照回退逻辑 | 领域服务或应用层 |
| `tools/lib/derived-data-paths.mjs` | 派生数据路径 | 基础设施层 |

尤其是 `tools/lib/thought-modules.mjs`——它被 `src/db/training/write.mjs` 直接 import（第 23 行），当前路径为 `../../../tools/lib/thought-modules.mjs`。这是从 `src/` 跨越引用 `tools/` 的实例，属于 B9 要解决的核心问题。建议在 B9 实施步骤中显式列出 `tools/lib/` 的处理方案。

### 5. `tools/training-db-archive.mjs` 与 `src/db/training/archive.mjs` 的双轨

B9 表格列出了常见的双轨模块，但遗漏了：
- `tools/training-db-archive.mjs`（构建数据时写入 archive）
- `src/db/training/archive.mjs`（另一个 archive 实现）

两者都是 archive 写入路径，需要确认关系并去重。建议在 B9 实施步骤中补充此对。

### 6. `src/site/` 目录未在任何 PR 中处理

`src/site/` 包含 `dashboard-view.mjs`、`index.mjs`、`view-model-notes.mjs`。B8（Hexo 适配器）只处理了 `tools/generate-training-data.mjs` 的迁移，未说明 `src/site/` 中的文件属于哪一层：
- `dashboard-view.mjs` 是视图模型构建逻辑，应属于**应用层**或**适配器层**（取决于它是否直接依赖 Hexo 特定格式）
- `view-model-notes.mjs` 类似

建议在 B8 中补充 `src/site/` 的定位说明。

### 7. `core.training_day` 睡眠汇总字段——澄清了但未决策

Phase A3.2 新增了注释说明 schema 中缺少睡眠汇总字段，Checklist 中也加了验证项。但目前文档只停留在"澄清矛盾"层面，没有给出**决策**：

- 方案 A：通过 ALTER TABLE 补充 `sleep_total_minutes`、`night_sleep_minutes`、`nap_minutes`、`sleep_start_time`、`sleep_end_time` 等字段到 `core.training_day`（推荐——与系统文档描述一致，也支持 Telegram sleep 图片的"刷新 core.training_day 睡眠汇总"逻辑）

建议在 Phase A 中选定方案并给出具体 ALTER TABLE 语句或在 Phase B 中明确通过 CTE 实现。

PR #8 (`tools/` 目录对齐) 是整个 v13 中变更面最广的 PR——涉及 ~20 个 Telegram sync 文件重组、6+ 个重复模块去重、多个 re-export 文件迁移。建议在该 PR 完成后运行一个验证脚本：

并在 Checklist B9 末尾加上此项。

### 10. 建议为 `tools/` 重复模块去重编写自动化 diff 脚本

B9 Step 1 要求手动 diff 四对重复文件（`training-domain.mjs`、`training-parser.mjs`、`training-snapshot.mjs`、`dashboard-view.mjs`），但手动 diff 容易遗漏微小差异。建议编写一个一次性脚本：

```javascript
// tools/_diff-duplicates.mjs（临时脚本）
import { readFileSync } from 'fs';
const pairs = [
  ['tools/training-domain.mjs', 'src/domain/training/training-domain.mjs'],
  // ...
];
for (const [a, b] of pairs) {
  const contentA = readFileSync(a, 'utf8');
  const contentB = readFileSync(b, 'utf8');
  console.log(`${a} vs ${b}: ${contentA === contentB ? 'IDENTICAL' : 'DIFFERS'}`);
}
```
