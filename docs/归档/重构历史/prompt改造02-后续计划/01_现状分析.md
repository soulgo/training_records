# 01 现状分析：真实系统现状描述

## 结论

当前系统已经有结构化 Prompt source、生成器、运行时识别链路、schema 校验、批次归档、ingest 审计和 core 入库。它不是纯手写 Prompt，也不是 Skills/pipeline 架构。

本轮后续改造必须限定在当前代码可承载的范围内：

- 改 `prompts/_source/*.json` 后运行 `node tools/prompt-generator.mjs`。
- 改 schema 时同步 `src/core/ai/telegram-recognition-schema.mjs` 与测试。
- 改图片识别链路时同步 `src/app/use-cases/image-recognition.use-case.mjs`、`src/app/use-cases/telegram-sync/image-processing.mjs`。
- 改归档和合并时同步 `src/adapters/telegram/sync-batch-logic.adapter.mjs`、`src/adapters/telegram/sync-dates.adapter.mjs`。
- 改入库字段时以 `sql/training_records/*.sql` 和 `src/adapters/postgres/*.mjs` 为准。

## 代码事实源

| 范围 | 当前文件 | 已实现事实 |
|---|---|---|
| Prompt 源 | `prompts/_source/shared-rules.json`、`recognition-rules.json`、`app-profiles.json`、`analysis-rules.json` | JSON source 是 Prompt 维护入口 |
| Prompt 生成 | `tools/prompt-generator.mjs` | 生成 `prompts/telegram-training-image-recognition.md` 与 `prompts/training-analysis.md`，写入 `prompt-metadata` |
| 图片识别 schema | `src/core/ai/telegram-recognition-schema.mjs` | schema name 为 `telegram_training_image`，version 为 `v2`，支持 `measurement/workout/nutrition/sleep/unknown` |
| 识别请求 | `src/app/use-cases/image-recognition.use-case.mjs` | strict `json_schema` 失败后可降级 `json_object` / 无 response format；解析 JSON 后归一化再校验 |
| Prompt 加载 | `src/app/use-cases/telegram-sync/image-processing.mjs` | 读取生成后的 Prompt；读不到文件时使用硬编码 fallback Prompt |
| 批次分析 | `src/adapters/telegram/sync-batch-logic.adapter.mjs` | 低置信、日期冲突、无日期、sleep 缺数据等在 batch 层判定 ready/skipped |
| 日期归档 | `src/adapters/telegram/sync-dates.adapter.mjs` | 图片日期优先；无图片日期时可用 Telegram document filename；sleep 按醒来日期减一天 |
| 飞书复用 | `src/app/use-cases/feishu-sync.use-case.mjs`、`src/adapters/feishu/sync-batch-logic.adapter.mjs` | 飞书转成 Telegram-compatible batch 后复用 `runTelegramSync()` 和 `recognizeBatch()` |
| 入库 | `src/db/training/write.mjs`、`src/adapters/postgres/incremental-write.pg.mjs`、`core-row-writer.pg.mjs` | ready 图片批次先写 ingest，再增量写 core 表 |
| 数据库结构 | `sql/training_records/core.sql`、`ingest.sql`、`archive.sql` | `core.activity/meal/measurement/sleep/training_day` 与 `ingest.telegram_*` 是当前合同 |

## 当前运行链路

1. Telegram 或飞书事件被归一化为 batch。
2. 图片 batch 调用 `recognizeBatch()`。
3. `loadRecognitionSystemPrompt()` 读取 `prompts/telegram-training-image-recognition.md`，失败时退回硬编码 fallback Prompt。
4. `recognizeTelegramImageMessage()` 发送图片和 user text，附带 `caption`、`text`、图片 URL 或 inline data。
5. AI 返回内容经过 JSON 候选提取、`normalizeRecognitionPayload()`、`buildRecognitionSchema()` 校验。
6. `analyzeTelegramBatch()` 按 `imageType` 分流，执行低置信、日期、字段存在性和 batch 合并规则。
7. `persistNormalizedBatch()` 写 `ingest.telegram_batch/message/recognition`。
8. ready 图片批次通过 `persistTelegramImageBatchIncremental()` 写 `core.*`。

## 当前 Prompt 资产

| 文件 | 现状 | 本轮处理边界 |
|---|---|---|
| `prompts/_source/recognition-rules.json` | 图片识别主规则，覆盖四类图片和日期规则 | 可以直接修改 |
| `prompts/_source/shared-rules.json` | 空值、置信度、共享日期规则 | 可以直接修改 |
| `prompts/_source/app-profiles.json` | 华为健康、Apple Health 的 app profile | 可以扩展，但必须同步生成结果测试 |
| `prompts/_source/analysis-rules.json` | `/analysis` 文本分析 Prompt | 不属于图片识别主改造，不混入本轮 |
| `prompts/telegram-training-image-recognition.md` | 生成产物，运行时读取 | 不手写，必须由生成器生成 |
| `prompts/training-analysis.md` | 生成产物 | 本轮仅核对，不作为图片识别改造对象 |

## 当前支持的图片类型

| `imageType` | Prompt 输出 | batch 处理 | core 入库 |
|---|---|---|---|
| `measurement` | `records.measurement` | 取最后一个 measurement candidate，补 `measuredAt` | `core.measurement` |
| `workout` | `records.activities`、`records.dailyWorkoutSummary` | 活动去重排序，总览合并 | `core.activity`、`core.training_day` |
| `nutrition` | `records.meals`、`records.totalCalories`、`records.details` | 餐次归一化、总热量兜底、details 去重 | `core.meal`、`core.training_day.nutrition_details_json` |
| `sleep` | `records.sleep` | `resolveSleepArchiveDate()` 后归档，缺 sleep 时跳过 | `core.sleep`、`core.training_day` 睡眠汇总列 |
| `unknown` | 空 records、低置信或 warning | 通常不会形成可入库事实 | 只保留 ingest 审计 |

## 当前稳定性机制

- schema version：`RECOGNITION_SCHEMA_VERSION = 'v2'`。
- JSON 容错：支持原文、fenced code、SSE `data:`、子串、balanced JSON。
- response format fallback：`json_schema` -> `json_object` -> 无 response format。
- provider fallback：空响应、超时、429、5xx、网络类错误可切换 fallback provider。
- 识别缓存：需要显式开启 `TELEGRAM_RECOGNITION_CACHE_ENABLED`，cache key 包含 `fileUniqueId/promptVersion/schemaVersion/model`。
- 批次门槛：默认 `minConfidence: 0.75`。
- 日期 gate：多图片日期冲突、多文件名日期冲突、无可靠日期时跳过。
- pending：AI 服务类或数据库持久化失败可进入 `ingest.telegram_pending_batch`。

## 当前已确认的代码级问题

1. `records.sleep` 在 Prompt 中要求输出，但 schema 的 `records.required` 没有包含 `sleep`。
2. Prompt 允许 meals `recommendedMin/recommendedMax` 为 `null`，schema 只允许 number；SQL `core.meal.recommended_min/max` 允许空。
3. 硬编码 fallback Prompt 未包含 `sleep`，与 schema v2 和生成 Prompt 不一致。
4. workout 只结构化输出 `time/type/detail`，`calories/heart_rate/distance/avg_speed/duration` 依赖 `normalizeBatchActivity()` 从 `detail` 正则提取。
5. `buildRecognitionMessages()` 直接拼入 `caption` 和 `text`，当前没有长度截断或显式隔离边界。
6. `renderAppProfilesMemory()` 会截断 aliases、page cues、field aliases、unit conversions、time priority，新增 profile 不能只看 source JSON。

## 明确不属于当前现状的内容

以下内容当前没有实现，不能写成主方案依据：

- NOT IMPLEMENTED IN CODE：Skills 编排。
- NOT IMPLEMENTED IN CODE：分类 Prompt + 专项 Prompt 的多次 AI 调用。
- NOT IMPLEMENTED IN CODE：统一 `RecognitionTask` 引擎。
- NOT IMPLEMENTED IN CODE：workout sets/reps/weight 结构化 schema 或 DB 表。
- NOT IMPLEMENTED IN CODE：nutrition foods/macros 结构化 schema 或 DB 表。

## 收敛判断

当前可落地路线不是重做架构，而是先修复 Prompt/schema/fallback/测试/DB 映射之间的合同裂缝。任何新增字段、Skills、动态 Prompt 拼装，都必须等现有合同和测试收敛后再评估。
