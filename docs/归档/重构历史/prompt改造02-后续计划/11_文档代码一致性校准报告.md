## 修正的关键问题

### 1. Prompt/schema sleep required 合同

真实差异：

- Prompt：`prompts/_source/recognition-rules.json` 要求睡眠截图输出 `records.sleep` 全字段。
- Schema：`src/core/ai/telegram-recognition-schema.mjs` 的 `records.required` 未包含 `sleep`。
- Batch：`src/adapters/telegram/sync-batch-logic.adapter.mjs` 后置跳过缺 sleep 的 sleep image。

文档修正：

- 在 `02`、`07`、`08`、`10` 中列为 P0。
- 明确最小修复文件和测试。

### 2. nutrition recommended nullable 合同

真实差异：

- Prompt：recommended range 没有可靠范围时填 `null`。
- Schema：`recommendedMin/recommendedMax` 当前只允许 number。
- SQL：`core.meal.recommended_min/recommended_max` 允许 null。
- Code：`normalizeNutrition()` 和 writer 可处理 null。

文档修正：

- 在 `02`、`05`、`06`、`07`、`08`、`10` 中统一为 P0 合同修复。

### 3. fallback Prompt 漏 sleep

真实差异：

- 生成 Prompt 和 schema v2 支持 `sleep`。
- `fallbackRecognitionSystemPrompt` 只列 `measurement/workout/nutrition/unknown`。

文档修正：

- 在 `02`、`07`、`08`、`09`、`10` 中列出 fallback 修复和测试。

### 4. workout DB 字段来自 detail 正则，不是 Prompt schema

真实差异：

- Prompt/schema activity 只有 `time/type/detail`。
- `core.activity` 有 calories、heart_rate、distance、avg_speed、duration 字段。
- `normalizeBatchActivity()` 从 `detail` 正则提取。

文档修正：

- `05` 改为要求 Prompt 生成现有正则可解析的 detail 格式。
- `06` 明确 DB 字段不是 AI 结构化字段。

### 5. App Profile 生成器截断风险

真实差异：

- `app-profiles.json` 中的字段可能因为 `renderAppProfilesMemory()` 截断而不进入生成 Prompt。

文档修正：

- `02`、`03`、`05`、`08` 要求关键 alias 生成结果测试。

### 6. caption/text 直接进入 user message

真实差异：

- `buildRecognitionMessages()` 直接拼接 caption/text。
- 当前没有截断或注入边界。

文档修正：

- `02`、`05`、`07`、`08`、`09` 改为明确代码修改项和测试项。
