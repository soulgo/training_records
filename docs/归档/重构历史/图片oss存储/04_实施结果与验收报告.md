## 补齐项（对照 03 文档验收标准）

本次在初版基础上补齐三处遗漏：

1. **workflow summary 上传统计**：adapter 经 `lastUploadStats` 收集，经 `writeThoughtImageArtifacts → attachThoughtStorageMetadata → normalizeSyncReportBatch` 透传到 result JSON，两个 workflow 的 Telegram/Feishu summary 各新增 `## Image storage` 聚合表。满足 03「workflow summary 要求」与「验收标准 → 运维」。
2. **dev≠main 隔离校验**：`sync-dev.yml` 的 `Sync updates` 步骤在 `COS_ENABLED=true` 时校验 dev bucket/domain 不等于 main（`vars.COS_BUCKET`/`vars.COS_DOMAIN`）。满足 03「配置校验规则」dev 校验项。
3. **默认域名格式校验**：`resolveTencentCosConfig` 校验 `COS_DOMAIN` 必须等于 `https://{COS_BUCKET}.cos.{COS_REGION}.myqcloud.com`，未备案自定义域名直接 fail-fast。满足 03「配置校验规则」与「关键失败模式 → 默认 COS 域名被误换成未备案自定义域名」。

## 风险说明

- 本地未使用真实腾讯云 COS bucket/secrets 做外部集成上传；当前验证通过注入 COS SDK 客户端模拟。
- `cos-nodejs-sdk-v5` 传递依赖包含 deprecated 包，`npm ci` 报告 10 个 audit 问题（7 moderate、3 critical）；本次未执行破坏性 `npm audit fix --force`。
- 方案保持历史本地图片路径不迁移，历史图片可访问依赖现有静态资源仍被保留和部署。

## 最终验收结论

已在现有图片链路的 artifact 写入边界完成腾讯云 COS 扩展。默认行为保持本地存储；开启 COS 后，Telegram/飞书随想图片上传 COS，成功 URL 写入数据库并被 Markdown 继续引用；上传失败不会落库。未改数据库 schema、未改 Markdown 生成架构、未改 Cloudflare Worker 逻辑，dev/main 代码逻辑一致，仅配置来源不同。
