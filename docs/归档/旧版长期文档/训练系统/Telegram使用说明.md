# Telegram 使用说明

这份文档面向日常使用者，专门说明当前仓库里 Telegram Bot 的常见用法：怎么发锻炼、体脂秤、饮食和睡眠图片，怎么发随想，怎么编辑随想，怎么删除随想，怎么移动随想，以及怎么使用分析和 AI 助手。

默认前提：

- 你是在已经授权的 Telegram chat 里和 Bot 交互
- 当前随想模块有三个：`锻炼`、`杂七杂八` 和 `身体反馈`
- 睡眠数据会进入训练数据链路，但不通过 `/随想`、`/thought` 直接写入随想页

## 1. 你可以用 Telegram 做什么

当前主要有两类用法：

- 发锻炼、体脂秤、饮食、睡眠截图，让系统自动识别并归档
- 发“随想”，把文字或带图内容写进站点随想页
- 发送 `/分析 问题` 获取训练建议
- 发送 `/help`、`/帮助`、`help` 或 `帮助` 查看当前命令清单

这些入口不要混淆：

- 普通图片消息会走截图识别
- 但如果图片 caption 以 `/随想` 或 `/thought` 开头，这批图片会被当作“随想”，不会再走训练数据图片识别
- 如果文档附件 caption 以 `/随想` 或 `/thought` 开头，并且附件是 `.md` / `.markdown` Markdown 文件，这条消息会被当作“Markdown 附件随想”
- `/help`、`/帮助`、`help`、`帮助`、`命令`、`指令`、`使用说明` 会优先由 Cloudflare Worker 直接回复，不会触发 GitHub Actions；如果消息已经进入 Telegram Sync，也会直接回发帮助，不写数据库或文件

## 2. 帮助命令

如果记不住命令，可以直接给 Bot 发：

```text
/help
/帮助
help
帮助
命令
指令
使用说明
```

Bot 会直接回发当前可用命令清单，包括截图、随想、编辑、删除、移动和 `/分析`。

这类帮助消息优先在 Cloudflare Worker 层处理，不会触发 GitHub `repository_dispatch`，也不会启动 `Telegram Sync` GitHub Actions。如果 webhook 配置或部署版本导致消息已经进入 `Telegram Sync`，同步脚本也会直接回发帮助，不会写数据库、Markdown 或图片识别结果。

## 3. 命令识别优先级

Telegram 同步入口使用声明式命令注册表识别消息意图。当前优先级固定为：

1. `help`
2. `move`
3. `delete`
4. `analysis`
5. `explicit_edit`
6. `edited_message`
7. `reply_edit`
8. `thought`
9. `image`

维护规则：

- `help` 必须最先处理，避免帮助消息被其它文本分支消费。
- `move` 必须排在 `thought` 前面，保证 `/随想 <id> <模块>` 继续按移动处理。
- `analysis` 是不写数据的直接回复分支。
- `explicit_edit` 必须排在相册图片归组前面，保证单图 caption 的编辑命令仍可替换图片。
- `edited_message` 和 `reply_edit` 必须排在 `thought` 前面，保证已知随想的编辑不会被识别成新随想。
- `image` 仍由图片和相册分组逻辑处理，registry 只声明它的优先级位置。
- Markdown 文档附件随想仍归入 `thought` 命令组；附件类型识别由 Telegram 同步归一化逻辑处理。

调整命令优先级或 alias 后，至少运行：

```bash
node --test test/telegram-sync.test.mjs test/telegram-sync-runner.test.mjs
```

## 4. 图片怎么发

### 4.1 发送锻炼、体脂秤、饮食、睡眠截图

最简单的方式就是直接把图片发给 Bot：

- 单张图片可以直接发
- 多张同一天的图片可以作为一个相册一起发
- 如果同一相册里混入了不同日期的图片，整批可能被跳过，不会强行错归档

归档日期的核心规则：

- 系统优先看图片里真实可见的日期
- 图片里没有可靠日期时，才可能回退到 Telegram 原始文件名日期
- 如果既没有图片日期，也没有可用文件名日期，这批图片会被跳过

发送方式建议：

- 如果你想依赖“文件名里的日期”做回退，优先用 Telegram `文件` 发送，不要用 `照片`
- 因为 `照片` 发送时，Telegram Bot API 通常拿不到原始文件名
- 如果只能用 `照片` 发送，尽量保证截图画面里本身就能看到日期

当前稳定支持的截图类型：

| 截图类型 | 识别结果 | 主要落表/落点 |
| --- | --- | --- |
| 锻炼总览、活动明细 | 当日活动热量、锻炼时长、活动小时数、活动明细、距离、心率等 | `core.training_day`、`core.activity`、`archive.training_activity` |
| 体脂秤、身体成分 | 体重、BMI、体脂率、骨骼肌、内脏脂肪、基础代谢、水分、蛋白质、骨盐量、去脂体重等 | `core.measurement`、`archive.training_measurement` |
| 饮食记录 | 餐次热量、建议范围、总摄入、餐次明细 | `core.training_day`、`core.meal`、`archive.training_meal` |
| 睡眠记录 | 入睡/起床时间、总睡眠、深睡/浅睡/REM/清醒、睡眠评分、心率、HRV、血氧、呼吸率、解读和建议 | `core.sleep`、`core.training_day` 睡眠汇总 |

睡眠截图有一个特殊日期口径：系统会把“醒来日期的前一天”作为睡眠归档日。例如截图显示 2026-06-05 早上醒来，这条夜间睡眠会归到 2026-06-04。这样可以避免跨午夜睡眠被记到醒来的那一天。

如果你只补发一张无日期的体脂秤或饮食图，推荐用 Telegram `文件` 发送，并让文件名带 `YYYY-MM-DD` 或 `YYYYMMDD`。如果是睡眠图，尽量保证截图里能看到醒来日期或完整的睡眠日期范围；睡眠图不会靠 AI 猜当前日期。

图片批次识别并入库成功后，数据库是页面和分析的主事实源。系统不会即时写 `训练记录.md`；Markdown 由 DB -> Markdown 备份 workflow 定时导出。数据库失败时会写入 pending replay 队列，并提示后续自动重放。

## 5. 发送随想

### 5.1 纯文字随想

可以直接给 Bot 发：

```text
/随想 今天深蹲动作轨迹更稳了
/thought 今天训练后臀部发力更明显
```

默认会进入 `锻炼` 模块。

写入成功后，Bot 会回复一条成功反馈，例如：

```text
随想写入成功，已入库
```

如果 PostgreSQL 暂时失败，Bot 会说明“已记录，数据库待补偿”，系统会在后续同步中自动重放 pending 队列。Markdown 不再作为即时 fallback 写入目标。

训练图片也遵循同样的补偿口径：如果 Telegram 回复或 GitHub Actions summary 中看到 `pending_replay` 或 `auto_retry`，表示当前批次已经进入自动补偿链路；如果失败分类是 `user_input`，通常需要重新发送更清晰的图片或修正日期来源。

### 5.2 指定随想模块

如果想把随想发到不同模块，可以在命令后面先写模块名：

```text
/随想 锻炼 今天腿练得很实
/随想 杂七杂八 今天把零碎事情记一下
/thought 杂七杂八 今天记一条非训练内容
/随想 身体反馈 今天硬拉后右侧腰背有点刺痛
```

当前支持的模块名只有：

- `锻炼`
- `锻炼随想`
- `杂七杂八`
- `身体反馈`

规则要点：

- 命令后的第一个词如果是上面这些模块名，会被当作模块选择，不会算进正文
- 如果第一个词不是已识别模块，就会被当成正文，模块仍然默认是 `锻炼`

### 5.3 带图随想

如果你想发“图片 + 随想”，做法是把命令写进图片 caption：

```text
/随想 今天深蹲轨迹更稳了
/thought 训练姿态记录
/随想 杂七杂八 今天把这张图顺手存一下
/随想 身体反馈 今天膝盖外侧有点酸，附上动作截图
```

说明：

- 单张图片支持
- 相册也支持
- 相册 caption 会生成一条随想，并把这组图片一起挂到同一条随想下
- 识别为随想后，这批图不会再进入训练数据图片 AI 识别

### 5.4 Markdown 文档附件随想

如果随想正文比较长，可以把 Markdown 文件作为 Telegram 文档附件发送，并在附件 caption 写命令：

```text
/随想
/随想 杂七杂八
/随想 身体反馈
```

支持的附件：

- 文件名以 `.md` 或 `.markdown` 结尾
- `text/markdown`、`text/x-markdown`
- `text/plain` 且文件名是 `.md` 或 `.markdown`

规则：

- 系统会下载第一个 Markdown 附件，按 UTF-8 解码，去掉 UTF-8 BOM，并 trim 后写入 `core.thought.body`
- caption 只用于识别命令和模块；如果 caption 同时写了正文和 Markdown 附件，页面正文以 Markdown 附件为准
- 单个 Markdown 附件大小上限为 5MB；超限、空文件或下载失败都不会入库，Telegram 回复会带失败原因
- Markdown 附件不会进入训练图片识别，也不会生成附件下载卡片
- 页面仍由 DB -> Markdown 备份导出后通过 Hexo 渲染 Markdown 正文

## 6. 怎么找到随想 ID

很多编辑、删除、移动命令都支持直接按 `id` 操作。

这个 `id` 就是随想页面上显示的 `#126`、`#175` 这种编号，也就是 Telegram message id。

如果你不知道 id，有两种最简单的办法：

- 去随想页面看卡片右侧的 `#数字`
- 或者直接回复原随想消息，不用手工填 id

## 7. 编辑随想

当前支持三种编辑方式。

### 7.1 直接编辑原 Telegram 消息

如果这条随想就是你自己刚发的原始 Telegram 消息，可以直接在 Telegram 里编辑它的内容。

适合场景：

- 改错别字
- 改正文
- 小幅修正文案

如果只是普通正文修订，这是最直接的方式。

### 7.2 回复原随想消息，发送修订版

回复原随想消息，再发一条新的修订命令：

```text
/随想 修订后的完整正文
/thought 修订后的完整正文
/随想 杂七杂八 修订后的完整正文
/随想 身体反馈 修订后的完整正文
```

规则：

- 这条新消息必须“回复”到原随想消息
- 如果没有显式写模块，系统会保留原来的模块
- 如果显式写了 `锻炼`、`杂七杂八` 或 `身体反馈`，系统会同步更新模块和标签

### 7.3 通过 ID 显式编辑

如果你不想回复原消息，也可以直接按 id 改：

```text
/随想编 126 修订后的完整正文
/随想编 126 杂七杂八 修订后的完整正文
/随想编 126 身体反馈 修订后的完整正文
```

这也是当前最适合“精确修改指定随想”的方式。

### 7.4 用 Markdown 文档附件编辑

如果原随想正文很长，编辑时可以重新发送一份 Markdown 文档附件，并把 caption 写成：

```text
/随想编 126
/随想编 126 杂七杂八
/随想编 126 身体反馈
```

规则：

- 这是“用新的 Markdown 附件正文整体替换旧正文”
- caption 只用于识别目标 id 和模块；如果 caption 同时写了正文，仍以附件内容为准
- 附件同样支持 `.md`、`.markdown`、`text/markdown`、`text/x-markdown`，以及 `text/plain` 且文件名是 Markdown 扩展名
- 单个附件大小上限为 5MB；空文件、下载失败或超限都不会入库

### 7.5 编辑时替换图片

如果你想把一条旧随想里的图片换掉，推荐使用：

```text
/随想编 126 修订后的完整正文
```

然后把新图片和这条命令一起发送。

这里要注意：

- 这是“替换图片”，不是“追加图片”
- 新图写入后，旧图会被删除
- 如果只是普通回复修订或直接编辑原消息，不建议依赖它来替图；要替图时优先用 `/随想编 <id> ...`

## 8. 删除随想

删除支持两种方式：

```text
/随想删
/随想删 126
```

规则：

- `/随想删` 必须回复原随想消息
- `/随想删 126` 是直接按 id 删除
- 删除时不需要写模块名
- 删除后会把 `core.thought` 标记为 deleted；已存在的 Markdown 备份和图片 artifact 不作为事实源
- 如果没有 id，也没有回复到可解析的原随想消息，系统会返回失败原因，不会提示删除成功

## 9. 移动随想

“移动”指的是把一条随想从一个模块改到另一个模块，比如从 `锻炼` 挪到 `杂七杂八`，或挪到 `身体反馈`。

支持两种方式：

```text
/移动 锻炼
/移动 杂七杂八
/移动 身体反馈
/移动 126 锻炼
/移动 126 杂七杂八
/移动 126 身体反馈
/随想 126 锻炼
/随想 126 杂七杂八
/随想 126 身体反馈
```

规则：

- `/移动 锻炼`、`/移动 杂七杂八`、`/移动 身体反馈` 需要回复原随想消息
- `/移动 126 锻炼`、`/移动 126 杂七杂八`、`/移动 126 身体反馈` 是直接按 id 移动
- `/随想 126 锻炼`、`/随想 126 杂七杂八`、`/随想 126 身体反馈` 也会按移动处理，兼容以前的发送习惯
- 移动只会改模块和标签
- 不会改正文、图片、日期、文件名和随想 id

## 10. 分析

### 10.1 `/分析` 训练建议

```text
/分析 今天怎么练
/analysis 最近7天训练怎么样
```

`/分析` 是专用训练分析命令，会读取训练、体脂、饮食和身体反馈摘要，生成训练建议。它不会写 Markdown、随想或数据库。

## 11. 失败反馈

Telegram 同步会尽量把失败原因直接回复到原消息：

- `user_input`：图片无可靠日期、置信度低、未授权 chat、目标随想不存在等输入问题。
- `ai_service`：AI 服务 HTTP 错误、限流、超时、空响应、JSON/schema 错误。
- `telegram_api`：Telegram 文件下载或消息回发失败。
- `database`：PostgreSQL 写入失败，通常会进入 pending replay 补偿。
- `github_action`：GitHub Actions 的安装依赖、同步、测试、提交、推送或部署阶段失败。
- `system_bug`：未归入上述类别的代码异常。

如果 Worker 无法启动 GitHub Action，会回复“GitHub Action 未能启动”。如果 Action 已经启动但中途失败，会回复失败阶段和 GitHub Actions 日志链接。

## 12. 常见建议

- 发训练数据截图时，尽量一批只发同一天的图，不要跨天混发
- 想靠文件名日期回退时，用 Telegram `文件` 发送，不要用 `照片`
- 想发“带图随想”时，记得把 `/随想` 或 `/thought` 写在 caption 开头
- 想发长篇 Markdown 随想时，用 Telegram `文件` 发送 `.md` / `.markdown`，并把 `/随想` 或模块命令写在附件 caption 开头
- 想精确修改某条随想时，优先用 `/随想编 <id> ...`
- 想删除或移动，但一时找不到 id 时，直接回复原随想消息最省事
- 如果正文开头正好是 `锻炼`、`杂七杂八` 或 `身体反馈`，系统可能把它当成模块名；这种场景建议把表达方式改一下，避免歧义
