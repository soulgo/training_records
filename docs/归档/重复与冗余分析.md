# 重复与冗余分析

> 审核时间: 2026-06-22

## 总体结论

当前主文档已经从历史讨论集合收敛到较小的事实文档集。主要冗余不再是“多个同名长文档”，而是同一事实在不同主文档中的重复解释风险。

建议把 `docs/总览/系统行为手册.md` 作为四类用户行为的 SSOT，其它文档只补充本领域细节。

## 信息碎片化问题

当前 AI Agent 若直接读全部 docs，会遇到三个问题：

1. 行为模型分散在总览、核心业务、消息链路、AI 识别体系、数据模型。
2. `telegram_*` 历史命名在表、函数和文档中反复出现，容易掩盖飞书共享链路。
3. 归档历史过多，不适合作为默认上下文。

## 收敛原则

1. 行为事实写 `总览/系统行为手册.md`。
2. 链路事实写 `消息链路/消息链路.md`。
3. 数据事实写 `数据模型/数据模型.md` 和 `数据模型/图片识别字段映射.md`。
4. AI 合同写 `AI识别体系/AI识别体系.md`，具体规则仍以 `prompts/_source` 和生成 prompt 为准。
5. 运维步骤写 `部署运维`、`运维手册`、`故障排查`，避免互相复制。
