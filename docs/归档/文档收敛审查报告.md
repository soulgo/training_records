## 问题列表

### 图片识别行为

### 1. 时间优先级文档目标包含当前代码未实现的系统接收时间兜底

- **严重级别**: P1
- **位置**:
  - 文档: `docs/总览/系统行为手册.md`
  - 代码: `src/adapters/telegram/sync-batch-logic.adapter.mjs:427`, `src/adapters/telegram/sync-dates.adapter.mjs:103`
- **证据**:
  - 文档片段:
    ```text
    理想优先级“图片内时间 -> 消息时间 -> 系统接收时间”与当前代码不完全一致。
    ```
  - 代码片段:
    ```js
    archivedDate = resolveDetectedDate(filenameDates);
    if (!archivedDate) {
      return buildSkippedBatchResult(... 'no reliable image or filename date')
    }
    ```
- **影响**: 运维或 AI Agent 可能误以为缺少日期的图片仍会按系统接收时间入库，实际会跳过 batch。
- **建议（最小修正）**: 若业务必须要三级兜底，补实现和测试；若不需要，正式文档只保留当前行为，不写系统接收时间兜底。
- **修复收益**: 避免错误补时间，减少日期归档事故和人工排障成本。
- **关联原则**: 以代码为真、按场景审计。

### 2. 识别 fallback prompt 漏掉 `sleep`

- **严重级别**: P1
- **位置**:
  - 文档: `docs/AI识别体系/AI识别体系.md:47`
  - 代码: `src/app/use-cases/telegram-sync/image-processing.mjs:16`
- **证据**:
  - 文档片段:
    ```text
    imageType 支持 measurement、workout、nutrition、sleep、unknown。
    ```
  - 代码片段:
    ```js
    识别类型只允许 measurement、workout、nutrition、unknown。
    ```
- **影响**: prompt 文件读取失败时，fallback prompt 会把睡眠识别能力降级为不可用，和正式 schema/prompt 不一致。
- **建议（最小修正）**: 修改 fallback prompt，加入 `sleep`，并补一条测试防止 fallback prompt 与 schema enum 漂移。
- **修复收益**: 避免极端故障路径下睡眠截图被误判为 unknown。
- **关联原则**: 合同优先、以代码为真。

### 3. `records.sleep` 已定义但不在 `records.required` 中

- **严重级别**: P2
- **位置**:
  - 文档: `prompts/telegram-training-image-recognition.md:126`
  - 代码: `src/core/ai/telegram-recognition-schema.mjs:24`
- **证据**:
  - 文档片段:
    ```text
    睡眠截图必须输出 records.sleep schema 中的全部字段。
    ```
  - 代码片段:
    ```js
    required: ['measurement', 'activities', 'meals', 'totalCalories', 'details', 'dailyWorkoutSummary']
    ```
- **影响**: schema 不强制 `records.sleep` 出现；当 AI 漏掉 sleep 对象时，可能由业务层再发现，错误定位成本更高。
- **建议（最小修正）**: 将 `sleep` 加入 `records.required`，或在文档中明确 `records.sleep` 是条件必填并保留业务层检查。
- **修复收益**: 降低结构漂移风险，提升 schema 即时拦截能力。
- **关联原则**: 合同优先。
