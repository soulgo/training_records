# CPU、内存与资源

## 现象

- AI 识别耗时过长。
- 图片下载失败或超时。
- Node 进程在 Actions 中异常退出。
- 同步处理大量图片时不稳定。

## 原因

- `AI_CONCURRENCY` 设置过高。
- `AI_TIMEOUT_MS` 或识别 fallback timeout 不合适。
- 单图下载大小超过 `MAX_IMAGE_DOWNLOAD_BYTES`。
- Actions runner 资源有限。

## 日志特征

- `timeout`
- `ETIMEDOUT`
- `fetch failed`
- `AI recognition request failed`
- `maxDownloadBytes`

## 排查步骤

1. 查并发归一：`src/app/use-cases/telegram-sync.use-case.mjs:891`。
2. 查 AI timeout：`src/adapters/ai/openai-compatible.adapter.mjs:7`。
3. 查图片下载大小：`src/app/use-cases/telegram-sync.use-case.mjs:121`、`src/app/use-cases/feishu-sync.use-case.mjs:61`。
4. 查 Actions summary 中 `timingsMs`。

## 解决方案

- 降低 `AI_CONCURRENCY`。
- 增加或修正 `AI_TIMEOUT_MS`、`TELEGRAM_RECOGNITION_FALLBACK_TIMEOUT_MS`。
- 对超大图片改用更小文件或配置 `MAX_IMAGE_DOWNLOAD_BYTES`。

## 预防措施

- 默认并发保持小值。
- 大批量导入前先在 dev 环境验证。
- 不在 Worker 中做重型 AI 或图片上传，重活放在 GitHub Actions Node 进程。
