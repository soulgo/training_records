# 部署

## 现象

- Worker 未更新。
- 静态站点未更新。
- 生产页面仍显示旧内容。
- dev Pages 预览没有新随想。

## 原因

- Worker deploy workflow 未运行或 wrangler 失败。
- sync 已成功派发 deploy，但 Pages workflow 独立失败；sync 不会等待或回滚已完成的业务入库。
- Pages 构建使用了旧快照。
- GitHub Pages 部署成功但 Cloudflare cache purge 失败。
- dev Pages 删除 `public/CNAME` 前构建失败。

## 日志特征

- `Cloudflare cache purge failed`
- `Cloudflare Pages deploy failed`
- `Thought page verification failed`
- `test -s public/index.html` 失败
- `Node.js 20 is deprecated` 且来源为 `cloudflare/wrangler-action@v3`，表示 Worker workflow 回退到了旧 Action；当前合同应使用 `npx --yes wrangler@3.114.14`。

## 排查步骤

1. Worker：查 `.github/workflows/deploy-cloudflare-worker.yml` 或 `deploy-cloudflare-worker-dev.yml`。
2. Pages：查 `.github/workflows/deploy-pages.yml` 或 `deploy-cloudflare-pages-dev.yml`。
3. shared build：查 `.github/actions/site-build/action.yml`。
4. 数据生成：查 `src/app/use-cases/generate-training-data.use-case.mjs`。
5. 页面验证：查 workflow 中 `Verify deployed thought module page`。

## 解决方案

- Worker 配置变化后重跑对应 Worker deploy。
- Worker CLI 部署失败时核对 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID` 和对应 `wrangler*.toml`；生产与 dev workflow 都使用固定版本 `wrangler@3.114.14`，不依赖 `cloudflare/wrangler-action`。
- DB-only 内容变化后重跑 Pages workflow。
- Cloudflare cache purge 失败时修正 `CLOUDFLARE_ZONE_ID` 和 token 权限后重跑。

## 预防措施

- main 用 GitHub Pages，dev 用 Cloudflare Pages。
- dev 构建上传前删除 `public/CNAME`。
- 生产发布后必须关注 cache purge step。
- Worker workflow 保持 Wrangler CLI 版本固定，并在升级前通过 workflow 契约测试确认配置文件和 Secret 映射不变。
