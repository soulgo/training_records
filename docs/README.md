# Training Records 文档

本目录是项目维护文档入口。

## 快速导航

| 文档 | 作用 |
| --- | --- |
| [系统核心](系统核心.md) | 系统当前核心逻辑：架构、业务、消息链路、AI 识别、数据模型、运维排障、开发指南、命令接口参考 |
| [系统配置](系统配置.md) | 部署配置：需要哪些参数（参数总表），参数在哪里找、在哪里设置（平台指南） |
| [重构历史](重构历史/README.md) | 以往重构优化历史文档索引（v13-v23、prompt 改造、核心代码优化、图片 OSS 等） |
| [后续规划_未实现](后续规划_未实现/README.md) | 未实现功能与后续计划索引（不作为当前事实入口） |

## 阅读建议

- 想理解系统怎么运转：读 [系统核心](系统核心.md)，重点看「一张图片如何识别并归档到某一天」。
- 想部署/配置系统：读 [系统配置](系统配置.md)，先看参数总表，再看平台指南。
- 想了解以前做过什么重构：读 [重构历史](重构历史/README.md)。
- 想看未实现的规划：读 [后续规划_未实现](后续规划_未实现/README.md)。

## 事实源规则

- 代码、SQL、workflow、prompt source 是最终事实源。
- PostgreSQL `core.*` 是训练、饮食、体脂、睡眠、随想、分析的事实源。
- Markdown 是 DB 派生备份，不是图片同步的主写入路径。
- `重构历史/` 是历史审计路径，`后续规划_未实现/` 是未实现规划；二者不作为当前行为依据。
- 文档整理不得修改运行逻辑、代码、配置或接口行为。

## 维护规则

1. 改代码、SQL、workflow、prompt 时，同步更新 [系统核心](系统核心.md) 或 [系统配置](系统配置.md)。
2. 不把新事实写进 `重构历史/` 或 `后续规划_未实现/`。
3. 已实现内容必须从 `后续规划_未实现/` 移出；需要追溯时归档到 `重构历史/`。
4. 纯文档整理不得修改运行逻辑。
