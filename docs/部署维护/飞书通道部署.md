# 飞书通道部署

本文用于首次部署飞书消息通道。飞书通道与 Telegram 共享同步主流程：训练图片进入 AI 识别和 PostgreSQL 入库，`/随想` 写入 `core.thought`，`/分析` 读取 `TrainingSnapshot` 后通过飞书回发文本。

## 当前已配置链路

飞书事件回调统一使用 Cloudflare Worker 自定义域名，不在飞书后台填写 `workers.dev` 地址。

| 环境 | 飞书 Request URL | Cloudflare Worker | Wrangler 配置 | GitHub dispatch | GitHub workflow | 写入分支 |
| --- | --- | --- | --- | --- | --- | --- |
| 生产 | `https://feishu.soulgo.chat` | `feishu-sync-dispatch` | `wrangler.feishu.toml` | `feishu_update` | `.github/workflows/feishu-sync.yml` | `main` |
| dev | `https://feishu-dev.soulgo.chat` | `feishu-sync-dispatch-dev` | `wrangler.feishu-dev.toml` | `feishu_update_dev` | `.github/workflows/feishu-sync-dev.yml` | `dev` |

两套 Worker 都需要分别配置 Cloudflare Worker Secrets：`GITHUB_TOKEN`、`FEISHU_ENCRYPT_KEY`、`FEISHU_VERIFICATION_TOKEN`。Secret 存储是按 Worker 隔离的，即使值可以复用，也要在生产和 dev Worker 里各配置一次。

Worker 已支持飞书明文回调和开启加密策略后的 `{"encrypt":"..."}` 回调。飞书后台开启加密策略时，Cloudflare Secret `FEISHU_ENCRYPT_KEY` 必须与飞书开放平台里的 `Encrypt Key` 完全一致，否则 URL 验证会失败。

## 1. 当前能力与边界

已支持：

- 飞书图片消息：锻炼、体脂秤、饮食、睡眠截图识别并入库，core 子表写 `source_channel='feishu'`。
- 飞书 `/随想` / `/thought`：文本随想 DB-first 写入。
- 飞书 `/帮助`、`/分析`：复用现有命令解析和回复链路。
- 飞书连续图片：Worker 通过 `FEISHU_IMAGE_BUFFER` 按 chat 缓冲约 3 秒后派发。

当前边界：

- 飞书不复制 Telegram 主流程；`npm run sync:feishu` 只是飞书适配入口。
- 飞书 Markdown 文档附件随想暂不支持；Markdown 附件能力仍是 Telegram 专属。
- 飞书随想编辑、删除、移动暂不作为主支持路径；当前先保证新建 `/随想`。
- `core.thought.telegram_message_id` 仍是历史兼容字段名。飞书原始 `message_id` 是字符串，系统会生成稳定数字代理 ID，并保留 `sourceChannel/sourceMessageId/sourceChatId`。

## 2. 参数总览

先按下面四类参数配置，避免把 GitHub、Cloudflare 和飞书后台混在一起。

### 2.1 最小生产配置清单

生产链路最少需要这些值：

| 存放位置 | 必填参数 | 可复用情况 |
| --- | --- | --- |
| 飞书开放平台 | `App ID`、`App Secret`、`Encrypt Key`、`Verification Token`、`Request URL`、事件权限 | 新增飞书通道专用；生产 Request URL 使用 `https://feishu.soulgo.chat`，dev 使用 `https://feishu-dev.soulgo.chat` |
| GitHub Actions Secrets | `FEISHU_APP_ID`、`FEISHU_APP_SECRET` | 来自飞书应用；dev 可选择复用 |
| GitHub Actions Variables | `FEISHU_ALLOWED_CHAT_IDS` | 来自飞书消息事件；dev 可选择复用 |
| GitHub Actions 既有 AI 配置 | `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` | 直接复用 Telegram/训练分析现有配置 |
| GitHub Actions 既有 DB 配置 | `TRAINING_DB_ENABLED`、`TRAINING_DB_URL` | 直接复用生产数据库配置 |
| Cloudflare Worker Secrets | `GITHUB_TOKEN`、`FEISHU_ENCRYPT_KEY`、`FEISHU_VERIFICATION_TOKEN` | `GITHUB_TOKEN` 的值可复用；生产和 dev Worker 都要单独设置 |
| Cloudflare Worker Variables | `GITHUB_DISPATCH_EVENT_TYPE` | 生产为 `feishu_update`；dev 为 `feishu_update_dev`，已写入对应 Wrangler 配置 |

如果通过 GitHub Actions 部署 Worker，还需要复用或配置：

| 存放位置 | 参数 | 获取方式 |
| --- | --- | --- |
| GitHub Actions Secrets | `CLOUDFLARE_API_TOKEN` | Cloudflare Dashboard 创建 API Token；如果已有 Telegram Worker 部署 token，可复用 |
| GitHub Actions Secrets | `CLOUDFLARE_ACCOUNT_ID` | Cloudflare Dashboard 账户首页右侧 Account ID；如果已有部署配置，可复用 |

### 2.2 飞书专属参数

| 参数 | 存放位置 | 获取方式 | 复用规则 | 备注 |
| --- | --- | --- | --- | --- |
| `FEISHU_APP_ID` | GitHub Actions Secret | 飞书开放平台 -> 企业自建应用 -> 凭证与基础信息 -> `App ID` | 生产必填；dev 可通过不配置 `DEV_FEISHU_APP_ID` 复用 | 与 `FEISHU_APP_SECRET` 成对 |
| `FEISHU_APP_SECRET` | GitHub Actions Secret | 飞书开放平台 -> 企业自建应用 -> 凭证与基础信息 -> `App Secret` | 生产必填；dev 可通过不配置 `DEV_FEISHU_APP_SECRET` 复用 | 不要放入 Variables |
| `DEV_FEISHU_APP_ID` | GitHub Actions Secret | Dev 飞书应用的 `App ID` | 可选；不配置则 dev workflow 复用 `FEISHU_APP_ID` | 需要独立 dev 飞书应用时再配置 |
| `DEV_FEISHU_APP_SECRET` | GitHub Actions Secret | Dev 飞书应用的 `App Secret` | 可选；不配置则 dev workflow 复用 `FEISHU_APP_SECRET` | 需要独立 dev 飞书应用时再配置 |
| `FEISHU_ALLOWED_CHAT_IDS` | GitHub Actions Variable | 飞书消息事件里的 `event.message.chat_id` | 生产必填；dev 可通过不配置 `DEV_FEISHU_ALLOWED_CHAT_IDS` 复用 | 多个 chat id 用英文逗号分隔 |
| `DEV_FEISHU_ALLOWED_CHAT_IDS` | GitHub Actions Variable | Dev 飞书消息事件里的 `event.message.chat_id` | 可选；不配置则 dev workflow 复用 `FEISHU_ALLOWED_CHAT_IDS` | 用独立 dev 群或 dev 应用时配置 |
| `FEISHU_ENCRYPT_KEY` | Cloudflare Worker Secret | 飞书开放平台 -> 当前应用 -> 开发配置 -> 事件与回调 -> 加密策略 -> `Encrypt Key` | 每个 Worker 都要配置；只有复用同一个飞书应用或同一套事件订阅时，值才可复用 | 与飞书后台 `Encrypt Key` 完全一致 |
| `FEISHU_VERIFICATION_TOKEN` | Cloudflare Worker Secret | 飞书开放平台 -> 当前应用 -> 开发配置 -> 事件与回调 -> 页面里的 `Verification Token` | 每个 Worker 都要配置；只有复用同一个飞书应用或同一套事件订阅时，值才可复用 | 与飞书后台 `Verification Token` 完全一致 |
| `FEISHU_API_BASE_URL` | 运行环境变量 | 默认 `https://open.feishu.cn` | 通常不配置 | 仅代理或测试飞书 API 时使用 |

`chat_id` 获取方式：

飞书开放平台的 `日志检索 -> 事件日志检索` 或 `开发配置 -> 事件与回调 -> 事件配置 -> 事件投递日志` 拿不到 `chat_id`。这类日志只展示投递元数据，例如 `eventId`、`address`、`httpCode`、`costMillis`，不是完整 webhook 消息体；如果只看到 `eventId` 而没有 `event.message.chat_id`，这是正常的。

推荐从 Cloudflare Worker 实时日志获取 `chat_id`。Worker 会为每条 `im.message.receive_v1` 打印一行不含消息正文的元数据：

```text
[feishu-webhook] {"event_id":"...","event_type":"im.message.receive_v1","app_id":"...","chat_id":"oc_xxx","message_id":"...","message_type":"text"}
```

操作步骤：

1. 先完成 Worker 部署和飞书事件订阅。
2. 在本地启动对应 Worker 的实时日志。
3. 在目标飞书群或私聊里给应用发送一条普通消息，例如 `/帮助` 或 `test`。
4. 从 `[feishu-webhook]` 日志里的 `chat_id` 复制 `oc_xxx`。
5. 按环境写入 GitHub Actions Variable。
6. 用 `Ctrl+C` 退出 tail。

生产 Worker tail：

```bash
npx wrangler tail feishu-sync-dispatch --format=pretty
```

dev Worker tail：

```bash
npx wrangler tail feishu-sync-dispatch-dev --format=pretty
```

变量填写规则：

```text
生产：FEISHU_ALLOWED_CHAT_IDS=oc_xxx
dev：DEV_FEISHU_ALLOWED_CHAT_IDS=oc_xxx
多个 chat：FEISHU_ALLOWED_CHAT_IDS=oc_xxx,oc_yyy
```

如果 tail 没有出现 `[feishu-webhook]` 日志，优先检查：

- tail 是否在发送飞书消息之前启动。
- 飞书 Request URL 是否填了当前环境的自定义域名：生产 `https://feishu.soulgo.chat`，dev `https://feishu-dev.soulgo.chat`。
- 飞书事件是否已订阅 `im.message.receive_v1`。
- 应用是否已经加入目标群，或是否能收到私聊消息。
- tail 是否连的是正确 Worker：生产 `feishu-sync-dispatch`，dev `feishu-sync-dispatch-dev`。
- Worker Variables 是否设置了 `FEISHU_EVENT_LOGGING=false`。默认不设置时会打印这条诊断日志。

兜底方式：如果 GitHub workflow 已经更新到新版 summary，也可以先在 GitHub Actions Variables 填一个占位值，例如 `DEV_FEISHU_ALLOWED_CHAT_IDS=oc_probe_placeholder`，触发一次 `Feishu Sync (Dev)` 后，在运行摘要 `Feishu sync result` 表格里看 `chatIds` 列。这个方式慢一些，优先用 Cloudflare tail。

## 3. 飞书开放平台配置

1. 进入飞书开放平台，创建企业自建应用。
2. 在当前应用的 `凭证与基础信息` 里记录：
   - `App ID` -> GitHub Actions Secret `FEISHU_APP_ID`
   - `App Secret` -> GitHub Actions Secret `FEISHU_APP_SECRET`
3. 在权限管理中开通并发布以下权限：
   - `im:message`
   - `im:message.p2p_msg`
   - `im:message.group_at_msg`
   - `im:resource`
4. 进入 `开发配置 -> 事件与回调`，准备回调参数：
   - `加密策略 -> Encrypt Key` -> Cloudflare Worker Secret `FEISHU_ENCRYPT_KEY`
   - 页面中的 `Verification Token` -> Cloudflare Worker Secret `FEISHU_VERIFICATION_TOKEN`
   - 生产应用 Request URL 填 `https://feishu.soulgo.chat`
   - dev 应用 Request URL 填 `https://feishu-dev.soulgo.chat`
5. 在 `事件配置` 中订阅事件：
   - `im.message.receive_v1`

Request URL 需要等 Cloudflare Worker 部署完成后再填写。保存 Request URL 前，对应 Worker 的 `FEISHU_ENCRYPT_KEY` 和 `FEISHU_VERIFICATION_TOKEN` 必须已经配置好；飞书保存时会立即发送 `url_verification` challenge。Worker 支持明文 challenge，也支持开启加密策略后的 `{"encrypt":"..."}` challenge。

事件投递日志在 `开发配置 -> 事件与回调 -> 事件配置 -> 事件投递日志`。只有 Request URL 保存成功、事件已订阅，并且应用实际收到消息后，日志里才会出现投递记录；该记录常常只包含投递元数据，不保证展示完整消息体或 `chat_id`。

## 4. GitHub 配置

在 GitHub 仓库 `Settings -> Secrets and variables -> Actions` 配置。

### 4.1 Secrets

生产飞书同步必填：

```text
FEISHU_APP_ID=飞书应用 App ID
FEISHU_APP_SECRET=飞书应用 App Secret
```

Dev 飞书同步可选：

```text
DEV_FEISHU_APP_ID=Dev 飞书应用 App ID
DEV_FEISHU_APP_SECRET=Dev 飞书应用 App Secret
```

如果 Dev Secret 未配置，`.github/workflows/feishu-sync-dev.yml` 会回退使用生产 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`。

如果通过 GitHub Actions 部署 Worker，还需要：

```text
CLOUDFLARE_API_TOKEN=Cloudflare API Token
CLOUDFLARE_ACCOUNT_ID=Cloudflare Account ID
```

这两个值如果已经用于 Telegram Worker 或 Pages 部署，可以复用。

### 4.2 Variables

生产飞书同步必填：

```text
FEISHU_ALLOWED_CHAT_IDS=oc_xxx
```

多个 chat id 用英文逗号分隔：

```text
FEISHU_ALLOWED_CHAT_IDS=oc_xxx,oc_yyy
```

Dev 飞书同步可选：

```text
DEV_FEISHU_ALLOWED_CHAT_IDS=oc_dev_xxx
```

如果 `DEV_FEISHU_ALLOWED_CHAT_IDS` 未配置，dev workflow 会回退使用生产 `FEISHU_ALLOWED_CHAT_IDS`。

## 5. main 与 dev 配置差异

飞书通道有生产和 dev 两套 GitHub Actions 入口。生产链路默认写 `main`，dev 链路默认写 `dev`，部署前需要确认你要接入哪一套。

| 项 | main / 生产 | dev / 预览 |
| --- | --- | --- |
| 飞书 Request URL | `https://feishu.soulgo.chat` | `https://feishu-dev.soulgo.chat` |
| Cloudflare Worker | `feishu-sync-dispatch` | `feishu-sync-dispatch-dev` |
| Wrangler 配置 | `wrangler.feishu.toml` | `wrangler.feishu-dev.toml` |
| GitHub workflow | `.github/workflows/feishu-sync.yml` | `.github/workflows/feishu-sync-dev.yml` |
| repository_dispatch type | `feishu_update` | `feishu_update_dev` |
| checkout 分支 | `main` | `dev` |
| 飞书 App | `FEISHU_APP_ID`、`FEISHU_APP_SECRET` | 优先 `DEV_FEISHU_APP_ID`、`DEV_FEISHU_APP_SECRET`；未配置时复用生产 Secret |
| 飞书 chat 白名单 | `FEISHU_ALLOWED_CHAT_IDS` | 优先 `DEV_FEISHU_ALLOWED_CHAT_IDS`；未配置时复用生产 Variable |
| 数据库 | `TRAINING_DB_ENABLED` + `TRAINING_DB_URL` | 固定 `TRAINING_DB_ENABLED=true` + `DEV_TRAINING_DB_URL` |
| DB application_name | `TRAINING_DB_APP_NAME`，默认 `feishu-sync` | `DEV_TRAINING_DB_APP_NAME`，默认 `feishu-sync-dev` |
| 同步成功后的页面部署 | dispatch `deploy-pages.yml`，ref 为 `main` | dispatch `deploy-cloudflare-pages-dev.yml`，ref 为 `dev` |
| Worker dispatch | `GITHUB_DISPATCH_EVENT_TYPE=feishu_update` | `GITHUB_DISPATCH_EVENT_TYPE=feishu_update_dev` |

如果只部署生产飞书通道，按本文后续步骤使用默认 `wrangler.feishu.toml` 即可。

如果要同时部署 dev 和 main，建议使用两个飞书应用或至少两个事件订阅 Request URL，并使用两个 Cloudflare Worker，避免 dev 消息误触发生产 workflow。当前仓库提供：

- 生产 Worker 配置：`wrangler.feishu.toml`，Worker 名称 `feishu-sync-dispatch`，Request URL 为 `https://feishu.soulgo.chat`。
- dev Worker 配置：`wrangler.feishu-dev.toml`，Worker 名称 `feishu-sync-dispatch-dev`，Request URL 为 `https://feishu-dev.soulgo.chat`。

dev Worker 至少需要独立区分：

- Worker 名称和自定义域名。
- 飞书开放平台 Request URL。
- `GITHUB_DISPATCH_EVENT_TYPE=feishu_update_dev`。
- `FEISHU_ENCRYPT_KEY`、`FEISHU_VERIFICATION_TOKEN` 是否对应 dev 飞书应用或 dev 事件订阅。即使值复用，也要写入 dev Worker Secrets。
- GitHub `DEV_FEISHU_APP_ID`、`DEV_FEISHU_APP_SECRET`、`DEV_FEISHU_ALLOWED_CHAT_IDS` 和 `DEV_TRAINING_DB_URL`。

## 6. Cloudflare Worker 配置

当前飞书通道使用两套 Cloudflare Worker：

| 环境 | 代码 | Wrangler | Worker 名称 | 自定义域名 | dispatch 类型 | Durable Object |
| --- | --- | --- | --- | --- | --- | --- |
| 生产 | `cloudflare/feishu-sync-dispatch-worker.mjs` | `wrangler.feishu.toml` | `feishu-sync-dispatch` | `feishu.soulgo.chat` | `feishu_update` | `FEISHU_IMAGE_BUFFER` |
| dev | `cloudflare/feishu-sync-dispatch-worker.mjs` | `wrangler.feishu-dev.toml` | `feishu-sync-dispatch-dev` | `feishu-dev.soulgo.chat` | `feishu_update_dev` | `FEISHU_IMAGE_BUFFER` |

飞书后台只填写自定义域名：生产填 `https://feishu.soulgo.chat`，dev 填 `https://feishu-dev.soulgo.chat`。不要在飞书后台填写 `workers.dev` URL；生产 Worker 使用 custom domain 部署后，`workers.dev` 入口可能被禁用。

### 6.1 Worker Secrets

Worker Secret 是 Cloudflare Worker 运行时变量，不是 GitHub Actions Secret。生产和 dev Worker 都需要单独设置：

```text
GITHUB_TOKEN=能调用 repository_dispatch 的 GitHub token
FEISHU_ENCRYPT_KEY=飞书事件订阅 Encrypt Key
FEISHU_VERIFICATION_TOKEN=飞书事件订阅 Verification Token
```

`GITHUB_TOKEN` 获取方式：

- GitHub -> Settings -> Developer settings -> Personal access tokens。
- Fine-grained token 选择当前仓库，给 `Contents` read/write 权限即可调用 `repository_dispatch`。
- 如果使用 classic token，`repo` scope 可用但权限更宽。
- 如果已有 Telegram Worker 使用的同类 PAT，值可以复用；但仍要给 `feishu-sync-dispatch` Worker 单独写入这个 Secret。

可以在 Cloudflare Dashboard 的对应 Worker `Settings -> Variables -> Worker Secrets` 配置，也可以本地运行。

生产 Worker：

```bash
npx wrangler secret put GITHUB_TOKEN --config wrangler.feishu.toml
npx wrangler secret put FEISHU_ENCRYPT_KEY --config wrangler.feishu.toml
npx wrangler secret put FEISHU_VERIFICATION_TOKEN --config wrangler.feishu.toml
```

dev Worker：

```bash
npx wrangler secret put GITHUB_TOKEN --config wrangler.feishu-dev.toml
npx wrangler secret put FEISHU_ENCRYPT_KEY --config wrangler.feishu-dev.toml
npx wrangler secret put FEISHU_VERIFICATION_TOKEN --config wrangler.feishu-dev.toml
```

检查 Secret 是否已写入：

```bash
npx wrangler secret list --config wrangler.feishu.toml
npx wrangler secret list --config wrangler.feishu-dev.toml
```

`secret list` 只能看到 Secret 名称，不能读取 Secret 明文值。要确认值是否正确，需要回到飞书开放平台核对 `Encrypt Key` 和 `Verification Token`，或重新执行 `wrangler secret put` 覆盖。

### 6.2 Worker Variables

生产 `wrangler.feishu.toml` 已配置：

```toml
routes = [
  { pattern = "feishu.soulgo.chat", custom_domain = true }
]

[vars]
GITHUB_DISPATCH_EVENT_TYPE = "feishu_update"
```

dev `wrangler.feishu-dev.toml` 已配置：

```toml
routes = [
  { pattern = "feishu-dev.soulgo.chat", custom_domain = true }
]

[vars]
GITHUB_DISPATCH_EVENT_TYPE = "feishu_update_dev"
```

可选变量：

```text
GITHUB_OWNER=soulgo
GITHUB_REPO=training_records
GITHUB_DISPATCH_EVENT_TYPE=feishu_update
```

`GITHUB_OWNER` 和 `GITHUB_REPO` 未配置时默认使用 `soulgo/training_records`。不要用同一个生产 Worker 同时承载 dev 和 main，除非你明确知道飞书事件来源不会混用。

### 6.3 部署 Worker

本地部署生产 Worker：

```bash
npx wrangler deploy --config wrangler.feishu.toml
```

本地部署 dev Worker：

```bash
npx wrangler deploy --config wrangler.feishu-dev.toml
```

或在 GitHub Actions 运行 `Deploy Cloudflare Feishu Worker`。该 workflow 当前部署生产 Worker，支持手动触发，也会在 `main` 分支修改以下文件时自动部署：

- `cloudflare/feishu-sync-dispatch-worker.mjs`
- `wrangler.feishu.toml`
- `.github/workflows/deploy-cloudflare-feishu-worker.yml`

部署后确认 Worker 已绑定 `FEISHU_IMAGE_BUFFER` Durable Object，并且 SQLite migration 已生效。如果绑定尚未生效，图片消息会退回为单条直接 dispatch，消息不会丢失，但连续多图可能无法合并为一个缓冲批次。

部署完成后使用以下 Request URL：

```text
生产：https://feishu.soulgo.chat
dev：https://feishu-dev.soulgo.chat
```

## 7. 事件订阅 Request URL

回到飞书开放平台应用的事件订阅页：

1. 按环境填入对应 Worker URL。
2. 确认 `Encrypt Key` 与 Cloudflare Worker Secret `FEISHU_ENCRYPT_KEY` 一致。
3. 确认 `Verification Token` 与 Cloudflare Worker Secret `FEISHU_VERIFICATION_TOKEN` 一致。
4. 保存 Request URL，让飞书完成 `url_verification`。
5. 确认已订阅 `im.message.receive_v1`。

| 环境 | 飞书后台 Request URL |
| --- | --- |
| 生产 | `https://feishu.soulgo.chat` |
| dev | `https://feishu-dev.soulgo.chat` |

保存时飞书会向 Request URL 发送 URL verification 请求。Worker 会校验 token，并返回飞书传入的 `challenge`。如果开启了加密策略，Worker 会先使用 `FEISHU_ENCRYPT_KEY` 解密 `encrypt` 字段，再校验 token 和返回 challenge。

如果 URL verification 失败：

- `Challenge code没有返回`：Worker 没有返回 `{"challenge":"..."}`。优先检查 Request URL 是否填成当前环境的自定义域名、`FEISHU_ENCRYPT_KEY` 是否和飞书加密策略一致、`FEISHU_VERIFICATION_TOKEN` 是否一致。
- `401 invalid_encrypted_payload`：飞书加密策略开启，但 Cloudflare Worker Secret `FEISHU_ENCRYPT_KEY` 与飞书事件订阅页 `Encrypt Key` 不一致。
- `401 invalid_token`：Cloudflare Worker Secret `FEISHU_VERIFICATION_TOKEN` 与飞书事件订阅页 `Verification Token` 不一致。
- `401 unauthorized`：明文事件签名校验失败，检查 `FEISHU_ENCRYPT_KEY` 和 `X-Lark-*` 签名头。
- `500 missing_feishu_encrypt_key` / `missing_feishu_verification_token`：Cloudflare Worker Secret 未配置或未生效。
- `405 method_not_allowed`：Request URL 不是 Worker endpoint，或请求方法不对。

## 8. 验证

### 8.1 Worker URL 探测

生产 Worker：

```bash
curl -i -m 10 https://feishu.soulgo.chat
curl -i -m 10 -X POST https://feishu.soulgo.chat \
  -H 'content-type: application/json' \
  --data '{"schema":"2.0","header":{"event_type":"url_verification","token":"wrong-token"},"event":{"type":"url_verification","token":"wrong-token","challenge":"probe"}}'
```

dev Worker：

```bash
curl -i -m 10 https://feishu-dev.soulgo.chat
curl -i -m 10 -X POST https://feishu-dev.soulgo.chat \
  -H 'content-type: application/json' \
  --data '{"schema":"2.0","header":{"event_type":"url_verification","token":"wrong-token"},"event":{"type":"url_verification","token":"wrong-token","challenge":"probe"}}'
```

预期结果：

- GET 返回 `405 method_not_allowed`，说明域名已打到 Worker。
- 错误 token 的 POST 返回 `401 invalid_token`，说明 Worker 已解析请求并进入 token 校验。
- 如果返回 DNS、TLS、404 或 Cloudflare 非 Worker 页面，优先检查 custom domain route。

### 8.2 本地空 payload 验证

```bash
FEISHU_APP_ID=cli_xxx \
FEISHU_APP_SECRET=xxx \
FEISHU_ALLOWED_CHAT_IDS=oc_xxx \
AI_API_KEY=xxx \
AI_BASE_URL=https://api.openai.com/v1 \
AI_MODEL=gpt-4.1 \
TRAINING_DB_ENABLED=true \
TRAINING_DB_URL=postgresql://... \
npm run sync:feishu
```

没有 `repository_dispatch` payload 且没有待补偿队列时，应输出空同步报告，不应报缺少飞书基础配置。

### 8.3 自动链路验收

1. 在飞书目标 chat 发送 `/帮助`，应启动 `Feishu Sync` 并收到飞书文本回复。
2. 发送 `/随想 今天训练后髋部有点紧`，应写入 `core.thought`，summary 中对应 batch 为 `ready + stored`。
3. 发送一张带清晰日期的训练截图，应完成 AI 识别，并写入 `core.*`，对应记录的 `source_channel` 为 `feishu`。
4. 如果同步只改数据库，没有仓库文件 diff，应看到 `Feishu Sync` 异步触发 `deploy-pages.yml`。
5. 到站点或数据库确认页面数据来自最新 PostgreSQL 快照。
6. 到 GitHub Actions 运行摘要 `Feishu sync result` 查看 `sourceId` 和 `chatIds`。如果飞书已投递但 GitHub Actions 未启动，再查 Cloudflare Worker 日志和 `GITHUB_DISPATCH_EVENT_TYPE`。
7. 飞书开放平台日志可用于确认是否投递到正确 `address` 和返回的 `httpCode`，但不要依赖该日志获取 `chat_id`。

dev 链路验收时，把上面的 GitHub Actions 观察目标换成 `Feishu Sync (Dev)`，确认 checkout 分支为 `dev`，数据库使用 `DEV_TRAINING_DB_URL`，页面部署触发 `deploy-cloudflare-pages-dev.yml`。

推荐测试命令：

```bash
node --test test/feishu-sync.test.mjs test/github-workflows.test.mjs test/cloudflare-config.test.mjs
```

## 9. 排查速查

| 现象 | 优先检查 |
| --- | --- |
| 飞书保存 Request URL 失败，提示 `Challenge code没有返回` | Request URL 是否为当前环境自定义域名；Worker Secret `FEISHU_ENCRYPT_KEY`、`FEISHU_VERIFICATION_TOKEN` 是否已配置并与飞书一致 |
| `https://feishu.soulgo.chat` 或 `https://feishu-dev.soulgo.chat` 访问不到 Worker | Cloudflare Worker custom domain route 是否存在；DNS 是否在 Cloudflare；Worker 是否已部署 |
| 飞书消息没有启动 GitHub Actions | Worker `GITHUB_TOKEN`、`GITHUB_OWNER`、`GITHUB_REPO`、`GITHUB_DISPATCH_EVENT_TYPE`；生产应为 `feishu_update`，dev 应为 `feishu_update_dev` |
| 飞书事件日志里 `httpCode` 是 `202` 但 `success` 是 `fail` | 旧版 Worker 仍在返回 `202`；重新部署 `cloudflare/feishu-sync-dispatch-worker.mjs`，新版成功事件会对飞书返回 `200` |
| dev 消息触发了生产 workflow | 飞书 dev Request URL 是否误填 `https://feishu.soulgo.chat`；dev Worker 是否使用 `wrangler.feishu-dev.toml` |
| GitHub Actions 启动但拒绝消息 | 在运行摘要 `Feishu sync result` 里查看 `chatIds`，确认 `FEISHU_ALLOWED_CHAT_IDS` 或 `DEV_FEISHU_ALLOWED_CHAT_IDS` 是否包含该值 |
| `Feishu Sync` 显示 unauthorized chat | 把运行摘要 `chatIds` 列里的 `oc_xxx` 加入 `FEISHU_ALLOWED_CHAT_IDS` 或 `DEV_FEISHU_ALLOWED_CHAT_IDS` |
| 飞书图片下载失败 | `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`im:resource` 权限、应用是否能访问该 chat |
| 图片被跳过无日期 | 飞书没有文件名日期兜底，重发带可见日期的截图 |
| `/分析` 不回复 | `AI_*`、`TRAINING_SNAPSHOT_SOURCE`、数据库读取、飞书发送消息权限 |
| 入库后页面未更新 | `deploy-pages.yml` 是否被异步触发，`TRAINING_SNAPSHOT_SOURCE` 是否为 `database` |

更完整排查见 [常见问题排查](../问题排查/常见问题排查.md)。
