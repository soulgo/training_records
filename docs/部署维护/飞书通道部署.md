# 飞书通道部署

本文用于部署飞书消息通道。飞书通道与 Telegram 共享同步主流程：训练图片进入 AI 识别和 PostgreSQL 入库，`/随想` 写入 `core.thought`，`/分析` 读取 `TrainingSnapshot` 后通过飞书回发文本。

> 2026-06-15 更新：main 飞书已与 main Telegram 合并到统一 Worker `feishu-sync-dispatch` 和统一 workflow `.github/workflows/sync.yml`。完整 main 配置见 [main 统一入口 GitHub 与 Cloudflare 配置清单](../优化重构/main%20环境下%20cloudflare%20和%20github%20action%20的%20telegram%20和飞书合并_v20/main统一入口GitHub与Cloudflare配置清单.md)。

## 当前链路

飞书事件回调统一使用 Cloudflare Worker 自定义域名，不在飞书后台填写 `workers.dev` 地址。

| 环境 | 飞书 Request URL | Cloudflare Worker | Wrangler 配置 | GitHub dispatch | GitHub workflow | 写入分支 |
| --- | --- | --- | --- | --- | --- | --- |
| 生产 | `https://feishu.soulgo.chat` | `feishu-sync-dispatch` | `wrangler.toml` | `feishu_update` | `.github/workflows/sync.yml` | `main` |
| dev | `https://feishu-dev.soulgo.chat` | `sync-dispatch-dev` | `wrangler.dev.toml` | `feishu_update_dev` | `.github/workflows/sync-dev.yml` | `dev` |

生产和 dev 飞书都已与各自环境的 Telegram 入口合并；飞书 handler 源文件仍保留，由统一 Worker 复用。

## 1. 当前能力与边界

已支持：

- 飞书图片消息：锻炼、体脂秤、饮食、睡眠截图识别并入库，core 子表写 `source_channel='feishu'`。
- 飞书 `/随想` / `/thought`：文本随想 DB-first 写入。
- 飞书 `/帮助`、`/分析`：复用现有命令解析和回复链路。
- 飞书连续图片：Worker 通过 `FEISHU_IMAGE_BUFFER` 按 chat 缓冲约 3 秒后派发。
- 飞书明文回调和开启加密策略后的 `{"encrypt":"..."}` 回调。

当前边界：

- 飞书不复制 Telegram 主流程；`npm run sync:feishu` 是飞书适配入口。
- 飞书 Markdown 文档附件随想暂不支持；Markdown 附件能力仍是 Telegram 专属。
- 飞书随想编辑、删除、移动暂不作为主支持路径；当前先保证新建 `/随想`。
- `core.thought.telegram_message_id` 仍是历史兼容字段名。飞书原始 `message_id` 是字符串，系统会生成稳定数字代理 ID，并保留 `sourceChannel/sourceMessageId/sourceChatId`。

## 3. 飞书开放平台配置

1. 进入飞书开放平台，创建企业自建应用。
2. 在当前应用的 `凭证与基础信息` 里记录：
   - `App ID` -> GitHub Actions Secret `FEISHU_APP_ID` 或 `DEV_FEISHU_APP_ID`
   - `App Secret` -> GitHub Actions Secret `FEISHU_APP_SECRET` 或 `DEV_FEISHU_APP_SECRET`
3. 在权限管理中开通并发布：
   - `im:message`
   - `im:message.p2p_msg`
   - `im:message.group_at_msg`
   - `im:resource`
4. 进入 `开发配置 -> 事件与回调`，记录：
   - `Encrypt Key` -> Cloudflare Worker Secret `FEISHU_ENCRYPT_KEY`
   - `Verification Token` -> Cloudflare Worker Secret `FEISHU_VERIFICATION_TOKEN`
5. 填写 Request URL：
   - 生产：`https://feishu.soulgo.chat`
   - dev：`https://feishu-dev.soulgo.chat`
6. 订阅事件 `im.message.receive_v1`。

保存 Request URL 前，对应 Worker 的 `FEISHU_ENCRYPT_KEY` 和 `FEISHU_VERIFICATION_TOKEN` 必须已配置好。飞书保存时会立即发送 URL verification challenge。

## 4. GitHub 配置

在 GitHub 仓库 `Settings -> Secrets and variables -> Actions` 配置。

生产飞书同步必填：

```text
FEISHU_APP_ID=飞书应用 App ID
FEISHU_APP_SECRET=飞书应用 App Secret
FEISHU_ALLOWED_CHAT_IDS=oc_xxx
```

dev 飞书同步可选：

```text
DEV_FEISHU_APP_ID=Dev 飞书应用 App ID
DEV_FEISHU_APP_SECRET=Dev 飞书应用 App Secret
DEV_FEISHU_ALLOWED_CHAT_IDS=oc_dev_xxx
```

如果 Dev Secret / Variable 未配置，`.github/workflows/sync-dev.yml` 会回退使用生产 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 和 `FEISHU_ALLOWED_CHAT_IDS`。

## 5. main 与 dev 差异

| 项 | main / 生产 | dev / 预览 |
| --- | --- | --- |
| 飞书 Request URL | `https://feishu.soulgo.chat` | `https://feishu-dev.soulgo.chat` |
| Cloudflare Worker | `feishu-sync-dispatch` | `sync-dispatch-dev` |
| Wrangler 配置 | `wrangler.feishu.toml` | `wrangler.dev.toml` |
| GitHub workflow | `.github/workflows/feishu-sync.yml` | `.github/workflows/sync-dev.yml`，手动运行时选择 `channel=feishu` |
| repository_dispatch type | `feishu_update` | `feishu_update_dev` |
| checkout 分支 | `main` | `dev` |
| 数据库 | `TRAINING_DB_ENABLED` + `TRAINING_DB_URL` | 固定 `TRAINING_DB_ENABLED=true` + `DEV_TRAINING_DB_URL` |
| 同步成功后的页面部署 | dispatch `deploy-pages.yml`，ref 为 `main` | dispatch `deploy-cloudflare-pages-dev.yml`，ref 为 `dev` |

dev 飞书不再使用 `wrangler.feishu-dev.toml`、`feishu-sync-dispatch-dev` 或 `.github/workflows/feishu-sync-dev.yml`。

## 6. Cloudflare Worker 配置

### 6.1 生产飞书 Worker

生产使用独立 Worker：

```bash
npx wrangler deploy --config wrangler.feishu.toml
npx wrangler secret put GITHUB_TOKEN --config wrangler.feishu.toml
npx wrangler secret put FEISHU_ENCRYPT_KEY --config wrangler.feishu.toml
npx wrangler secret put FEISHU_VERIFICATION_TOKEN --config wrangler.feishu.toml
```

Tail：

```bash
npx wrangler tail feishu-sync-dispatch --format=pretty
```

### 6.2 dev 统一 Worker

dev 使用统一 Worker：

```bash
npx wrangler deploy --config wrangler.dev.toml
npx wrangler secret put GITHUB_TOKEN --config wrangler.dev.toml
npx wrangler secret put FEISHU_ENCRYPT_KEY --config wrangler.dev.toml
npx wrangler secret put FEISHU_VERIFICATION_TOKEN --config wrangler.dev.toml
```

如果同一个 dev Worker 同时承载 Telegram，还需配置：

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN --config wrangler.dev.toml
npx wrangler secret put TELEGRAM_SECRET_TOKEN --config wrangler.dev.toml
```

Tail：

```bash
npx wrangler tail sync-dispatch-dev --format=pretty
```

`wrangler.dev.toml` 已固定：

```toml
GITHUB_DISPATCH_EVENT_TYPE_FEISHU = "feishu_update_dev"
```

不要在 Cloudflare Dashboard 手工改成 `GITHUB_DISPATCH_EVENT_TYPE=feishu_update_dev`；统一 dev Worker 通过分渠道变量区分 Telegram 和飞书。

## 7. chat_id 获取

推荐从 Cloudflare Worker 实时日志获取。Worker 会为 `im.message.receive_v1` 打印一行不含消息正文的元数据：

```text
[feishu-webhook] {"event_id":"...","event_type":"im.message.receive_v1","app_id":"...","chat_id":"oc_xxx","message_id":"...","message_type":"text"}
```

如果 tail 没有日志，优先检查：

- tail 是否在发送飞书消息之前启动。
- 飞书 Request URL 是否填了当前环境自定义域名。
- 飞书事件是否已订阅 `im.message.receive_v1`。
- 应用是否已经加入目标群，或是否能收到私聊消息。
- tail 是否连的是正确 Worker：生产 `feishu-sync-dispatch`，dev `sync-dispatch-dev`。
- Worker Variables 是否设置了 `FEISHU_EVENT_LOGGING=false`。默认不设置时会打印诊断日志。

## 8. 验证

### 8.1 Worker URL 探测

生产：

```bash
curl -i -m 10 https://feishu.soulgo.chat
curl -i -m 10 -X POST https://feishu.soulgo.chat \
  -H 'content-type: application/json' \
  --data '{"schema":"2.0","header":{"event_type":"url_verification","token":"wrong-token"},"event":{"type":"url_verification","token":"wrong-token","challenge":"probe"}}'
```

dev：

```bash
curl -i -m 10 https://feishu-dev.soulgo.chat
curl -i -m 10 -X POST https://feishu-dev.soulgo.chat \
  -H 'content-type: application/json' \
  --data '{"schema":"2.0","header":{"event_type":"url_verification","token":"wrong-token"},"event":{"type":"url_verification","token":"wrong-token","challenge":"probe"}}'
```

预期：

- GET 返回 `405 method_not_allowed`。
- 错误 token 的 POST 返回 `401 invalid_token`。
- 如果返回 DNS、TLS、404 或 Cloudflare 非 Worker 页面，优先检查 custom domain route。

### 8.2 自动链路验收

1. 在飞书目标 chat 发送 `/帮助`，应触发飞书同步并收到飞书文本回复。
2. 发送 `/随想 今天训练后髋部有点紧`，应写入 `core.thought`。
3. 发送一张带清晰日期的训练截图，应完成 AI 识别，并写入 `core.*`，对应记录的 `source_channel` 为 `feishu`。
4. 如果同步只改数据库，没有仓库文件 diff，应异步触发页面部署。
5. 到 GitHub Actions 运行摘要 `Feishu sync result` 查看 `sourceId` 和 `chatIds`。

dev 链路验收时，GitHub Actions 观察目标是 `Sync (Dev)`，并确认 channel 为 `feishu`、checkout 分支为 `dev`、数据库使用 `DEV_TRAINING_DB_URL`、页面部署触发 `deploy-cloudflare-pages-dev.yml`。

推荐测试命令：

```bash
node --test test/feishu-sync.test.mjs test/feishu-dispatch-worker.test.mjs test/sync-dispatch-worker.test.mjs test/github-workflows.test.mjs test/cloudflare-config.test.mjs
```

## 9. 排查速查

| 现象 | 优先检查 |
| --- | --- |
| 飞书保存 Request URL 失败，提示 `Challenge code没有返回` | Request URL 是否为当前环境自定义域名；Worker Secret `FEISHU_ENCRYPT_KEY`、`FEISHU_VERIFICATION_TOKEN` 是否已配置并与飞书一致 |
| `https://feishu.soulgo.chat` 或 `https://feishu-dev.soulgo.chat` 访问不到 Worker | Cloudflare Worker custom domain route 是否存在；DNS 是否在 Cloudflare；Worker 是否已部署 |
| 飞书消息没有启动 GitHub Actions | Worker `GITHUB_TOKEN`、`GITHUB_OWNER`、`GITHUB_REPO`、dispatch 变量；生产应发 `feishu_update`，dev 应发 `feishu_update_dev` |
| dev 消息触发了生产 workflow | 飞书 dev Request URL 是否误填 `https://feishu.soulgo.chat`；dev Worker 是否部署为 `sync-dispatch-dev`；`wrangler.dev.toml` 是否含 `GITHUB_DISPATCH_EVENT_TYPE_FEISHU=feishu_update_dev` |
| GitHub Actions 启动但拒绝消息 | 在运行摘要 `Feishu sync result` 里查看 `chatIds`，确认 `FEISHU_ALLOWED_CHAT_IDS` 或 `DEV_FEISHU_ALLOWED_CHAT_IDS` 是否包含该值 |
| 飞书图片下载失败 | `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`im:resource` 权限、应用是否能访问该 chat |
| 图片被跳过无日期 | 飞书没有文件名日期兜底，重发带可见日期的截图 |
| `/分析` 不回复 | `AI_*`、`TRAINING_SNAPSHOT_SOURCE`、数据库读取、飞书发送消息权限 |
| 入库后页面未更新 | 对应 Pages workflow 是否被异步触发，`TRAINING_SNAPSHOT_SOURCE` 是否为 `database` |

更完整排查见 [常见问题排查](../问题排查/常见问题排查.md)。
