# 飞书通道部署

本文只写当前飞书通道部署方式。飞书不再单独维护一套同步 Action 或独立 Worker；main/dev 都进入统一 Worker，再由统一 GitHub Actions workflow 判断 channel。

## 1. 需要配置的参数

### 1.1 飞书开放平台

| 参数 | main | dev | 写到哪里 |
| --- | --- | --- | --- |
| App ID | 生产飞书应用 | dev 独立应用或复用生产 | GitHub Secret `FEISHU_APP_ID` / `DEV_FEISHU_APP_ID` |
| App Secret | 生产飞书应用 | dev 独立应用或复用生产 | GitHub Secret `FEISHU_APP_SECRET` / `DEV_FEISHU_APP_SECRET` |
| Encrypt Key | 生产飞书应用事件配置 | dev 飞书应用事件配置 | Cloudflare Worker Secret `FEISHU_ENCRYPT_KEY` |
| Verification Token | 生产飞书应用事件配置 | dev 飞书应用事件配置 | Cloudflare Worker Secret `FEISHU_VERIFICATION_TOKEN` |
| Request URL | `https://feishu.soulgo.chat` | `https://feishu-dev.soulgo.chat` | 飞书开放平台事件订阅 |
| 事件订阅 | `im.message.receive_v1` | `im.message.receive_v1` | 飞书开放平台事件订阅 |
| 权限 | `im:message`、`im:message.p2p_msg`、`im:message.group_at_msg`、`im:resource` | 同 main | 飞书开放平台权限管理 |

### 1.2 GitHub Actions

| 参数 | main | dev | 说明 |
| --- | --- | --- | --- |
| `FEISHU_APP_ID` | 必填 | 可回退使用 | 飞书 Open API tenant token |
| `FEISHU_APP_SECRET` | 必填 | 可回退使用 | 飞书 Open API tenant token |
| `FEISHU_ALLOWED_CHAT_IDS` | 必填 | 可回退使用 | 飞书 chat 白名单 |
| `DEV_FEISHU_APP_ID` | 不用 | 独立 dev 应用时填 | 未填时回退 `FEISHU_APP_ID` |
| `DEV_FEISHU_APP_SECRET` | 不用 | 独立 dev 应用时填 | 未填时回退 `FEISHU_APP_SECRET` |
| `DEV_FEISHU_ALLOWED_CHAT_IDS` | 不用 | 独立 dev 白名单时填 | 未填时回退 `FEISHU_ALLOWED_CHAT_IDS` |
| `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` | 必填 | 共用 | 图片识别和 `/分析` |
| `TRAINING_DB_URL` | 必填 | 不用 | main PostgreSQL |
| `DEV_TRAINING_DB_URL` | 不用 | 必填 | dev PostgreSQL |

飞书复用的可选参数：

- `AI_PROVIDER`
- `AI_TIMEOUT_MS`
- `AI_CONCURRENCY`
- `TELEGRAM_RECOGNITION_MODEL`
- `TELEGRAM_RECOGNITION_FALLBACK_API_KEY`
- `TELEGRAM_RECOGNITION_FALLBACK_BASE_URL`
- `TELEGRAM_RECOGNITION_FALLBACK_MODEL`
- `TELEGRAM_RECOGNITION_FALLBACK_TIMEOUT_MS`
- `TELEGRAM_RECOGNITION_CACHE_ENABLED`
- `TRAINING_DB_TIMEOUT_MS`
- `TRAINING_SNAPSHOT_SOURCE`
- `TRAINING_ANALYSIS_GOAL`

### 1.3 Cloudflare Worker

| 参数 | main Worker `feishu-sync-dispatch` | dev Worker `sync-dispatch-dev` | 说明 |
| --- | --- | --- | --- |
| `GITHUB_TOKEN` | 必填 | 必填 | 调用 GitHub `repository_dispatch` |
| `FEISHU_ENCRYPT_KEY` | 必填 | 必填 | 解密和签名校验 |
| `FEISHU_VERIFICATION_TOKEN` | 必填 | 必填 | URL verification 和 token 校验 |
| `FEISHU_EVENT_LOGGING` | 可选 | 可选 | 默认 `true`，关闭填 `false` |
| `FEISHU_IMAGE_BUFFER` | 必须绑定 | 必须绑定 | Durable Object，连续图片缓冲 |

Wrangler 固定配置：

| 环境 | Worker | Wrangler | 飞书 dispatch type |
| --- | --- | --- | --- |
| main | `feishu-sync-dispatch` | `wrangler.toml` | `feishu_update` |
| dev | `sync-dispatch-dev` | `wrangler.dev.toml` | `feishu_update_dev` |

## 2. 参数解释

- App ID / App Secret 只在 GitHub Actions 中使用，用于下载飞书图片、发送回执、回复 `/帮助` 和 `/分析`。
- Encrypt Key / Verification Token 只在 Cloudflare Worker 中使用，用于验证飞书回调。
- `FEISHU_ALLOWED_CHAT_IDS` 和 `DEV_FEISHU_ALLOWED_CHAT_IDS` 是业务白名单；从 Worker tail 日志里的 `chat_id` 获取。
- `FEISHU_IMAGE_BUFFER` 会把同一 chat 的连续图片缓冲约 3 秒再统一 dispatch，减少多图批次被拆散。
- 飞书图片会通过 Open API 下载，再以内联 data URL 交给 AI；不依赖 Telegram 文件 URL。
- 飞书进入同步后会保留 `sourceChannel='feishu'`、`sourceMessageId`、`sourceChatId` 和 `eventId`，core 子表写 `source_channel='feishu'`。

## 3. 当前链路

| 环境 | 飞书 Request URL | Worker | GitHub dispatch | GitHub workflow | 写入分支 |
| --- | --- | --- | --- | --- | --- |
| main | `https://feishu.soulgo.chat` | `feishu-sync-dispatch` | `feishu_update` | `.github/workflows/sync.yml` | `main` |
| dev | `https://feishu-dev.soulgo.chat` | `sync-dispatch-dev` | `feishu_update_dev` | `.github/workflows/sync-dev.yml` | `dev` |

链路：

```text
飞书 im.message.receive_v1
-> Cloudflare Worker 识别为 feishu
-> 校验 token / signature / encrypted payload
-> repository_dispatch feishu_update 或 feishu_update_dev
-> sync.yml 或 sync-dev.yml
-> Determine sync channel = feishu
-> npm run sync:feishu
-> PostgreSQL / 回执 / 异步页面部署
```

## 4. 飞书开放平台配置

1. 创建或进入企业自建应用。
2. 在 `凭证与基础信息` 记录 App ID 和 App Secret。
3. 在 `权限管理` 开通并发布：
   - `im:message`
   - `im:message.p2p_msg`
   - `im:message.group_at_msg`
   - `im:resource`
4. 在 `开发配置 -> 事件与回调` 记录 Encrypt Key 和 Verification Token。
5. 在事件订阅 Request URL 填：
   - main: `https://feishu.soulgo.chat`
   - dev: `https://feishu-dev.soulgo.chat`
6. 订阅 `im.message.receive_v1`。

保存 Request URL 前，必须先把对应 Worker 的 `FEISHU_ENCRYPT_KEY` 和 `FEISHU_VERIFICATION_TOKEN` 配好；飞书保存时会立即发送 challenge。

## 5. 部署 Worker

main：

```bash
npx wrangler deploy --config wrangler.toml
npx wrangler secret put GITHUB_TOKEN --config wrangler.toml
npx wrangler secret put FEISHU_ENCRYPT_KEY --config wrangler.toml
npx wrangler secret put FEISHU_VERIFICATION_TOKEN --config wrangler.toml
```

dev：

```bash
npx wrangler deploy --config wrangler.dev.toml
npx wrangler secret put GITHUB_TOKEN --config wrangler.dev.toml
npx wrangler secret put FEISHU_ENCRYPT_KEY --config wrangler.dev.toml
npx wrangler secret put FEISHU_VERIFICATION_TOKEN --config wrangler.dev.toml
```

如果同一个 Worker 同时承载 Telegram，还要在同一 Worker 上配置：

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN --config wrangler.toml
npx wrangler secret put TELEGRAM_SECRET_TOKEN --config wrangler.toml
```

dev 同理把 `wrangler.toml` 换成 `wrangler.dev.toml`。

Tail 日志：

```bash
npx wrangler tail feishu-sync-dispatch --format=pretty
npx wrangler tail sync-dispatch-dev --format=pretty
```

## 6. chat_id 获取

推荐从 Worker tail 获取。收到飞书消息时会打印不含正文的元数据：

```text
[feishu-webhook] {"event_id":"...","event_type":"im.message.receive_v1","app_id":"...","chat_id":"oc_xxx","message_id":"...","message_type":"text"}
```

把 `chat_id` 写入：

- main: GitHub Variable `FEISHU_ALLOWED_CHAT_IDS`
- dev: GitHub Variable `DEV_FEISHU_ALLOWED_CHAT_IDS`

如果没有日志，优先检查：

- tail 是否连的是正确 Worker。
- Request URL 是否填了当前环境域名。
- 应用是否已加入目标群或能收到私聊。
- 是否订阅了 `im.message.receive_v1`。
- 是否设置了 `FEISHU_EVENT_LOGGING=false`。

## 7. 验证

Worker 探测：

```bash
curl -i -m 10 https://feishu.soulgo.chat
curl -i -m 10 https://feishu-dev.soulgo.chat
```

预期 `GET` 返回 `405 method_not_allowed`。

错误 token 的 URL verification 探测：

```bash
curl -i -m 10 -X POST https://feishu-dev.soulgo.chat \
  -H 'content-type: application/json' \
  --data '{"schema":"2.0","header":{"event_type":"url_verification","token":"wrong-token"},"event":{"type":"url_verification","token":"wrong-token","challenge":"probe"}}'
```

预期返回 `401 invalid_token`。

自动链路验收：

1. 发送 `/帮助`，应触发 `Sync (Main)` 或 `Sync (Dev)`，并收到飞书文本回复。
2. 发送 `/随想 今天训练后髋部有点紧`，应写入 `core.thought`。
3. 发送一张带清晰日期的训练截图，应写入 `core.*`，对应记录 `source_channel='feishu'`。
4. 如果只有 DB 内容变化，没有仓库文件 diff，应异步触发对应 Pages workflow。
5. GitHub Actions summary 中查看 `Feishu sync result`、`sourceId`、`chatIds`、`persistenceStatus` 和 `failureDisposition`。

推荐测试：

```bash
node --test test/feishu-sync.test.mjs test/feishu-dispatch-worker.test.mjs test/sync-dispatch-worker.test.mjs test/github-workflows.test.mjs test/cloudflare-config.test.mjs
```

## 8. 排查速查

| 现象 | 优先检查 |
| --- | --- |
| 飞书保存 Request URL 失败 | URL 是否是当前环境域名；Worker Secret `FEISHU_ENCRYPT_KEY` / `FEISHU_VERIFICATION_TOKEN` 是否一致 |
| 飞书消息没有启动 GitHub Actions | Worker `GITHUB_TOKEN`、dispatch type、GitHub repo 权限 |
| dev 消息触发生产 workflow | dev Request URL 是否误填生产域名；`wrangler.dev.toml` 是否是 `feishu_update_dev` |
| GitHub Actions 启动但拒绝消息 | `FEISHU_ALLOWED_CHAT_IDS` 或 `DEV_FEISHU_ALLOWED_CHAT_IDS` 是否包含该 chat |
| 飞书图片下载失败 | `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`im:resource` 权限 |
| 图片被跳过无日期 | 重发带可见日期的截图 |
| `/分析` 不回复 | `AI_*`、数据库快照、飞书发送消息权限 |
| 入库后页面未更新 | 对应 Pages workflow 是否被异步触发，`TRAINING_SNAPSHOT_SOURCE` 是否为 `database` |

更完整配置见 [GitHub 与 Cloudflare 配置](GitHub与Cloudflare配置.md)，通用排查见 [常见问题排查](../问题排查/常见问题排查.md)。
