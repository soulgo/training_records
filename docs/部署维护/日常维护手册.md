# 日常维护手册

本文面向接手项目的维护人员，整理最常用的本地、数据库、Telegram、部署和检查操作。

## 1. 本地开发

```bash
npm ci
npm test
npm run build
npm run server
```

默认从 `训练记录.md` 构建页面。只要不切换 `TRAINING_SNAPSHOT_SOURCE=database`，本地构建不依赖 PostgreSQL。

## 2. 手工维护训练记录

1. 修改 `训练记录.md`。
2. 运行 `npm run build:data`。
3. 查看 `训练数据解析.md` 是否符合预期。
4. 运行 `npm test` 或至少运行解析相关测试。
5. 需要同步数据库时运行 `npm run import:markdown`。

注意：不要手工维护 `训练数据解析.md`，它是生成文件。

## 3. 数据库维护

新库初始化使用：

```bash
psql "$TRAINING_DB_URL" -f sql/pgsql17.sql
```

常用命令：

```bash
npm run import:markdown
npm run export:markdown
npm run sync:db
npm run reconcile:markdown
npm run backfill:core
npm run backfill:thoughts
```

维护原则：

- `TRAINING_DB_ENABLED=false` 时，数据库读写会跳过或返回空快照。
- `TRAINING_DB_ENABLED=true` 且配置了 `TRAINING_DB_URL` 后，Telegram 同步会优先写 PostgreSQL。
- 切换 `TRAINING_SNAPSHOT_SOURCE=database` 前，先确认 `core.*` 中有可渲染数据，尤其是体脂测量记录。

## 4. Telegram 同步维护

手动运行同步：

```bash
npm run sync:telegram
```

必要环境变量：

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_ALLOWED_CHAT_IDS`
- `AI_API_KEY`
- `AI_BASE_URL`
- `AI_MODEL`
- `TRAINING_DB_ENABLED`
- `TRAINING_DB_URL`

即使只处理随想，当前同步入口也会统一校验 AI 和数据库相关变量。

当前图片同步稳定支持：

- 锻炼截图：活动总览、活动明细、热量、时长、距离、心率。
- 体脂秤截图：体重、BMI、体脂率、骨骼肌、基础代谢等身体成分。
- 饮食截图：餐次、总摄入和餐次明细。
- 睡眠截图：入睡/起床、睡眠阶段、睡眠评分、心率、HRV、血氧、呼吸率、解读和建议。

睡眠图按醒来日期减一天归档。维护时如果看到截图显示 6 月 5 日早上醒来，而数据归到 6 月 4 日，这是预期行为。

V9 以后，Telegram 图片正常成功路径是增量入库：先写 `ingest.*`，再 upsert 本批次 `core.measurement`、`core.activity`、`core.meal`、`core.sleep`，最后刷新目标 `core.training_day` 汇总。成功批次不会默认全量覆盖 `训练记录.md`；只有需要保持人工账本可见时，才对目标日期做 Markdown 增量合并。PostgreSQL 失败时仍回退写 Markdown，并追加 pending 队列等待后续重放。

图片识别规则变更后，至少运行：

```bash
node tools/prompt-generator.mjs
node --test test/prompt-generator.test.mjs test/telegram-sync.test.mjs test/telegram-sync-runner.test.mjs
```

如果涉及睡眠表结构或数据库读写，再补充：

```bash
node --test test/training-db-core.test.mjs test/training-db-archive.test.mjs test/training-snapshot.test.mjs
```

真实 dev Bot / dev workflow 验收按 [V9 真实 Telegram 场景验收 Runbook](../优化重构/重构优化_v9/真实Telegram场景验收Runbook_v9.md) 执行，重点保留 GitHub Actions summary、Telegram 回复、数据库目标日期和 `训练记录.md` 目标日期 diff。

## 5. Webhook 与 Cloudflare

部署 Worker：

```bash
npx wrangler deploy
```

刷新 Telegram webhook：

```bash
npm run telegram:webhook
```

GitHub Actions 中，`deploy-cloudflare-worker.yml` 会在 Worker 部署后自动刷新 webhook，`refresh-telegram-webhook.yml` 支持手动和每 6 小时定时刷新。

Cloudflare Worker 至少需要：

- `TELEGRAM_SECRET_TOKEN`
- `GITHUB_TOKEN`，普通同步 dispatch 必需
- `TELEGRAM_BOT_TOKEN`，Worker 直接回复帮助消息必需
- 可选 `GITHUB_OWNER`，默认 `soulgo`
- 可选 `GITHUB_REPO`，默认 `training_records`
- Durable Object binding `TELEGRAM_ALBUM_BUFFER`

## 6. 部署站点

普通部署由 `.github/workflows/deploy-pages.yml` 处理。它调用 `.github/actions/site-build/action.yml`，完成：

1. Setup Node.js 22。
2. 缓存 Hexo 实际生成的 `db.json`。
3. `npm ci`。
4. 可选 `npm run sync:db`，统一执行 archive 回填、Markdown 对账和随想回填。
5. 可选测试。
6. `npm run build`。
7. 上传并部署 `public/`。

Telegram 同步产生内容变更后，`telegram-sync.yml` 会在同一个 workflow 中调用 site-build 部署站点，不依赖 bot push 再触发 Pages workflow。

Telegram Sync 已经完成依赖安装后，会以 `install_dependencies: false` 调用共享 site-build，避免重复 `npm ci`。dispatch 场景还会写 GitHub Actions summary，维护时优先看 `batchId`、`taskStatus`、`persistenceStatus`、`archivedDate`、图片计数、pending 状态、`failureDisposition` 和 failed message ids。

Dev 分支在线预览由 `.github/workflows/deploy-cloudflare-pages-dev.yml` 处理。它在 `dev` 分支站点相关文件变化或手动触发时运行，使用 Dev 数据库变量构建，删除 `public/CNAME` 后通过 Wrangler Direct Upload 发布到 Cloudflare Pages。默认项目名为 `training-records-dev`，默认访问地址为 `https://training-records-dev.pages.dev`；如需改名，设置 GitHub Variable `CLOUDFLARE_PAGES_DEV_PROJECT_NAME`。

## 7. 推荐验证矩阵

| 场景 | 命令 |
| --- | --- |
| 文档或说明更新 | 检查 Markdown 链接和 `git diff --check` |
| Markdown 导出/解析变化 | `node --test test/export-training-markdown.test.mjs test/training-parser.test.mjs` |
| Telegram 命令或同步变化 | `node --test test/telegram-sync.test.mjs test/telegram-sync-runner.test.mjs test/telegram-sync-notify.test.mjs` |
| 数据库读写变化 | `node --test test/training-db-core.test.mjs test/reconcile-training-markdown-to-core.test.mjs test/training-db-archive.test.mjs` |
| Workflow/config 变化 | `node --test test/github-workflows.test.mjs test/cloudflare-config.test.mjs` |
| 页面视图变化 | `node --test test/dashboard-view.test.mjs test/dashboard-page.test.mjs` |
| Worker 变化 | `node --test test/telegram-sync-dispatch-worker.test.mjs test/telegram-webhook.test.mjs` |
| 阶段性收尾 | `npm run test:fast && npm run build` |

## 8. 接手检查清单

- 确认本地 `npm ci`、`npm test`、`npm run build` 可运行。
- 确认 `TRAINING_SNAPSHOT_SOURCE` 当前线上取值。
- 确认 GitHub Secrets/Variables 是否齐全。
- 确认 Cloudflare Worker 变量和 Durable Object binding 是否齐全。
- 确认 Telegram webhook 是否指向当前 Worker URL。
- 确认 PostgreSQL schema 已包含 `archive.*`、`ingest.*`、`core.*`。
- 确认 PostgreSQL schema 已包含 `core.sleep`、`archive.training_sleep` 以及睡眠健康指标字段。
- 确认 `runtime/telegram-sync-pending.ndjson` 是否为空。
- 确认 `CHANGELOG.md` 最新版本条目和 `package.json` 版本是否符合预期。
