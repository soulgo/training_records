# 数据入库流程

## 流程

```mermaid
flowchart TD
  A[ready batch] --> B[persistNormalizedBatch]
  B --> C[resolveTrainingCoreConfig]
  C --> D[ensureCoreSchema]
  D --> E[upsert ingest.telegram_batch]
  E --> F[upsert ingest.telegram_message]
  F --> G[upsert ingest.telegram_recognition]
  G --> H{batch kind}
  H -->|thought*| I[PostgresThoughtRepository.persistMirror]
  H -->|image| J[persistTelegramImageBatchIncremental]
  H -->|other ready archivedDate| K[mergeBatchIntoDay + replaceCoreDay]
  I --> L[commit]
  J --> L
  K --> L
  L --> M[upsertRecognitionAiCallLogs]
```

## 写入目标

| schema | 表 | 来源 |
| --- | --- | --- |
| `ingest` | `telegram_batch` | 每个 batch 的 payload 和状态。 |
| `ingest` | `telegram_message` | batch 内消息、来源 identity、图片 file ids。 |
| `ingest` | `telegram_recognition` | AI 识别结果。 |
| `ingest` | `ai_call_log` | AI 识别 started / 结果审计。 |
| `ingest` | `telegram_pending_batch` | AI 或 DB 失败后的 pending replay。 |
| `core` | `training_day` | 日汇总。 |
| `core` | `activity` | 训练活动。 |
| `core` | `meal` | 饮食。 |
| `core` | `measurement` | 体脂/体测。 |
| `core` | `sleep` | 睡眠。 |
| `core` | `thought` | 随想正文、模块、图片引用、状态。 |

## 失败补偿

`runMessageSync` 捕获 ready batch 的数据库写入异常。若失败分类不是 `user_input`，调用 `appendPendingRecognitionBatch` 写入 pending，返回 `persistenceStatus: pending_replay`。pending 数据默认存储在数据库 `ingest.telegram_pending_batch`，旧 NDJSON 队列只在 `TELEGRAM_SYNC_REPLAY_LEGACY_NDJSON_PENDING` 场景参与重放。
