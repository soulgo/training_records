# 时间归档逻辑

## 日期来源

图片批次归档日期由 `src/adapters/telegram/sync-batch-logic.adapter.mjs` 计算：

1. AI 识别结果中的日期，经 `normalizeRecognitionDate` 标准化。
2. 睡眠图片使用 `resolveSleepArchiveDate`，可按睡眠记录时间调整归档日。
3. 文件名日期作为 fallback，由 `collectFilenameDates` 收集。
4. 多张图片日期冲突时跳过。

## 源码证据

| 规则 | 代码位置 |
| --- | --- |
| 日期工具导入 | `src/adapters/telegram/sync-batch-logic.adapter.mjs:11-16` |
| AI 日期标准化 | `src/adapters/telegram/sync-batch-logic.adapter.mjs` 中 `normalizeRecognitionDate` 调用 |
| 睡眠归档日期 | `src/adapters/telegram/sync-batch-logic.adapter.mjs` 中 `resolveSleepArchiveDate` 调用 |
| filename fallback | `src/adapters/telegram/sync-batch-logic.adapter.mjs` 中 `collectFilenameDates` 调用 |
| 多日期冲突跳过 | `src/adapters/telegram/sync-batch-logic.adapter.mjs` 中 `imageDates.size > 1` 分支 |
| 无可靠日期跳过 | `src/adapters/telegram/sync-batch-logic.adapter.mjs` 中 `!archivedDate` 分支 |

## 输出字段

| 字段 | 含义 |
| --- | --- |
| `archivedDate` | 最终写库和展示归档日期。 |
| `dateSources` | 每张图片的日期来源、识别日期和证据。 |
| `dateConfidence` | 日期可靠性分类。 |
| `dateStages` | 日期决策过程，包含 imageDates、filenameDates、是否使用 filename fallback。 |
| `warnings` | 日期冲突、文件名 fallback、Telegram photo 无文件名等提示。 |

## 睡眠特殊规则

睡眠图片不会简单使用消息日期。识别结果为 `imageType === 'sleep'` 时，流程调用 `resolveSleepArchiveDate(recognition.records?.sleep, normalizedDetectedDate, message)`，然后将该日期写入 `sleep.records[*].archivedDate` 和日汇总。

- 优先使用截图内可见的入睡日期；只有醒来日期时，归档到醒来日的前一天。
- 截图只有单个 `M/D` 醒来页头日期时，消息时间只提供年份补全。例如消息年份为 2026、截图页头为 `8/3`，先得到 `2026-08-03`，再归档到 `2026-08-02`。
- 消息日期不作为睡眠图片的归档日期回退；截图无可靠日期、入睡时间或醒来时间时仍跳过，避免把历史睡眠错误写入发送日前一天。
